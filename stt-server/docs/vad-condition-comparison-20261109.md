# 전사 옵션 비교: VAD와 앞 문장 조건 (2026-11-09)

무음과 소음에서 STT가 말을 지어내는 문제(11/8 운영 안정성 시험, `backend/docs/stability-test-20261108.md`)를 막으려고 `large-v3-turbo`의 전사 옵션을 바꿔 비교했다. 백엔드의 알려진 문장 필터(#263, #267)는 이미 본 문장만 지우므로 처음 보는 문장은 막지 못한다. 그래서 STT 단계에서 말소리가 없는 구간을 아예 전사하지 않는 방법을 시험했다.

**결론.** 기본값을 `vad_filter=True`, `condition_on_previous_text=False`로 바꾼다. 어르신의 실제 대화 녹음에서 지어낸 말과 같은 말 되풀이가 거의 사라졌다. 받아 적은 글자 수는 기존과 비슷하다(-3%). 대신 짧은 말을 일부 빠뜨리고, 아주 작은 목소리는 통째로 버릴 수 있다(아래 "실패 사례").

## 시험 조건

- **장비:** ck(Tesla P100), 운영 예비 STT와 같은 모델과 연산 형식(`large-v3-turbo`, `float32`). 운영 예비 STT 서비스는 건드리지 않고 빈 GPU에서 별도 프로세스로 돌렸다. 기본 처리 서버의 `float16` 환경에서는 비교하지 않았다.
- **설정:** 나머지 옵션은 운영과 같다(`word_timestamps=True`, 언어 `ko`). faster-whisper 1.2.1.

| 이름 | 옵션 |
| --- | --- |
| 기존 | 기본값(VAD 끔, 앞 문장 조건 켬) |
| 반복 억제 | `condition_on_previous_text=False` |
| VAD | `vad_filter=True` (faster-whisper에 든 Silero VAD 기본값) |
| **VAD + 반복 억제(채택)** | `vad_filter=True`, `condition_on_previous_text=False` |
| VAD + 앞뒤 여유 | VAD, `speech_pad_ms=1000` |
| 크기 맞춘 뒤 VAD | 소리 크기를 RMS -23 dBFS로 맞춘 뒤 VAD |

## 1. 어르신의 실제 대화 (판단 근거)

### 자료

YouTube CC BY(YouTube의 CC BY 3.0) 영상 10편의 소리, 모두 2시간 26분이다. 영상 편집 구간(인트로, 업로더 해설, 끝 음악, 내비게이션 음성)을 빼면 2시간 13분이다.

- 「다큐멘터리 김순례씨」, 채널 rcdbtv리차드백: 막내아들과 81~88세 어머니의 대화 9편. 집 6편, 차 안 1편, 병문안 1편, 어머니가 쇠약해진 시기 1편이다. 영상 ID는 uCgRTGOoBtA, bvDQ3Sidga0, CcicTguW_wg, Nyh-GHA1zlk, x3XcGT-tCX4, -HORNstk9OI, EGtRmaqdgeo, Uoj2K2OFBIk, VUijgjbSwpU.
- 「김용대 어르신 인터뷰 영상, 울산 중구 구술 자서전쓰드리기 사업」, 채널 장동희TV: 사업 측 인터뷰어와 어르신(경상 방언)의 구술 인터뷰. 영상 ID bpJK79vtODw.
- 10편 중 9편이 같은 어르신과 아들이라 화자가 다양하지 않다.
- 녹음마다 전사를 읽어 어르신과 가족 또는 인터뷰어의 대화가 맞는지, 편집 구간이 어디인지 확인했다. 이 확인은 AI 하위 에이전트가 했다. 병문안 1편은 어머니 말이 12~20%뿐이라 근거로는 약하다.

### 방법

정답 대본이 없어서, 구간마다 실제 소리 크기와 Silero VAD 말소리 비율을 함께 기록하고 후보를 뽑았다.

- **지어낸 말 후보:** 말소리 비율이 0.1 미만인 구간에 나온 글, 알파벳이나 깨진 글자, 한 구간 안에서 같은 구절을 네 번 넘게 되풀이한 것.
- **빠뜨린 말 후보:** 기존 설정이 말소리 구간에 받아 적은 글이, 다른 설정에서는 겹치는 구간도 없고 앞뒤 10초 안에 같은 글자도 없는 경우.
- **표본 판정:** 편집 구간과 겹치는 후보를 뺐다(576개 → 383개). 설정마다 최대 20개씩 뽑은 187개를 AI 판정자 두 개가 따로 판정했다. 판정자는 Claude 하위 에이전트이고, 소리를 듣지 않고 전사, 소리 크기, 말소리 비율, 다른 설정의 같은 시간대 전사만 봤다. 187건 중 170건이 일치했다. 불일치는 '불명확'으로 분모에 넣었다.
- **추정:** 추정치 = 일치한 판정 수 ÷ 그 설정의 표본 수 × 그 설정의 후보 수.

### 결과

| 설정 | 지어낸 말 (추정, 표본) | 같은 말 5번 이상 연속 | 기존이 받아 적은 말을 빠뜨린 곳 (추정, 표본) | 말소리 구간 안 글자 수 |
| --- | --- | ---: | --- | ---: |

| 반복 억제 | 약 3곳 (7개 중 1개) | 1곳 | 약 35곳 (15개 중 13개) | 25,220 |
| VAD | 약 0곳 (3개 중 0개) | **4곳** | 약 35곳 (15개 중 13개) | 26,646 |
| **VAD + 반복 억제** | **약 0곳 (2개 중 0개)** | **0곳** | **약 24곳 (14개 중 10개)** | 25,188 |
| VAD + 앞뒤 여유 | 약 7곳 (9개 중 3개) | 6곳 | 약 64곳 (19개 중 17개) | 26,402 |

- **기존의 추정치는 오차가 큽니다.** 표본이 10개라 95% 구간이 대략 21~68곳입니다.
- **지어낸 말 열은 VAD 쪽에 유리합니다.** 이 열은 말소리 구간 밖의 글과 알파벳 섞인 글만 셉니다. VAD 설정은 말소리 구간 안에서만 전사하기 때문입니다. 그래서 말소리 구간 안에서 같은 말을 되풀이하는 것은 "같은 말 5번 이상 연속" 열로 따로 셌습니다.
  - VAD(앞 문장 조건 켬)는 실제 대화 위에 "일곱"을 38번, "하하하하"를 24번 덮어썼습니다.
  - VAD + 반복 억제에서는 이런 되풀이가 없었습니다.
- **글자 수:** 말소리 구간(말소리 비율 0.5 이상) 안의 글자 수입니다. VAD + 반복 억제는 기존보다 2.9% 적습니다. 다른 VAD 설정은 되풀이 글자가 섞여서 더 많아 보입니다.

**기존 설정이 지어낸 말의 예** (모두 셈에 넣은 구간)
- 조용한 틈에 "네" 13번 (EGtRmaqdgeo 4:38~4:52)
- 앞에서 한 "4월 미친날"을 무음에서 다시 반복 (CcicTguW_wg 9:07~9:09)
- 알파벳이 섞인 말: "혹시 뭐 51év하고 나isko yaş" (Uoj2K2OFBIk 18:13)
- 영상 끝 무음의 "다음 영상에서 만나요": 이건 셈에서 뺀 편집 구간에서 나온 예입니다.

## 2. 낭독과 강연 문장, 합성 대화, 소음 (참고)

| 설정 | 문장 43개 글자 오류율 (원래 / -20dB / -30dB) | 합성 면회 대화 4개 글자 오류율 (원래 / -20dB, 목록 필터 뒤) | 말소리 없는 녹음 21개 중 지어낸 말이 나온 수 (목록 필터 뒤) |
| --- | --- | --- | ---: |
| 기존 | 4.7% / 4.7% / 4.7% | 11.8% / 12.8% | 9 |
| 반복 억제 | 4.7% / - / - | 3.4% / 3.9% | 9 |
| VAD | 4.7% / 4.9% / 20.5% | 7.8% / 8.0% | 3 |
| VAD + 반복 억제 | 4.7% / 4.9% / 20.5% | 3.4% / 3.9% | 2 |

**자료와 라이선스**
- 문장 43개: Google FLEURS ko_kr 20개(CC BY 4.0, 낭독), Zeroth-Korean 15개(CC BY 4.0, 낭독), Pansori-TEDxKR 8개(CC BY-NC-ND 4.0, TEDx 강연, 시험에만 사용).
- 합성 대화: Windows TTS로 만든 면회 대화.
- 소음: ESC-50, DEMAND, Wikimedia Commons. 소음 묶음 24개 중 3개(1953년 뉴스 해설 2개, 1938년 노래 1개)는 실제 말과 가사라서 지어낸 말 셈에서 뺐다.

**관찰**
- 기존 설정은 합성 대화가 끝난 뒤 무음에 "know me … tame … aprendpa …" 같은 말을 덧붙였다. 반복 억제를 켜면 사라진다.
- 비와 발소리의 "감사합니다"는 VAD 설정에서 나오지 않았다. 카페 소음의 "감사합니다"와 기침을 옮긴 "콕콕콕"은 VAD + 반복 억제에서도 남는다.
- faster-whisper는 Whisper의 신뢰도 기준(no_speech_prob > 0.6이면서 avg_logprob < -1.0이면 건너뛰기)을 이미 기본으로 적용한다. 이 모델에서는 남은 구간의 no_speech_prob이 모두 0으로 나와, 이 기준으로 지어낸 말을 더 거를 수 없었다.

## 실패 사례 (알고 쓰는 것)

- **짧은 말을 빠뜨린다.** 실제 대화에서 약 24곳(시간당 약 10곳)이다. 예: "다리가 좀 뻗쳐지지", "뭐지 이름이?", "엄마 용서해 주거든", "넷째도 글쎄". 받아 적은 글자 수는 기존보다 2.9% 적다.
- **아주 작은 목소리를 통째로 버린다.** 문장을 -30dB(평균 약 -62 dBFS)로 줄이면 43개 중 7개가 빈 결과였다.
  - VAD 기준값을 0.35나 0.2로 낮춰도 같았다. -20dB(평균 약 -52 dBFS)에서는 문제가 없었다.
  - 실제 대화 녹음은 평균 -27~-12 dBFS였다. 앱 녹음의 실제 소리 크기는 따로 확인해야 한다.
  - 운영에서 원인을 가릴 수 있도록, 전사 뒤 원래 길이와 VAD가 남긴 길이를 로그에 남긴다(`stage=asr_vad`, 전사 내용은 남기지 않음).
- **반복 억제만 켜면 긴 구간을 건너뛸 수 있다.** 판단 근거 밖의 공개 회의 녹음에서, 반복 억제만 켠 설정은 실제 발언 27초를 건너뛰었다. 기존 설정도 다른 곳에서 58초를 건너뛰었다. VAD를 함께 켠 설정은 두 구간을 모두 받아 적었다. 그래서 반복 억제는 VAD와 함께 켠다.

## 쓰지 않은 자료

Wikimedia Commons 녹음 10개(정치인 예방, 기자회견, 회의 등)와 UniDataPro 전화 녹음 1개로도 같은 비교를 했다. 기자와 사진기자 목소리가 섞이는 등 면회와 조건이 달라 판단 근거로 쓰지 않았다.

## 되돌리기

코드를 바꾸지 않고 실행 환경에 값을 준다.
- 직접 실행할 때는 명령 앞에 붙인다.
- ck 예비 서버는 비공개 `runtime.env`에 적는다. `backend/ops/ck-backup/run-stt.sh`가 이 값을 넘긴다.
- 값은 true/false(또는 1/0, yes/no, on/off)만 받는다. 그 밖의 값이면 서버가 시작하지 않는다.

```bash
SAEROK_STT_ASR_VAD_FILTER=false SAEROK_STT_ASR_CONDITION_ON_PREVIOUS_TEXT=true ./scripts/run_stt_server.sh
```

## 한계

- 실제 대화 자료는 YouTube 영상의 소리라서, 앱으로 휴대폰에서 녹음한 소리와 다르다. 10편 중 9편이 같은 두 사람이다.
- 판정은 AI 판정자(소리를 듣지 않음)가 했다. 수치는 표본 판정을 후보 수에 곱한 추정치이고, 기존 설정의 추정은 표본이 적어 오차가 크다.
- 실제 면회 녹음(가족이 요양원에서 녹음한 것)과 기본 처리 서버의 `float16` 환경에서는 확인하지 않았다.
