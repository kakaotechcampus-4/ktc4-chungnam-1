# GPT-6 Luna 전환과 합성 입력 재점검

2026-11-03 KST. 로컬 작업이며 GitHub와 운영 서버에는 반영하지 않았다.

## 변경과 검사 범위

- 기준 코드: `local/claude-integration-2-20261103`, `2947fed`.
- 작업 브랜치: `local/luna6-model-20261103`.
- PM이 이미 정한 GPT-6 Luna 전환과 출력 상한 16000을 적용했다. 카드와 리포트의 BE 기본 설정 및 시뮬레이션을 맞췄다. 이전 모델을 명시한 작업은 계속 처리한다.
- Responses API 스트리밍, 추론 `low`, 기존 시간 제한과 재시도 규칙은 유지한다. 프롬프트는 카드 v1, `report-2`, `proposals-4` 그대로다.
- 원격 develop(`e465099`)의 프롬프트는 `report-1`, `proposals-1`이고 `participantCount`, `common.medical_claims`, `_QUIZ`가 없다. 이 출력은 develop 코드의 출력이 아니며, `run.py`와 `verify.py`는 화자 미확인 처리, 리포트 의료 효능 검사, 사진 맞히기 검사, 아픈 기억 제외 범위 수정이 들어간 코드에서만 실행된다.
- [기존 점검](2026-11-03-real-model-spot-check.md)의 [실행기](2026-11-03-real-model-spot-check/README.md)와 합성 입력을 재사용했다. 새 `SPOT_CHECK_MODEL`로 모델만 선택하며 이전 출력 파일은 수정하지 않았다.
- 실제 가족 대화, 운영 DB, STT, 앱과 S3는 사용하지 않았다. 사진 입력도 기존 합성 설명 텍스트만 사용했으므로 VLM 이미지 인식 검증은 아니다.
- 모델 기능은 [공식 GPT-6 Luna 문서](https://developers.openai.com/api/docs/models/gpt-6-luna)를 참고했다. 중계 API 호출 호환은 아래 실제 요청으로 따로 확인했다. 모델 가중치는 배포하지 않으며 기존 ML API의 인증 및 이용 조건을 따른다. 호출 주소와 키는 이 기록에 넣지 않는다.

## 실행 결과

각 입력은 AI 환경에서 한 번씩 실행했다. 이후 BE가 사용하는 SDK 버전이 달라 리포트와 제안만 BE 환경에서 한 번 더 호출했다. 같은 입력의 반복이므로 독립 표본으로 합산하지 않는다.

| 환경과 기능 | 기능 실행 | 모델 호출 | 결과 | 기능별 소요 시간 |
| --- | --- | --- | --- | --- |
| AI 환경, 카드 rich-uuid | 1 | 5 | 12장 생성 | 54.3초 |
| AI 환경, 카드 sparse-uuid | 1 | 5 | 12장 생성 | 49.4초 |
| AI 환경, 리포트 3개와 제안 3개 | 6 | 6 | JSON 처리 완료 | 1.3~5.3초 |
| BE 환경, 같은 리포트와 제안 | 6 | 6 | JSON 처리 완료 | 1.6~6.5초 |

- 실제 호출 22회 모두 응답의 모델명이 `gpt-6-luna`였다. 요청 실패, JSON 처리 실패와 출력 잘림은 이 표본에서 없었다.
- AI 환경은 `langchain-openai 1.6.7`, `openai 3.24.0`, BE 환경은 `1.7.1`, `3.31.0`이다. Python 3.12.13을 사용했다.
- AI 환경 호출의 입력은 총 39997토큰, 출력은 11041토큰이다. BE 환경은 입력 8562, 출력 1562토큰이다. 카드 단계마다 문맥을 다시 보내므로 총 토큰 수는 원문 길이가 아니다.
- 한 호출의 최대 출력은 2291토큰이었다. 16000 상한이 전송되는 것은 검사했지만, 상한까지 쓰는 긴 출력과 기존 8000 한도 초과 사례는 재현하지 않았다.
- 호출 비용과 동시 처리 성능은 측정하지 않았다. 모델 변경과 프롬프트 수정이 섞인 과거 기록을 비교해 속도나 품질의 우수성을 주장하지 않는다.

## 내용 확인

| 확인한 상황 | 이번 출력 | 판정 범위 |
| --- | --- | --- |
| 고향 정정과 주제 제외 | rich 카드에 잘못된 고향 통영과 피란 주제가 없고, 별도 경험인 부산 국제시장 원단 구매는 남음 | 이 카드 묶음에서 확인 |
| 장소가 같다는 이유로 추천 제외 확대 | clear 제안은 멸치 주제 `more`만 반환. 국제시장 주제에 `less/exclude` 없음 | 두 SDK 실행에서 관찰. 모든 대화에 대한 보장은 아님 |
| 사진을 보고 정답 맞히기 | 카드 질문의 `_QUIZ` 및 `_BANNED` 검사 통과 | 정규식과 출력 정독. 의미 전체를 보장하지 않음 |
| 사진 속 경험을 본인 경험으로 단정 | sparse 3번은 “텃밭을 돌보시던 때”, “모종을 심으실 때”라고 질문함. 입력은 사람 없는 텃밭 사진 설명뿐임 | 미해결. 사진이 있다는 이유로 직접 가꿨다고 전제하면 안 됨 |
| 한 라벨에 두 사람의 발화가 섞임 | merged 제안은 이야기와 주제 모두 빈 목록. 리포트는 화자 미확인을 설명함 | 직접 AI 호출 시험. 실제 BE는 이 입력에서 생성 호출 자체를 건너뜀 |
| 화자 미확인 공장 경험과 제3자 건강 발언 | third는 공장 경험을 이야기 후보로 만들지 않음. BE SDK 출력은 직원의 약과 기억력 언급을 리포트에 요약함 | 제3자 발언 요약 범위는 남은 검토 항목. 새 진단이나 치료 효과를 만든 것은 아님 |
| 저장된 사실의 정정 | 여수 정정을 기존 이야기 수정이 아닌 새 이야기 후보로 반환함 | 정정 승인과 기존 이야기 갱신 연결까지 완료됐다는 뜻이 아님 |

일반 질문에도 아랫목이나 가족과 함께 식사한 경험을 전제하는 표현이 있다. 구체적인 삶을 지어내지 않으려면 경험 유무를 단정하지 않는 질문이 필요하다. 이번 변경은 모델 설정이므로 프롬프트와 제품 기준은 임의로 수정하지 않았다.

`scan.py`가 리포트의 “오늘”을 카드 질문 금지어로 표시한 것은 적용 범위가 달라 생긴 오탐이다. 리포트가 해당 면회를 요약하는 문장과 최근 기억을 시험하는 질문을 구분했다. 피란이라는 단어가 리포트에 나온 것도 사용자가 그만하고 싶다고 말한 상황의 요약이며 추천 제외 위반으로 세지 않았다.

## 적용 시 주의

로컬 회귀 검사: AI 136개 통과, BE 620개 통과와 Docker 이미지 조건 3개 건너뜀.
BE 테스트는 테스트 전용 PostgreSQL에서 실행했다. AI용 DB도 이번 작업 전용으로 따로 만들었다.
앱, workflow와 STT 코드는 이번에 수정하지 않아 해당 전체 검사는 다시 실행하지 않았다.

- 기존 운영 `.env`에 5.6 모델이 명시돼 있으면 새 기본값보다 우선한다. 운영 적용 시 카드와 리포트 두 설정을 확인한다. 이번 작업은 운영 설정을 바꾸지 않았다.
- 기존 카드 작업에 저장된 모델은 유지한다. 이미 만든 카드와 리포트도 다시 만들지 않는다.
- 출력 한도를 늘려도 작업 임대나 전체 시간 제한은 늘어나지 않는다.
- 실제 앱의 녹음부터 두 번째 회차까지 통합 검증, VLM 이미지 품질, 긴 전사 입력과 반복 안정성은 이번 시험 범위가 아니다.
