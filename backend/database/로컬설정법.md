# 로컬 PostgreSQL 설정

스키마는 Alembic migration으로만 만든다. `init.sql`은 Alembic 버전 기록을 남기지 않아 이후 migration이 적용되지 않으므로 작업용 DB에 쓰지 않는다.

PostgreSQL 17 기준이며 15 이상이 필요하다. 스키마가 15부터 지원하는 `ON DELETE SET NULL (column)` 구문을 쓴다.

직접 설치하지 않고 Docker로 띄우려면 [컨테이너 실행](../docs/deployment.md#로컬에서-postgresql만-컨테이너로-띄우기)을 따르고 3번부터 진행한다.

## 1. DB 만들기

관리자 계정으로 psql 또는 pgAdmin에서 실행한다.

```sql
CREATE ROLE saerok LOGIN PASSWORD '로컬비밀번호';
CREATE DATABASE saerok OWNER saerok;
```

## 2. 연결 설정

`backend/`에서 `.env`를 만들고 연결 문자열을 채운다. `.env`는 커밋하지 않는다.

```powershell
copy .env.example .env
```

```
SAEROK_DATABASE_URL=postgresql+psycopg://saerok:로컬비밀번호@localhost:5432/saerok
```

## 3. 스키마 적용

```powershell
uv sync
uv run alembic upgrade head
uv run alembic current
```

`current` 결과에 `(head)`가 보이면 끝이다. 다른 사람의 migration을 받은 뒤에도 `upgrade head`를 다시 실행한다.

## 4. migration 테스트

migration을 추가했다면 실행한다. 테스트 DB를 만들고 지우므로 관리자 계정을 쓴다. 이 값이 없으면 테스트는 건너뛴다.

```powershell
$env:SAEROK_TEST_DATABASE_URL="postgresql://postgres:관리자비밀번호@localhost:5432/postgres"
uv run pytest tests/test_migrations.py
```

## 초기화

```powershell
uv run alembic downgrade base
uv run alembic upgrade head
```

## migration 교체 후 1회 초기화

2026-10-04에 이전 스키마의 migration 두 개(`db2bf9003e7f`, `a8c31f17d902`)를 새 스키마 기준 initial migration 하나(`f8fd6d0e862c`)로 교체했다. 이전 migration을 적용했거나 `init.sql`로 만든 DB에는 `downgrade`와 `upgrade head`가 적용되지 않는다. 관리자 계정으로 DB를 지우고 다시 만든 뒤 3번을 실행한다. 로컬 DB에는 합성 데이터만 둔다.

```sql
DROP DATABASE saerok;
CREATE DATABASE saerok OWNER saerok;
```
