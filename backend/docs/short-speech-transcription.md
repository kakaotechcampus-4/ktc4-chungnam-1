# 프로필 세부 정보의 음성 입력

2026-10-18 22:03~22:04 KST의 [#138 BE 답변](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/issues/138#issuecomment-6250248022)을 연결한 구현이다. 운영 서버에는 아직 반영하지 않았다.

`POST /api/v1/speech-transcriptions`에 인증 토큰과 multipart의 `audio` 파일 하나를 보낸다. 프로필과 회차 ID는 필요 없다. 응답은 `{"schemaVersion": 1, "text": "..."}`이며 기존 앱의 `ServerSpeechApi` 형식과 같다.

- 필수 동의, WAV/PCM 16-bit/16kHz/mono, 실제 파일 손상, 크기와 5분 제한을 검사한다. 5분 초과는 `AUDIO_TOO_LARGE` 413으로 반환한다. 앱은 녹음을 시작한 뒤 5분 타이머를 켜고 멈추므로 5분을 채운 파일은 늘 300초를 조금 넘는다(11/8 운영 시험에서 300.004초 파일이 거절됨). 그래서 멈추는 데 걸리는 시간으로 2초를 더 받는다(302초까지). 이 오류 코드 선택은 PR에서 확인할 구현안이다.
- 세션 토큰의 서명과 만료는 본문을 읽기 전에 확인한다. 본문은 짧은 음성 상한(10 MiB와 `SAEROK_MAX_AUDIO_BYTES` 중 작은 값)에 1 MiB를 더한 크기까지만 받고, 넘으면 끝까지 받지 않고 `AUDIO_TOO_LARGE` 413으로 끊는다([요청 본문 크기 상한](../README.md#요청-본문-크기-상한)).
- 같은 계정의 요청은 동시에 1건(`SAEROK_SHORT_TRANSCRIPTION_CONCURRENCY_PER_ACCOUNT`)만 처리한다. 한 요청이 STT 응답을 기다리는 동안 DB 연결과 STT 서버를 붙잡기 때문이다(2026-11-09 PM 결정). 앞 요청이 끝나기 전에 온 요청은 S3 저장과 STT 호출 없이 `SPEECH_TRANSCRIPTION_IN_PROGRESS` 429(`retryable: true`)로 거절한다. 라우트가 요청의 DB 연결에 세션 수준 advisory lock을 잡아 세며 트랜잭션은 열지 않는다. 서버 전체의 동시 처리 수 제한은 아니다([계정별 사용 한도](../README.md#계정별-사용-한도)).
- 현재 STT 클라이언트를 재사용해 한 명으로 요청한다. 화자 분리를 끄거나 새 모델을 선택하지 않는다. #189에서 병합된 공용 클라이언트(`app.state.ai_server_client`)를 그대로 써서, 기본 STT 서버 연결이 실패하면 면회 분석과 같은 규칙으로 예비 서버에 한 번 전환한다.
- 음성은 기존 비공개 음성 버킷에 암호화해 임시 업로드한다. 원본 키만 정리 대기열에 먼저 저장하고 전사와 개인 식별정보는 DB나 로그에 저장하지 않는다.
- 처리 중에는 대기열의 `not_before`까지 삭제 실행기가 건너뛴다. 요청이 끝나면 즉시 삭제를 시도하고 재확인 대상으로 바꾼다. S3 삭제만 실패해도 전사 성공을 취소하지 않는다.
- 프로세스가 종료돼도 최초 저장한 큐가 남는다. 큐 실행과 S3 Lifecycle은 별도 운영 설정이다. 이 코드만으로 정확한 24시간 내 삭제가 보장된다고 설명하지 않는다.
- 전사 문자열이 비었으면 앱의 직접 입력 안내를 사용한다. 잡음을 알아듣지 못한 것으로 판정하는 새 점수 기준은 만들지 않았다.

현재 BE의 `ai_server_timeout_seconds`를 전체 STT 대기 상한에도 사용한다. 앱은 2분 제한을 쓰므로 BE 제한이 더 길면 앱이 먼저 직접 입력을 안내하고 서버는 정리를 계속할 수 있다. 10초, 1분, 5분 실제 처리 시간과 대기열 혼잡을 측정한 뒤 #138의 별도 제한 값을 정해야 한다. 현 설정을 적절한 사용자 대기 시간으로 검증한 것은 아니다.

`e84b1c6da032` migration으로 정리 대기열에 `not_before`를 추가한다. 삭제 기록 migration `a49d71b28c36` 다음이다. 처리 중인 임시 업로드가 남았으면 downgrade를 거절한다. 기존 삭제 실행 코드도 이 열을 확인하는 버전과 함께 배포해야 한다.

테스트는 합성 WAV, 가짜 S3와 STT, 실제 격리 PostgreSQL을 사용한다. 실제 음성을 외부로 전송하지 않는다. 동시 요청 거절은 같은 테스트 앱에 요청을 겹쳐 보내 확인했고, 실제 앱의 연속 입력이나 운영 서버의 동시 요청으로 확인한 것은 아니다.
