# 화자 구분이 부족한 전사의 해석과 제안 차단

로컬 보완안이다. 실제 모델과 운영 자료로 검증하지 않았으며 GitHub와 운영에 반영하지 않았다.

- 발화가 있는 구간의 라벨만 검사한다. 빈 라벨과 null 라벨을 화자 확인으로 세지 않는다.
- 미확인 발화가 있거나 라벨 수가 입력 인원보다 적으면 BE가 리포트와 변경 제안의 모델 호출을 모두 생략한다. 프롬프트 지시만으로 처리하지 않는다.
- 리포트 제목은 `화자 미확인 안내`로 저장한다. 본문은 화자를 충분히 구분하지 못해 대화 해석, 카드별 요약, 새 이야기 후보와 주제 조정 제안을 만들지 않았다는 고정 안내다.
- `cardSummaries`, `lifeFactProposals`, `topicProposals`는 모두 빈 목록이다. 보호자가 직접 저장한 소감과 카드 평가는 변경하지 않는다.
- 다른 호출 경로에서 임의 해석이나 제안을 넣거나 안내를 지우면 `UNVERIFIED_SPEAKER_FACT`로 저장을 거절한다. 일부 후보만 안전하다고 임의로 고르지 않는다.
- 모델 호출을 하지 않았으므로 저장 이력은 `model=not-invoked`, `promptVersion=speaker-unverified-v1`이다. 안내 저장 후 기존 작업 상태는 `completed`가 된다. 이는 AI 분석 성공을 뜻하지 않는다. 기존 리포트 조회 API의 제목과 본문으로 제한을 알리며, 전사문은 기존 완료 시 삭제 정책을 그대로 따른다. 화자 수정이나 완료된 회차 재분석 기능을 새로 추가하지 않았다.
- 발화가 전혀 없는 경우는 `EMPTY_TRANSCRIPT` 실패다. 위 안내로 완료 처리하지 않는다.
- 한 명 입력에 한 라벨이 나온 경우는 허용한다. 라벨 수가 맞아도 보호자와 어르신의 역할이 확인된 것은 아니다. 프롬프트의 출처 구분과 보호자의 이야기 승인 절차는 계속 필요하다.

한 참여자가 말하지 않은 경우에도 라벨은 입력 인원보다 적을 수 있다. 이 검사는 화자 분리 모델의 실패를 확정하는 기준이 아니다. 현재 응답에는 후보별 근거 발화 연결이 없어 미확인 구간을 쓰지 않은 후보만 따로 살릴 수 없다. 이 제한은 PR에서 AI 담당자가 검토해야 한다.

라벨이 충분한 결과에서도 모델이 인물과 역할을 잘못 해석할 가능성은 남는다. 이 변경은 그 의미를 모두 검증하는 기능이 아니다. 실제 STT와 리포트 모델의 품질 검사는 별도이며, 합성 검사 통과를 실제 화자 식별 성공률로 보고하지 않는다.

`tests/test_speaker_fact_boundary.py`는 실제 worker의 생성 함수 연결, 격리 PostgreSQL과 리포트 및 제안 조회 API를 검사한다. 외부 모델은 대역으로 바꿔 호출 여부를 확인한다. 충분한 라벨, 한 명 입력, 빈 전사, 임대 만료와 검증 우회도 함께 검사한다.
