# 화자 구분이 부족한 전사의 해석과 제안 차단

실제 STT 모델, 실제 리포트 모델과 운영 자료로는 검증하지 않았다.

- 발화가 있는 구간의 라벨만 검사한다. 빈 라벨과 null 라벨을 화자 확인으로 세지 않는다.
- 미확인 발화가 있거나 라벨 수가 입력 인원보다 적으면 BE가 리포트와 변경 제안의 모델 호출을 모두 생략한다. 프롬프트 지시만으로 처리하지 않는다.
- 작업은 `failed`, 오류 코드는 `SPEAKER_UNVERIFIED`로 남긴다. 리포트, 카드별 요약, 이야기와 주제 제안은 저장하지 않는다. 보호자가 직접 저장한 소감과 카드 평가는 변경하지 않는다.
- 실패한 작업의 전사는 최초 STT 저장 뒤 24시간 기한 안에서 남는다([수동 복구](speech-recovery.md)). 그래서 보호자가 리포트를 다시 요청(6-5)할 수 있다. 11/5 멘토 리뷰 전에는 고정 안내만 저장하고 `completed`로 끝내서 전사가 지워지고, 다시 요청과 녹음 재전송이 모두 막혔다.
- 다시 요청해도 같은 전사와 같은 참여 인원으로 판단하므로 같은 이유로 다시 실패할 수 있다. 참여 인원을 고쳐 다시 요청하는 기능은 아직 없다.
- 다른 호출 경로에서 미확인 전사로 만든 결과를 넘기면 `UNVERIFIED_SPEAKER_FACT`로 저장을 거절한다. 일부 후보만 안전하다고 임의로 고르지 않는다.
- 발화가 전혀 없는 경우는 `EMPTY_TRANSCRIPT` 실패다.
- 한 명 입력에 한 라벨이 나온 경우는 허용한다. 라벨 수가 맞아도 보호자와 어르신의 역할이 확인된 것은 아니다. 프롬프트의 출처 구분과 보호자의 이야기 승인 절차는 계속 필요하다.

한 참여자가 말하지 않은 경우에도 라벨은 입력 인원보다 적을 수 있다. 이 검사는 화자 분리 모델의 실패를 확정하는 기준이 아니다. 현재 응답에는 후보별 근거 발화 연결이 없어 미확인 구간을 쓰지 않은 후보만 따로 살릴 수 없다. 이 제한은 PR에서 AI 담당자가 검토해야 한다.

라벨이 충분한 결과에서도 모델이 인물과 역할을 잘못 해석할 가능성은 남는다. 이 변경은 그 의미를 모두 검증하는 기능이 아니다. 실제 STT와 리포트 모델의 품질 검사는 별도이며, 합성 검사 통과를 실제 화자 식별 성공률로 보고하지 않는다.

`tests/test_speaker_fact_boundary.py`는 실제 worker의 생성 함수 연결, 격리 PostgreSQL과 리포트 및 제안 조회 API를 검사한다. 외부 모델은 대역으로 바꿔 호출 여부를 확인한다. 충분한 라벨, 한 명 입력, 빈 전사, 실패 뒤 전사 보관과 다시 요청, 검증 우회도 함께 검사한다.
