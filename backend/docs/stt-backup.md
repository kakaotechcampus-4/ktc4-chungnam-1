# STT 연결 실패 시 예비 서버 전환

예비 주소를 설정했을 때만 동작한다. 기본 서버와 예비 서버를 동시에 호출하지 않는다.
연결의 기동과 SSH 운영 설정은 별도 작업이며 이 변경은 HTTP 클라이언트와 설정 전달만 다룬다.

| 조건 | 동작 |
| --- | --- |
| 기본 서버 정상 | 기본 서버만 호출 |
| `ConnectError`, `ConnectTimeout` | 예비 서버 한 번 호출 |
| 전송 또는 응답 대기 중 오류 | 이미 처리 중일 수 있어 재전송하지 않음 |
| HTTP 오류, 결과 형식 또는 작업 ID 불일치 | 기존 오류 유지 |
| 예비 서버도 연결 실패 | `ConnectError`는 `AI_SERVER_UNAVAILABLE`, 연결 시간 초과는 `AI_SERVER_TIMEOUT`으로 종료 |
| 다음 작업 | 기본 서버부터 다시 시도 |

`SAEROK_AI_SERVER_BACKUP_URL`은 기본적으로 비어 있어 기존 동작을 유지한다.
예비 주소를 설정하면 서버별 연결 제한은
`SAEROK_AI_SERVER_FAILOVER_CONNECT_TIMEOUT_SECONDS`(기본 5초, 0초 초과 30초 이하)다.
두 시도는 기존 전체 STT 제한 시간(기본 600초)을 공유한다.

같은 작업 ID, 입력과 삭제 기한을 사용하고 두 시도가 끝나기 전에는 S3 원본을 삭제하지 않는다.
기존 worker의 성공 및 최종 실패 정리를 유지한다. 큐를 다시 만들거나 종료된 실패 작업을
복구하지 않으며 원본 삭제 기한을 연장하지 않는다. 공개 요청 및 응답 계약도 바꾸지 않는다.

전환 로그는 `speech_analysis_backup_used reason=connect_failure`만 남긴다.
요청 본문, 전사문, URL, 객체 키와 연결 예외 메시지는 넣지 않는다.

2026-11-03 KST 검증: Python 3.12의 잠금 의존성과 PostgreSQL 17 임시 DB에서 BE 전체
429건 통과. 테스트의 리포트 생성기는 대체 객체를 사용하며 실제 ML API 실행과 구분한다.
실제 BE 컨테이너에서 합성 S3 입력과 ck 모델을 사용해 정상 우선, 연결 실패 시
한 번 전환 및 양쪽 연결 실패를 확인했다. 실제 사용자 자료, 두 화자 정확도와 긴 녹음 품질은
검증하지 않았다. 운영 연결과 배포 파일은 이 PR에 포함하지 않는다.
