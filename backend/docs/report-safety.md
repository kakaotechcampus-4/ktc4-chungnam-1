# 전사와 리포트 안전 검사

빈 발화 목록으로 리포트를 만들지 않는다. 참여자 수, 관측된 화자 라벨 수와 미확인 라벨 수를 생성 입력에 전달한다. 두 사람의 녹음에 라벨이 하나만 나오는 경우도 어르신의 단독 발언으로 단정하지 않도록 지시한다. 이 지시를 실제 모델이 지키는지는 별도 평가가 필요하다.

생성 결과를 저장하기 전 제목, 본문, 카드 요약과 이야기 및 주제 제안에서 직접적인 치료 효과 보장 표현을 검사한다. 위반하면 `UNSAFE_MEDICAL_CLAIM`으로 끝내며 리포트나 제안 일부를 먼저 저장하지 않는다. 오류 로그에 생성 원문을 넣지 않는다.

이 검사는 `common/medical_claims.py`의 정규식으로 대표 구문을 찾는다. '병원', '약', '치매'라는 단어 자체는 금지하지 않는다. 병원 방문이나 복약에 관한 대화와, 서비스가 치매를 치료한다는 주장은 구분한다.

## 검증 범위

합성 문구에서 직접적인 효과 보장 7건, 일반 의료 주제와 부정 문구 10건을 검사한다. 실제 임시 DB에서는 각 응답 위치의 위반 시 부분 저장이 없는지 확인한다.

모든 의료적 표현이나 우회 문구를 이해하는 의미 검사는 아니다. 실제 모델 출력 품질 평가, 화자 역할 배정 정확도와 임상적 사실 검증을 완료했다고 쓰지 않는다. 다른 표현이 발견되면 사례와 오탐 사례를 함께 추가해 검사한다.
