# 리포트 의료 효과 표현 검사

생성 결과를 저장하기 전 제목, 본문, 카드 요약과 이야기 및 주제 제안에서 직접적인 치료 효과 보장 표현을 검사한다. 위반하면 `UNSAFE_MEDICAL_CLAIM`으로 끝내며 리포트나 제안 일부를 먼저 저장하지 않는다. 오류 로그에 생성 원문을 넣지 않는다.

이 검사는 `common/medical_claims.py`의 정규식으로, 문장 하나가 통째로 치료, 예방, 기억 회복 효과를 단정할 때만 잡는다(카드 문안 검사와 같은 방식). '병원', '약', '치매'라는 단어 자체는 금지하지 않는다. 병원 방문이나 복약에 관한 대화와, 서비스가 치매를 치료한다는 주장은 구분한다. 어르신이나 가족의 말을 옮긴 문장("...라고 하셨어요"), 들은 이야기, 부정과 유보는 문장 전체가 주장이 아니어서 걸리지 않는다. 11/5 멘토 리뷰에서 인용 문장까지 잡아 리포트 전체가 실패할 수 있다는 지적을 받아 좁혔다.

## 검증 범위

합성 문구에서 직접적인 효과 보장 7건, 일반 의료 주제와 부정 문구 10건, 말을 옮긴 문장 5건, 여러 문장 중 주장 문장 1건을 검사한다. 실제 임시 DB에서는 각 응답 위치의 위반 시 부분 저장이 없는지 확인한다.

모든 의료적 표현이나 우회 문구를 이해하는 의미 검사는 아니다. 실제 모델 출력 품질 평가와 임상적 사실 검증을 완료했다고 쓰지 않는다. 다른 표현이 발견되면 사례와 오탐 사례를 함께 추가해 검사한다.
