# 화면 디자인 기준

새록 앱의 화면을 만들 때 따르는 기준이다. 기술 선택은 [`README.md`](README.md), 개발 환경은 [`SETUP.md`](SETUP.md)에 있다.

피그마 시안과 [`docs/design-references/`](docs/design-references/README.md)의 자료는 참고 재료다. 구도와 담을 내용은 시안을 따르고, 색과 간격과 컴포넌트는 이 문서를 따른다. 시안은 세 사람이 나눠 그려 형식이 통일되어 있지 않다.

<br>

## 원칙

- **한 화면에 한 가지 일.** 주 사용자는 50~60대 보호자다. 화면을 열었을 때 무엇을 해야 하는지 한 번에 보여야 한다.
- **화면에는 색이 있다.** 크림과 초록 네 색으로 화면을 이룬다. 색은 꾸미기 위한 것이 아니라 무엇이 중요한지 알리기 위한 것이다. 네 색 밖의 색조를 들이지 않는다.
- **주 행동은 진한 초록 버튼 하나.** 화면마다 가장 중요한 행동을 진한 초록 버튼으로 두고, 나머지는 그보다 약하게 만든다.
- **디자인 요소는 더해도 되지만 기능은 더하지 않는다.** 화면에 없던 버튼, 입력, 단계를 만들지 않는다.
- **미정 항목을 화면으로 확정하지 않는다.** 카드 수, 자동 선택, 추가 대화 방식은 PM 문서의 검토 중 항목이다.

<br>

## 색

### 팔레트

네 색이 전부다. [`docs/design-references/04-Color-palette.webp`](docs/design-references/04-Color-palette.webp)에서 가져왔다.

| 이름 | 값 | 쓰는 곳 |
| --- | --- | --- |
| 아이보리 | `#FFFBF7` | 화면 배경 |
| 크림 | `#FAF2E7` | 카드와 입력 상자의 면 |
| 세이지 | `#E5EFE7` | 선택되거나 강조된 영역의 면 |
| 포레스트 | `#074321` | 본문 글자, 주 버튼 면, 선택 표시 |

세 밝은 색끼리의 대비는 1.06~1.14 : 1 이다. **면만으로는 서로 구분되지 않는다.** 카드와 배경을 나누려면 테두리를 함께 써야 한다.

### 파생 단계

네 색으로는 글자 위계와 테두리를 만들 수 없다. 포레스트의 밝기 단계만 파생해서 쓴다. **새 색조를 들이지 않는다.**

| 이름 | 값 | 쓰는 곳 |
| --- | --- | --- |
| 포레스트 보조 | `#0A5C2D` | 보조 글자 |
| 포레스트 흐림 | `#0D783B` | 비활성 글자 |
| 라인 | `#DCE1D9` | 구분선과 기본 테두리 |

### 역할

화면에서는 **역할 이름으로 부른다.** 팔레트 이름을 직접 부르지 않는다. 색을 바꿀 때 역할 표만 고치면 화면이 따라오고, 나눠 작업할 때 해석이 갈리지 않는다.

| 역할 | 값 | 아이보리 배경 대비 | 크림 면 대비 | 세이지 면 대비 |
| --- | --- | --- | --- | --- |
| 배경 | `#FFFBF7` | — | — | — |
| 표면 | `#FAF2E7` | 1.08 : 1 | — | — |
| 강조 면 | `#E5EFE7` | 1.14 : 1 | — | — |
| 본문 글자 | `#074321` | 11.1 : 1 | 10.3 : 1 | 9.7 : 1 |
| 보조 글자 | `#0A5C2D` | 7.9 : 1 | 7.3 : 1 | 6.9 : 1 |
| 비활성 글자 | `#0D783B` | 5.4 : 1 | 5.0 : 1 | 4.7 : 1 |
| 구분선, 테두리 | `#DCE1D9` | 1.29 : 1 | 1.20 : 1 | 1.13 : 1 |
| 강조, 주 버튼 면 | `#074321` | 11.1 : 1 | — | — |
| 주 버튼 위 글자 | `#FFFBF7` | 포레스트 면 위 11.1 : 1 | — | — |

모든 글자 색이 세 면 위 어디에서도 4.5 : 1 을 넘는다. **비활성 글자도 4.5 : 1 이 하한이다.** 그보다 흐린 색을 글자에 쓰지 않는다.

순수한 검정과 순수한 흰색을 쓰지 않는다. 크림 바탕 위에서 둘 다 이물감이 있다.

### 상태는 색과 형태를 함께 쓴다

색이 생겼어도 **색만으로 상태를 알리지 않는다.** 색각 이상 사용자를 위한 요건이며, 흑백이라서 생긴 제약이 아니다.

| 상태 | 표현 |
| --- | --- |
| 선택됨 | 세이지 면에 2px 포레스트 테두리와 포레스트 원 안의 체크 |
| 선택 안 됨 | 배경 면에 1px 라인 테두리와 빈 원 |
| 강한 강조 | 포레스트 면에 아이보리 글자 |
| 보통 강조 | 포레스트 테두리에 포레스트 글자 |
| 약한 상태 | 라인 테두리에 비활성 글자 |
| 영역 강조 | 크림 또는 세이지 면에 본문 글자 |
| 초점 | 면이 아이보리로 밝아지고 테두리가 1px 라인에서 1.5px 포레스트로 굵어진다 |

### 눌림과 비활성

색을 늘리지 않고 만든다. 버튼마다 눌린 색을 따로 정하지 않는다.

- **눌림** — 원래 면 위에 포레스트 12% 덮개를 얹는다.
- **비활성** — 컴포넌트 전체의 투명도를 30%로 낮춘다. 글자만 흐리게 바꾸는 부분 처리를 하지 않는다.

### 경고

| 용도 | 값 | 대비 |
| --- | --- | --- |
| 필수 표시, 오류 글자와 아이콘 | `#99392E` | 아이보리 배경 위 6.9 : 1 |
| 오류 영역 배경 | `#F7E9E7` | 그 위엔 `#99392E` 글자, 6.0 : 1 |

흙빛이 도는 붉은색이다. 크림 계열 배경과 이미지의 따뜻한 톤에 얹혀도 부딪히지 않으면서 경고로 읽힌다.
**팔레트 네 색과 그 파생, 그리고 이 붉은색 말고는 화면에 색을 쓰지 않는다.**

오류는 색만으로 알리지 않는다. 테두리와 아이콘, 그리고 아래 한 줄 안내를 함께 쓴다.

<br>

## 글자

50~60대가 주 사용자다. 본문을 17로 두고, 그보다 작은 글자는 보조 정보에만 쓴다.
**크기와 굵기는 바꾸지 않는다.** 자간과 줄 간격을 역할별로 나눈다.

| 역할 | 크기 | 굵기 | 자간 | 줄 간격 |
| --- | --- | --- | --- | --- |
| 화면 제목 | 28 | 700 | -2% (-0.56) | 1.3 |
| 섹션 제목 | 20 | 700 | -1.5% (-0.30) | 1.35 |
| 버튼 | 18 | 600 | -1% (-0.18) | 1.25 |
| 본문 | 17 | 400 | -0.5% (-0.09) | 1.5 |
| 본문 강조 | 17 | 600 | -1% (-0.17) | 1.45 |
| 보조 | 15 | 400 | -0.5% (-0.08) | 1.5 |
| 캡션 | 13 | 400 | 0 | 1.4 |

- 캡션 13이 가장 작은 글자다. 그보다 작게 쓰지 않는다.
- 위 표보다 크게 쓰는 자리가 셋 있다. 각각 이유가 있다.
  - 홈의 앱 이름 44. 제목이 아니라 이름표다. 자간 -2%, 줄 간격 1.2.
  - 면회 중 대화 카드의 메인 질문 32와 꼬리 질문 26. 보호자가 휴대전화를 바닥에 두고
    곁눈질로 읽기 때문에 다른 화면보다 크다. 자간 -1.5%, 줄 간격 1.3.
  - 녹음 화면의 경과 시간 34. 멀리서도 보여야 한다. 자간 0이고 **고정폭 숫자를 쓴다.**
    폭이 일정하지 않으면 초가 바뀔 때마다 글자가 떨린다. 고정폭 숫자를 쓰는 자리는 여기뿐이다.
- 줄 간격은 위 표를 따른다. 제목은 좁히고 본문은 넓힌다.
- 한 줄에 담기지 않는 문장은 줄여 쓰기(`...`)보다 두 줄로 보여준다. 어르신 이름과 날짜처럼 잘리면 뜻이 사라지는 값은 특히 그렇다.

### 서체

**아직 정하지 않았다.** 두 자리가 필요하다.

- **본문 서체** — 위 크기 사다리를 그대로 쓸 수 있는 한글 고딕. [`docs/design-references/07-TossDesign.md`](docs/design-references/07-TossDesign.md)가 Pretendard를 후보로 둔다.
- **대화 카드 질문 서체** — [`docs/design-references/02-font.webp`](docs/design-references/02-font.webp)와 비슷한 느낌의 글꼴. **대화 카드의 메인 질문과 꼬리 질문, 음성 질문 텍스트에만** 쓰고 그 밖의 자리에는 쓰지 않는다.

둘 다 재배포를 허용하는 라이선스인지 확인하고, `app/assets/`에 두고 `pubspec.yaml`에 선언한다. 정해지기 전까지는 기기 기본 서체로 둔다.

## 간격과 모양

- 간격은 **4의 배수**만 쓴다. `4 8 12 16 20 24 32 40 48`
- 화면 좌우 여백은 **20**이다.
- 섹션 사이는 **32**, 같은 섹션 안의 항목 사이는 **12**를 기본으로 한다.
- **관계가 가까울수록 좁힌다.** 라벨과 입력처럼 붙어 있어야 하는 것은 **8**, 목록의 행 사이는 **16**이다.

**모서리는 높이에 연동한다.** 큰 것일수록 더 둥글다. 같은 버튼이라도 높이가 다르면 모서리가 다르다.

| 높이 | 모서리 |
| --- | --- |
| 56 | 16 |
| 48 | 14 |
| 40 | 12 |
| 32 | 10 |

높이를 갖지 않는 것은 따로 정한다.

| 요소 | 모서리 |
| --- | --- |
| 카드 | 16 |
| 이미지 | 16 |
| 칩, 뱃지 | 완전한 둥근 모양 |

iOS식으로 뭉개진 사각형(squircle)을 쓰지 않는다. 위 값만 쓴다.

### 그림자

떠 있는 느낌이 필요한 곳에만 옅게 쓴다. **평면이 기본이다.** 카드마다 다 넣지 않는다.

그림자 색은 검정이 아니라 **포레스트를 낮은 투명도로** 쓴다. 크림 바탕에 검정 그림자를 깔면 회색 얼룩으로 남는다.

떠 있는 정도가 높을수록 넓고 진하다.

| 단계 | 값 | 쓰는 곳 |
| --- | --- | --- |
| 1 | `0 2 8 rgba(7,67,33,0.08)` | 목록 카드, 대화 카드 |
| 2 | `0 4 12 rgba(7,67,33,0.10)` | 펼친 메뉴, 말풍선 |
| 3 | `0 6 20 rgba(7,67,33,0.12)` | 다이얼로그, 하단 탭바 |
| 4 | `0 8 24 rgba(7,67,33,0.16)` | 토스트 |
| 시트 | `0 -2 12 rgba(7,67,33,0.08)` | 아래에서 올라오는 시트 |

2단계와 4단계는 아직 쓰는 화면이 없다. 말풍선과 토스트가 생길 때를 위해 자리만 정해 둔다.

시트는 그림자를 **위쪽으로** 드리운다. 안쪽 그림자(inner shadow)를 쓰지 않는다. 눌림은 그림자가 아니라 덮개로 표현한다.

### 그라데이션

두 자리에만 쓴다. 그 밖에는 평면이다.

- 홈과 온보딩 화면에서 **그림 뒤에 두는 방사형 그라데이션.** 세이지에서 배경색으로 퍼진다.
- 화면 하단에 고정된 버튼 **위쪽의 가림 그라데이션.** 배경색에서 투명으로 간다. 스크롤되는 내용이 버튼에 닿아 겹쳐 보이는 것을 막는다.

## 공통 컴포넌트

높이는 그대로 두고 색과 질감을 정한다. 모서리는 위의 높이 연동 표를 따르므로, 높이 56인 것은 모두 16이다.

| 이름 | 규칙 |
| --- | --- |
| 주 버튼 | 포레스트 면에 아이보리 글자. 높이 56. 화면당 하나 |
| 보조 버튼 | 배경 면에 1px 포레스트 테두리, 포레스트 글자. 높이 56 |
| 글자 버튼 | 면 없이 포레스트 글자, 밑줄 |
| 하단 고정 버튼 | 주 버튼을 화면 맨 아래 고정한 것. 좌우 여백 20, 위쪽에 가림 그라데이션, 시스템 영역을 피한다 |
| 상단바 | 뒤로가기와 제목. 배경 면. 높이 56 |
| 하단 탭바 | 일대기, 홈, 마이페이지. 배경 면. 높이 64. 그림자 높음. 지금 탭은 포레스트에 채운 아이콘, 나머지는 비활성 글자에 선 아이콘 |
| 카드 | 크림 면, 모서리 16, 1px 라인 테두리, 그림자 낮음, 안쪽 여백 16 |
| 입력 상자 | 높이 56, 모서리 16, 크림 면에 1px 라인 테두리. 초점이 가면 배경 면에 1.5px 포레스트 테두리 |
| 칩 | 선택은 포레스트 면에 아이보리 글자, 선택 안 됨은 배경 면에 1px 라인 테두리와 포레스트 글자 |
| 진행 표시 | 라인 색 트랙에 포레스트 막대. 오른쪽에 `n / N`을 캡션으로 둔다 |
| 빈 상태 | 그림과 한 줄 안내. 다음에 할 일을 알려주는 버튼을 함께 둔다 |
| 로딩 | 화면 가운데 포레스트 점 세 개와 한 줄 안내 |
| 준비 중 | "화면 설계 중입니다" 안내. 보류 화면에서 쓴다 |

버튼과 탭처럼 누르는 요소는 **최소 48 x 48**을 확보하고, 누르는 요소 사이를 **12 이상** 띄운다. 주 버튼은 높이 56으로 둔다.

**화면 안의 주 버튼과 하단 고정 버튼을 같은 화면에 함께 두지 않는다.** 무엇이 가장 중요한지 흐려진다.

버튼 글자는 **누르면 무슨 일이 일어나는지 말한다.** 단계를 오가는 버튼은 `다음`, `확인`, `건너뛰기`처럼 짧게 두고, 그 밖의 주 행동은 `녹음 시작하기`처럼 무엇을 하는지 적는다. `여기를 눌러주세요` 같은 말을 쓰지 않는다.

주 버튼의 자리는 화면마다 같다. 아래에 둔다.

## 이미지

| 파일 | 쓰는 곳 |
| --- | --- |
| `logo.webp` | 스플래시 (A-1) |
| `onboarding.webp` | 처음 오셨네요 (B-1) |
| `main.webp` | 홈 |
| `patient.webp` | 프로필 설정 상단 원형 사진 |
| `family.webp` | 세부 정보 입력에서 첨부하는 가족 사진 |
| `visitation.webp` | 면회 인증샷 |

- 모두 `app/assets/images/`에 두고 `pubspec.yaml`에 선언한다.
- 형식은 **WebP**를 쓴다. 파일 이름은 영문 소문자와 하이픈만 쓴다.
- 화면 폭 전체로 쓰는 이미지는 **1236px**까지 만든다. 그보다 크게 만들지 않는다.
- **이미지는 원래 색을 유지한다.** 화면의 색이 절제되어 있으므로 이미지가 화면에서 색이 가장 많은 자리다.
- **배경이 흰 이미지를 그대로 올리지 않는다.** 화면 배경이 크림 계열이라 흰 사각형이 떠 보인다. 배경이 투명한 이미지를 쓰거나 화면 배경색에 맞춘다.
- 홈과 온보딩의 그림은 뒤에 방사형 그라데이션을 깔아 배경에 앉힌다.
- **실제 사람의 사진을 쓰지 않는다.** 저장소 전체 규칙이다.
- 사용자가 앱에서 직접 넣는 사진은 이미지 자산이 아니다. 목 데이터에는 실제 파일이 없으므로 위 이미지로 자리를 채운다.

## 계약 값의 표시 문구

`docs/architecture/data-contracts.md` 는 저장하는 값만 정하고 화면에 무엇이라 쓸지는 정하지
않는다. 화면에서 쓰는 문구를 여기 모아 둔다. **코드에서 문구를 새로 짓지 않고 이 표를 따른다.**

`VisitReport.mood` — 보호자 평가의 대화 만족도에서 계산한다.

| 값 | 문구 |
| --- | --- |
| `hard` | 힘든 만남 |
| `normal` | 잔잔한 만남 |
| `good` | 좋은 만남 |

`CaregiverEvaluation.careRecipientReaction` — 어르신의 반응.

| 값 | 문구 |
| --- | --- |
| `pleased` | 기뻐하셨어요 |
| `calm` | 차분하셨어요 |
| `angry` | 언짢아하셨어요 |
| `lowEnergy` | 기운이 없으셨어요 |
| `unknown` | 잘 모르겠어요 |

`cardReviews[].caregiverReaction` — 카드 한 장에 대한 보호자의 평가.

| 값 | 문구 |
| --- | --- |
| `positive` | 좋았어요 |
| `neutral` | 보통이에요 |
| `negative` | 아쉬웠어요 |

`Profile.condition.stage` — 어르신의 현재 상태.

| 값 | 문구 |
| --- | --- |
| `mildCognitiveImpairment` | 경도 인지장애 |
| `mildDementia` | 경도 치매 |
| `unknown` | 잘 모르겠어요 |

`LifeFact.category` — 생애 정보 항목.

| 값 | 문구 |
| --- | --- |
| `occupation` | 하시던 일 |
| `hometown` | 고향 |
| `hobby` | 취미 |
| `family` | 가족 |

`ChangeProposal.changes[]` — 변경 제안의 종류.

| 값 | 문구 |
| --- | --- |
| `topicPriority` + `direction: up` | 더 자주 꺼내기 |
| `topicPriority` + `direction: down` | 당분간 쉬어가기 |
| `lifeFactAdd` | 새로 알게 된 이야기 |

이 문구는 FE 가 화면을 만들며 정한 초안이다. 제품 문구로 확정하려면 PM 확인이 필요하다.

## 움직임

움직이는 시간은 아래 셋뿐이다. 이 안에서만 움직인다.

| 시간 | 쓰는 곳 |
| --- | --- |
| 120ms | 누름 |
| 200ms | 선택, 토글, 초점 이동 |
| 320ms | 시트와 팝업이 열리고 닫힐 때 |

- 가속은 끝에서 감속하는 곡선을 기본으로 하고, 시트가 올라올 때만 더 빠르게 붙는 곡선을 쓴다.
- **누를 때** 면 위에 포레스트 12% 덮개가 120ms 동안 얹힌다. 크기를 줄이거나 그림자를 바꾸지 않는다.
- **선택할 때** 면과 테두리가 200ms 동안 바뀐다. 체크 표시는 같은 시간에 함께 나타난다.
- **화면 전환**은 Flutter와 안드로이드의 기본 동작을 그대로 둔다. 어느 방향으로 이동했는지 알려주는 단서라서 남긴다.
- **기다리는 동안**에는 점 세 개가 차례로 밝아진다. 뼈대만 깜빡이는 표시(skeleton shimmer)를 쓰지 않는다.
- 튕기며 지나쳤다 돌아오는 움직임(bounce overshoot)을 쓰지 않는다.
- 320ms를 넘는 서서히 사라짐을 쓰지 않는다.
- 스크롤에 따라 배경이 따로 흐르는 움직임(parallax)을 쓰지 않는다.
- 장식을 위한 애니메이션을 넣지 않는다.

<br>

## 접근성

- 기준 화면은 412 x 917 dp 세로다. 고정 좌표에 의존하지 않는다.
- 시스템 글자 크기를 키워도 글자가 잘리거나 겹치지 않아야 한다. 높이를 고정한 상자 안에 긴 글을 넣지 않는다.
- 글자와 배경의 대비는 **4.5:1 이상**을 지킨다. 이 문서의 역할 표에 값이 적혀 있다.
- **색만으로 상태를 알리지 않는다.** 선택, 오류, 완료는 글자나 아이콘을 함께 쓴다.
- 누르는 요소는 최소 48 x 48이고 서로 12 이상 띄운다.
- 화면 변경은 `README.md`에 적힌 기준 크기에서 확인하고 실제 결과를 남긴다.
