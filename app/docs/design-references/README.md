# 디자인 레퍼런스

전면 재디자인에 참고할 UI, UX 자료를 모아 둔 곳이다. 여기서 정리한 내용이
[`app/DESIGN.md`](../../DESIGN.md)의 개정안 재료가 된다.

이 폴더는 **재료**고 DESIGN.md가 **기준**이다. 화면을 만들 때는 DESIGN.md를 따르고
이 폴더를 직접 보고 따라 그리지 않는다.

<br>

## 먼저 지킬 것

**레퍼런스에서 가져오는 것은 형태와 모양이다. 색은 가져오지 않는다.**

색은 `04-Color-palette.webp` 하나에서만 가져온다. 다른 레퍼런스의 색은 아래 표의
`가져올 것` 칸에 무엇이 적혀 있든 참고 대상이 아니다. 예를 들어
`03-Status-bar-and-buttons.webp`의 버튼에서 가져오는 것은 배치와 상태 구분 방식이고
그 주황색이 아니다.

<br>

## 레퍼런스 목록

| 파일 | 가져올 것 | 가져오지 않을 것 |
| --- | --- | --- |
| `01-SeniorDesignGuide.webp` | 시니어 친화적인 버튼 UI 설계 지침 | — |
| `02-font.webp` | 글꼴의 인상. 이 글꼴 자체를 구하는 것이 아니라 **비슷한 느낌의 글꼴을 찾아** 쓴다. 쓰는 자리는 **대화 카드의 메인 질문과 꼬리 질문, 음성 질문 텍스트뿐**이고 그 밖의 자리에는 쓰지 않는다 | — |
| `03-Status-bar-and-buttons.webp` | 세부 정보 입력 화면에 상단 진행 표시줄(단계 `n/N`)과 하단 버튼 구성(`건너뛰기` 글자 버튼 + `다음` / 마지막 단계는 `확인`)을 쓴다. 입력 전에는 비활성, 입력 후 활성으로 바뀌는 구분도 함께 쓴다 | 색(주황). 진행 표시줄과 하단 버튼을 뺀 나머지 UI, UX 전부 |
| `04-Color-palette.webp` | 네 가지 색으로 서비스 색감을 구성한다. 기본 배경은 **두 번째 색**이다. **색은 이 파일에서만 가져온다** | — |
| `05-Character-and-voice-text-conversion-button.webp` | 캐릭터 뒤에 그라데이션을 두는 방식을 **홈 화면과 가입 후 온보딩 화면**에 쓴다. 하단의 음성 텍스트 변환 버튼을 **세부 정보 입력 화면**에 쓴다 | 색. 그 밖의 모든 것 |
| `06-Input-format.webp` | **기본 정보 입력 화면과 보호자 평가 화면**에 체크박스 선택지 UI, 연령대 선택 UI, 그리고 지금 답하는 질문에 집중하도록 나머지 질문의 투명도를 낮추는 처리를 쓴다 | 색. 구간 이동 리모컨, 문항 아래 한 줄 설명 등 |
| [`07-TossDesign.md`](07-TossDesign.md) | 시스템을 운영하는 방식. 자간과 역할별 줄 간격, Pretendard 서체, 크기에 연동되는 모서리, 쓰임새별 그림자 단계, 움직임 상한(120·200·320ms), 상태 표현(눌림은 덮개·비활성은 전체 투명도·초점은 테두리와 배경), 컴포넌트 규칙, 문구 규칙, 색 이름을 원시와 역할 두 층으로 나누는 구조. 항목이 많아 별도 파일로 두었다 | **색 값 전부.** 차갑고 절제된 무채색 인상, 금융 도메인, 본문 15px 기준, 토스 이모지 서체 |

### 칸 설명

- **가져올 것** — 참고할 부분을 구체적으로 적는다.
- **가져오지 않을 것** — **이 칸을 비우지 않는다.** 비어 있으면 화면 전체를 따라 그리게 되고, 레퍼런스마다 다른 방향으로 끌려간다.

<br>

## 정하지 못한 것

DESIGN.md를 고쳐 쓰기 전에 확인해야 한다.

- **`02-font.webp`과 비슷한 글꼴 고르기.** 앱에 넣으려면 글꼴 파일을 `app/assets/`에 두고 `pubspec.yaml`에 선언해야 하므로, 재배포를 허용하는 라이선스인지 확인한다.
- **`04-Color-palette.webp`의 색 값.** 네 색의 순서와 역할은 위 표에 적었고, 실제 값은 DESIGN.md 개정 때 이미지에서 뽑아 `tokens.dart`에 넣는다.
