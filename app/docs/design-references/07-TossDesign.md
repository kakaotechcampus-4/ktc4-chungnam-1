# 07 토스 디자인 시스템

토스(Toss Design System) 정리 문서에서 **색과 분위기를 뺀** UI, UX 규칙만 옮긴 것이다.

이 폴더의 다른 레퍼런스와 같은 지위다. 여기 적힌 것은 **재료**고 기준은
[`app/DESIGN.md`](../../DESIGN.md)다. 화면을 만들 때 이 문서를 직접 보지 않는다.

<br>

## 이 문서를 쓰는 방법

토스는 20~40대가 송금하는 금융 앱이고 새록은 50~60대가 부모님 면회를 준비하는
앱이다. **인상과 색은 가져오지 않는다.** 토스의 무드는 "차갑고 절제된 무채색
캔버스 + 단일 블루"인데, 지금 재디자인하는 이유가 흑백이 건조해서였으므로 그대로
따라가면 같은 문제로 돌아온다. 색은 `04-Color-palette.webp` 하나에서만 가져온다.

가져오는 것은 **시스템을 운영하는 방식**이다. 값보다 규칙이 많고, 규칙은 색이
바뀌어도 그대로 선다.

원본은 공개 문서와 핸드오프 번들을 합성한 제3자 정리본이며, 색 절에 "맞춰 볼
배포물을 찾지 못했다"는 한계가 명시되어 있다. 수치를 옮길 때는 근거가 약할 수
있으므로 **규칙을 우선 가져오고 수치는 우리 기준과 대조한 뒤 쓴다.**

<br>

## 글자

### 크기는 이미 맞는다

현재 DESIGN.md의 글자 표와 토스의 사다리가 일곱 항목 모두 일치한다. **크기를 바꿀
필요가 없다.**

| 우리 역할 | 우리 값 | 토스 토큰 |
| --- | --- | --- |
| 화면 제목 | 28 / 700 | `h1` 28 / 700 |
| 섹션 제목 | 20 / 700 | `h4` 20 / 700 |
| 버튼 | 18 / 600 | `title-1` 18 / 600 |
| 본문 | 17 / 400 | `body-1` 17 / 400 |
| 본문 강조 | 17 / 600 | `title-2` 17 / 600 |
| 보조 | 15 / 400 | `body-2` 15 / 400 |
| 캡션 | 13 / 400 | `body-3` 13 / 400 |

### 얹을 것

- **자간.** 지금 우리 문서에는 자간 규정이 없다. 큰 글자일수록 좁힌다.
  - 28~24: `-2%`
  - 22~20: `-1.5%`
  - 18~17: `-1%` (강조), `-0.5%` (본문)
  - 13 이하: `0`
- **줄 간격을 역할별로 나눈다.** 지금은 "글자 크기의 1.5배" 하나뿐이라 큰 제목이
  뜬다.
  - 제목(28~20): `1.3`
  - 본문과 보조(17~15): `1.5`
  - 버튼과 라벨: `1.25`
  - 캡션: `1.4`
- **서체는 Pretendard.** 토스 자체 서체는 재배포가 금지되어 있고, 원본 문서가
  Pretendard를 가장 가까운 무료 대체로 명시한다. SIL OFL이라 앱에 넣을 수 있고
  위 사다리가 이 서체를 전제로 만들어졌다.
- **고정폭 숫자(`tabular-nums`)를 녹음 화면 경과 시간에 쓴다.** 숫자 폭이
  일정하지 않으면 초가 바뀔 때마다 글자가 떨린다. 금액이 없는 앱이므로
  이 한 자리에만 쓴다.
- **버튼 라벨은 문장처럼 읽히게 둔다.** 장식이 아니다.

<br>

## 간격과 모양

- 기준 단위는 4다. 우리와 같다.
- **관계가 가까울수록 간격을 좁힌다.** 라벨과 입력처럼 붙어 있어야 하는 것은 `8`,
  목록의 행 사이는 `16`, 섹션 사이는 그보다 넓게.
- **모서리를 크기에 연동한다.** 같은 버튼이라도 크면 더 둥글다.

| 높이 | 모서리 |
| --- | --- |
| 56 | 16 |
| 48 | 14 |
| 40 | 12 |
| 32 | 10 |

- 칩과 뱃지는 완전한 둥근 모양을 유지한다.
- **iOS식 뭉개진 사각형(squircle)을 쓰지 않는다.** 정해진 모서리 사다리만 쓴다.

<br>

## 그림자와 깊이

- **평면이 기본이다.** 그림자는 떠 있는 표면에만 쓴다. 지금 DESIGN.md도 같은
  원칙이라 방향이 맞는다.
- **쓰임새별로 단계를 나눈다.** 지금은 낮음과 높음 둘뿐인데 넷으로 나눈다.

| 단계 | 쓰는 곳 |
| --- | --- |
| 1 | 펼친 메뉴 |
| 2 | 말풍선, 툴팁 |
| 3 | 다이얼로그 |
| 4 | 토스트 |

- 아래에서 올라오는 시트는 그림자를 **위쪽으로** 드리운다.
- **그림자 색은 검정이 아니라 팔레트에서 가장 어두운 색을 낮은 투명도로 쓴다.**
  검정 그림자는 화면 위에 회색 얼룩처럼 남는다.
- **안쪽 그림자(inner shadow)를 쓰지 않는다.**

<br>

## 움직임

상한선이다. 이 안에서만 움직인다.

| 시간 | 쓰는 곳 |
| --- | --- |
| 120ms | 누름 |
| 200ms | 토글, 선택, 전환 |
| 320ms | 시트, 다이얼로그 |

- 가속 곡선은 끝에서 감속하는 형태를 기본으로 하고, 시트가 올라올 때만 더 빠르게
  붙는 곡선을 쓴다.
- **튕김(bounce overshoot)을 쓰지 않는다.**
- **320ms를 넘는 페이드를 쓰지 않는다.**
- **패럴랙스를 쓰지 않는다.**
- **스켈레톤 shimmer를 쓰지 않는다.** 대신 점 세 개가 차례로 뛰는 표시를 쓴다.

<br>

## 상태 표현

여기가 이 문서에서 가장 쓸모 있는 부분이다. 색을 늘리지 않고 상태를 만든다.

- **눌림은 그림자가 아니라 덮개다.** 원래 면 위에 어두운 반투명 층을 얹는다.
  버튼마다 눌린 색을 따로 만들지 않아도 된다.
- **비활성은 컴포넌트 전체의 투명도를 낮춘다(0.3).** 글자만 회색으로 바꾸는 식의
  부분 처리를 하지 않는다. 색이 넷뿐인 팔레트에서 특히 유리하다.
- **초점은 테두리를 굵게 하고 배경을 바꾼다.** 입력 상자는 평소 채운 면이다가
  초점이 오면 배경이 밝아지고 테두리가 1px에서 1.5px로 굵어진다.
- **오류는 테두리와 아래 도움말을 함께 쓴다.** 테두리만으로 알리지 않는다.
- **선택은 면을 뒤집는다.** 칩은 평소 테두리만 있다가 선택되면 면이 채워지고 글자가
  반전된다.

<br>

## 컴포넌트 규칙

### 버튼

- 높이 네 단계: `56` `48` `40` `32`. 각 단계의 모서리와 글자는 위 표를 따른다.

### 하단 고정 버튼

- 화면 맨 아래 고정되는 주 액션은 별도 컴포넌트로 다룬다. 화면 안에 있는 버튼과
  역할이 다르다.
- **스크롤되는 내용과 겹치지 않도록 버튼 위쪽에 배경색에서 투명으로 가는
  그라데이션을 둔다.** 색이 아니라 가림 기법이다.
- 아래쪽 시스템 영역(safe area)을 자동으로 피한다.
- **화면 안 주 버튼과 하단 고정 버튼을 같은 화면에 함께 두지 않는다.** 무엇이 가장
  중요한지 흐려진다.

### 목록 행

- **행 전체가 누르는 영역이다.** 오른쪽 화살표만 눌리게 하지 않는다.
- 왼쪽 아이콘 또는 사진, 가운데 제목과 부제, 오른쪽 값이나 화살표 자리를 정해 둔다.

### 메뉴와 시트

- **선택지가 짧으면 누른 자리 근처에 펼친다.** 아래에서 시트를 올리지 않는다.
  "위에서 눌렀는데 답이 아래에서 오면 인지 부하가 커진다"는 이유이고, 원본에서는
  이 변경으로 항목 선택률이 10% 올랐다고 검증되었다.
- 선택지가 많거나 설명이 붙으면 시트를 쓴다. 모바일에서는 다이얼로그보다 시트를
  먼저 고른다.

### 진행 표시

- **단계 표시는 세 상태를 갖는다.** 지난 단계는 채워진 채 완료 표시, 지금 단계는
  채워진 채 강조, 남은 단계는 비어 있다.
- 막대형 진행률은 오른쪽에 고정폭 숫자로 퍼센트를 붙인다.

### 선택 컨트롤

- **체크박스와 분절 컨트롤을 구분해 쓴다.** 여러 개를 고르는 곳은 체크박스나 칩,
  하나만 고르는 곳은 분절 컨트롤이다.
- 체크박스는 작은 정사각에 살짝 둥근 모서리. 평소 테두리, 선택되면 면이 채워지고
  안에 체크 표시가 들어간다.

### 종료 화면

- 가운데 정렬한 표시 하나, 제목, 보조 한 줄, 그리고 그림 하나. 빈 상태와 완료
  화면이 같은 뼈대를 쓴다.

### 아이콘

- 선 아이콘과 채운 아이콘 두 벌을 갖고, **채운 아이콘은 지금 선택된 탭에만 쓴다.**
- 기본 크기는 24. 선 굵기는 1.5 안팎.
- **아이콘 색을 따로 지정하지 않고 글자 색을 물려받게 한다.**

<br>

## 문구

새록은 이미 해요체를 쓰고 있어 방향이 같다. 규칙만 정리한다.

- **해요체로 쓴다.** 격식체(~합니다, ~하십시오)를 쓰지 않는다. 우리 잘못으로 생긴
  오류 화면에서도 해요체를 유지한다.
- **버튼은 일어날 일을 직접 말한다.** "여기를 눌러주세요"가 아니라 "다음",
  "녹음 시작하기"처럼 적는다.
- **오류는 멈춰 세우지 않고 다음으로 안내한다.** 무엇이 잘못됐는지보다 지금 무엇을
  하면 되는지를 먼저 쓴다.
- **한 문장은 목적을 말하고 다음 문장은 언제 쓰는지를 말한다.**
- 쓰지 않는 것: 챗봇 말투("~해보세요!"), 과장("최고의", "혁신적인"), 제목의 느낌표,
  영문 대문자 나열.

`app/DESIGN.md`의 "계약 값의 표시 문구" 표에 있는 값은 이 규칙보다 우선한다.
그 표는 데이터 계약과 묶여 있어 임의로 고치지 않는다.

<br>

## 시스템 운영

- **색 이름을 두 층으로 나눈다.** 지금 `tokens.dart`는 `ink`, `surface`처럼 색 자체의
  이름만 있다. 색이 넷으로 늘면 "이 색을 어디에 쓰는가"가 흐려지므로, 역할 이름
  층을 하나 더 둔다.
  - 1층(원시): 팔레트의 네 색과 그 단계
  - 2층(역할): `배경`, `표면`, `본문 글자`, `보조 글자`, `테두리`, `강조`, `오류`
  - 화면에서는 **2층만 부른다.** 1층은 새 역할을 만들 때만 쓴다.
  - 두 사람이 나눠 작업할 때 해석이 갈리지 않게 하는 장치다.
- **컴포넌트를 직관으로 늘리지 않는다.** 새 모양이 필요해 보이면 기존 것의 변형으로
  풀 수 있는지 먼저 본다.

<br>

## 우리 기준이 이기는 것

토스 값과 우리 값이 다른 자리다. **전부 우리 값을 쓴다.** 옮겨 적지 않도록 적어 둔다.

| 항목 | 토스 | 새록 | 이유 |
| --- | --- | --- | --- |
| 본문 크기 | 15 | **17** | 50~60대 기준으로 정한 값이다 |
| 화면 좌우 여백 | 24 | **20** | 프로토타입 구성을 유지한다 |
| 입력 상자 모서리 | 12 | **16** | 카드와 같은 값으로 맞춰 둔 것이다 |
| 누르는 영역 최소 | 44 x 44 | **48 x 48** | 우리 기준이 더 엄격하다 |

<br>

## 가져오지 않는 것

- **색 값 전부.** 색은 `04-Color-palette.webp`에서만 가져온다.
- **차갑고 절제된 무채색 인상.** 우리가 벗어나려는 방향이다.
- **금융 도메인.** 송금과 결제 흐름, 계좌 목록, 금액 표기, 잔액 증감 표시, 슈퍼앱
  껍데기 구조. 원본 문서도 "차용할 것은 시각 언어이지 금융 서비스 개념이 아니다"라고
  못박는다.
- **금융 데이터용 숫자 규칙.** 고정폭과 비례폭을 나누는 규칙은 녹음 경과 시간
  한 자리에만 쓴다.
- **토스 이모지 서체.** 우리는 `app/assets/images/`에 자체 그림 여섯 개가 있다.
- **막대 차트 규칙.** 리포트에 점수와 등급을 만들지 않으므로 쓸 자리가 없다.
