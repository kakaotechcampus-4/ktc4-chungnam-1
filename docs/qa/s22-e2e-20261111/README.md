# 새록 최종 E2E 검증 보고서

검사일: 2026년 11월 11일. 05:37 KST 1차 집계, 14:07 KST 추가 실기기 검사와 원래 앱 복원 완료

대상: Galaxy S22, 운영 서버, 앱과 백엔드 자동 테스트

문서 상태: GitHub 게시용. 실기기 검사 결과와 게시 전 최신 코드의 자동 검사 결과를 구분했다. 제품 코드 변경과 추가 배포는 포함하지 않는다.

## 1. 결과 요약

Galaxy S22에서 프로필을 입력하고 실제 AI 카드를 생성한 뒤, 합성 녹음과 소감을 운영 서버에 제출해 리포트를 조회했다. 이야기 후보를 수정하고 승인한 다음, 승인한 내용이 다음 카드에 반영되는 것을 확인했다. 두 번째 면회도 녹음 제출부터 리포트와 이야기 후보 조회까지 완료했다.

운영 서버에 제출한 두 녹음은 미리 만든 합성 WAV다. 시험용 앱에서는 녹음 파일을 반환하는 부분만 이 WAV를 사용하도록 바꿨으며, 로그인, API, S3, STT, AI 생성과 DB 저장은 실제 서비스를 사용했다. 이후 원래 마이크 구현을 사용하는 앱으로 되돌려 녹음 유지와 강제 종료 후 복구를 따로 검사했다. 실제 마이크로 녹음한 주변 음성은 서버에 보내지 않았다.

추가 검사에서는 합성 음성으로 실패 후 재요청, 끊긴 전송의 재제출, 짧은 음성 입력을 확인했다. 면회 사진 검사는 카메라 결과만 앱에 포함된 그림 PNG로 대체하고, 실제 업로드와 운영 리포트 표시까지 확인했다. 종료 시 시험용 기능이 없는 원래 APK로 복원했다.

| 구분 | 결과 |
| --- | --- |
| S22와 운영 서버의 핵심 흐름 | 합성 녹음으로 두 회차의 리포트까지 완료 |
| 이야기 확인 후 다음 추천 | 수정 승인한 이야기의 내용이 다음 카드 질문에 반영됨 |
| 저장된 이야기 정정 | 기존 카드 사용을 제한하고 다음 대화 준비에서 재생성한 뒤 카드 선택 가능 |
| 실기기 기능 오류 | 이번 운영 서버 연결 시험에서 새로 확정된 기능 오류 없음. 추가 자동 검사에서 발견한 시험 코드의 화면 접근과 서버 대역 누락을 수정하고 해당 항목 재검사 통과 |
| S22 자동 여정 | 정상 두 회차, 분석 실패 후 재요청, 화자 정보가 부족한 리포트의 3개 여정 통과. 외부 서비스는 합성 대역 |
| Flutter | 실기기 시험 소스: 정적 검사 0건, 1,447개 통과. 최신 코드: 1,330개 통과 후 테스트 파일 로딩 실패 7건, 해당 파일 재검사 128개 통과 |
| 백엔드 | Linux 전체 검사 1,047개 통과. 당시 건너뛴 Docker 검사 3개는 후속 관련 검사 11개에 포함해 모두 통과 |
| STT 패키지 | 자동 검사 45개 통과, 실제 음성 시험 파일이 필요한 1개 건너뜀 |
| AI 패키지 | 자동 테스트 247개 통과 |
| 별도로 기록한 실행 오류 | Windows 백엔드 최초 실패 표시 1건은 원인 미확정. 최신 Flutter 검사에서 테스트 파일 7개의 로딩 실패 후 해당 128개 재검사 통과 |

검사 목록은 총 62개 항목이며, 확인 완료 50개, 일부 확인 9개, 실기기 미실행 3개다. 1차 집계 뒤 6절과 7절의 미완료 항목을 추가로 실행했다. 실제 서버 연결, 실제 마이크의 파일 처리와 서버 응답을 대체한 화면 검사를 구분하며, 전체 기능을 실기기에서 모두 통과했다는 판정은 하지 않는다.

## 4. 실제 마이크와 추가 화면 검사

### 실제 마이크

원래 마이크 구현으로 녹음을 시작한 뒤 다른 앱으로 이동하고 화면을 껐다. 녹음 전경 서비스가 유지됐고, 녹음 데이터 프레임은 272,320에서 565,120, 774,080으로 증가했다. 강제 종료 후 앱을 다시 열었을 때 평가 이어가기 화면도 복원됐다.

이 결과는 해당 조건에서 녹음 처리가 계속됐다는 확인이다. 녹음 파일을 재생하거나 서버에 제출하지 않았으므로 음질, 파일 전체의 무결성과 전사 결과까지 통과한 것으로 보지 않는다.

근거: [마이크 상태 기록](evidence/microphone-state.json), [강제 종료 후 복원 화면 발췌](evidence/synthetic-ui.json).

### Windows 최초 실행의 실패 표시

Windows 백엔드 전체 검사에서 실패 표시 1건이 나온 뒤 실행이 멈췄다. 상세 실패 보고가 완성되지 않아 최초 원인은 확정하지 못했다. 검사 순서로 식별한 `test_like_leaves_evaluation_and_other_cards`는 단독 재실행에서 통과했다.

### 기기 자동 검사 재확인

S22에서 기존 화면 테스트도 추가 실행했다. 카메라, 마이크와 서버 응답은 합성 대역이다. 실제 외부 서비스와 연결한 검사는 위 표와 별도로 구분한다.

첫 실행에서 화면 아래 버튼을 스크롤하지 않고 누른 세 항목, 이전 검사의 키보드가 남은 한 항목이 실패했다. 검사 코드에 스크롤과 키보드 닫기를 넣고 관련 여섯 항목을 다시 실행해 모두 통과했다. 제품 코드는 수정하지 않았다. 시험용 서버 주소로 빠진 요청은 해당 화면의 카드 및 리포트 API 대역을 추가해 차단했다. 사진 동의 후 업로드와 세션 만료 후 로그아웃 두 항목도 다시 실행해 통과했다.

이 검사 코드 변경과 앱 여정을 포함한 PC 재검사 130개도 통과했고, 정적 검사 지적은 0건이다. S22의 첫 전체 자동 실행은 종료 로그에 `+147 -5`와 미완료 항목을 남겼다. 1차 집계의 146개는 종료 전 중간 값이므로 최종 로그 표기로 정정했다. 그 실행 전체를 통과로 적지 않는다. 관련 재검사 로그를 따로 남긴다.

S22의 전체 사용자 여정 3개도 따로 실행했다. 최초 실행에서는 화면 폭에 따라 줄이 바뀐 버튼 문구를 정확한 문자열로 찾는 시험 코드가 실패했다. 같은 버튼의 기존 접근성 이름으로 찾도록 시험 코드만 수정한 뒤 세 여정 모두 통과했다. 이 여정은 실제 앱 화면을 누르지만 운영 서버나 실제 마이크를 쓰지는 않는다.

ADB 연결이 간헐적으로 멈춰 연결을 다시 시작한 경우도 있었다. 앱 기능 오류로 확정하지 않는다. 로컬 APK의 Play 업데이트 검사에서 나온 `ERROR_APP_NOT_OWNED`도 Play에서 설치한 앱이 아닌 시험 환경의 제한으로 구분한다.

## 9. 판정과 근거 자료

**합성 녹음을 사용한 운영 서버 연결 시험에서 최초 프로필 입력부터 두 번째 면회 리포트까지 완료했다. 이야기 승인과 정정, 다음 카드 반영도 확인했다.** 실제 마이크의 녹음 유지와 복구는 별도 검사했으며, 실제 마이크 입력부터 운영 리포트까지 한 번에 이어지는 시험은 남아 있다.
