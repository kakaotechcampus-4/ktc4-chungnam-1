# PM 제품 기준

관리: 주 PM 김영석, 부 PM 이예은

12주 동안 팀이 공통으로 완성할 경험과 최종 목표는 [`12-week-team-goals.md`](12-week-team-goals.md)에서 관리한다.

주간 회의와 보고서 운영은 [`weekly-operations.md`](weekly-operations.md)에서 관리한다.

## 팀과 제품

| 항목 | 값 |
| --- | --- |
| 팀 | 새록새록 |
| 앱 | 새록 |
| 과정 | 카카오테크캠퍼스 충남대 1팀 2단계 |
| 주제 | 더 나은 일상 |
| 제품 | Android 우선 Flutter 모바일 앱 |

## 현재 한 줄 설명

새록은 경도인지장애부터 경도 치매 단계의 부모를 면회하는 보호자에게, 확인된 생애 정보와 지난 면회의 반응을 이용해 오늘 사용할 대화 소재를 제안하고 확인된 이야기를 축적하는 앱이다.

대상을 질환 단계로 한정할지, 대화가 어려워진 부모와 성인 자녀로 넓힐지는 검토 중이다. 확정 전까지 위 문장을 작업 기준으로 사용한다.

## 해결하려는 문제

치매 부모를 정기적으로 면회하는 보호자는 안부 이후 꺼낼 이야기가 부족해 같은 말을 반복하거나 침묵하게 되고, 면회를 제대로 하지 못했다는 죄책감을 느낀다.

제품의 1차 사용자는 보호자다. 환자의 기억 회복이나 병세 개선을 직접 약속하지 않는다.

## 제품 흐름

    프로필과 확인된 생애 정보 설정
    → 필수 동의와 피보호자 동의 확인
    → 대화 카드 후보 생성과 제공
    → 녹음을 포함한 면회
    → STT와 화자 처리
    → 리포트와 보호자 평가
    → 확인된 이야기와 반응 축적
    → 생애 시기별 스토리북 반영
    → 다음 회차 입력

회차가 쌓이면 대화의 질이 계속 좋아진다고 주장하지 않는다. 현재 시점의 피보호자에게 맞는 소재를 고르는 근거가 늘어난다고 설명한다.

## 현재 범위

- 프로필 이미지, 기본 정보, 취향과 생애 정보
- 대화 카드 후보와 추가 대화 지원
- 녹음을 포함한 면회
- 로컬 STT와 화자 처리 검토
- 회차 리포트와 보호자 평가
- 생애 시기별 이야기 블록과 스토리북
- 확인된 반응과 이야기를 다음 회차에 반영

## 개인정보 동의 기준

- 필수: 서비스 제공을 위한 개인정보 처리
- 필수: 건강 관련 민감정보 처리
- 필수 확인: 피보호자 본인 또는 적법한 대리인의 동의 확인
- 기능 이용 시 필수: 프로필 이미지 분석
- 선택: 서비스 품질 개선용 가명정보 활용
- 선택: 면회 준비와 리포트 완료 푸시 알림

외부 STT와 LLM은 업체명, 처리 국가, 보유기간, 자체 학습 여부와 처리위탁 또는 국외 이전 근거를 확정한 뒤 도입한다.

## 비범위

- 의료 진단, 병세 예측과 치료 효과 주장
- 피보호자가 직접 사용하는 인지 훈련
- AI가 보호자를 대신해 피보호자와 대화
- 확인되지 않은 생애 사실 추정
- 말기 치매 대상의 초기 MVP 검증

## 대화 상태 원칙

- 기존 주제가 이어지면 개입하지 않고 기록
- 다른 주제로 바뀌어도 대화가 이어지면 새 주제로 기록하고 개입하지 않음
- 주제가 바뀐 뒤 대화가 멈추면 추가 지원 방식 검토

## 검토 중인 제품 결정

- 최종 대상 표현
- 초기 카드 수와 추가 제공 방식
- AI 자동 선택과 보호자 최종 선택 중 결정권
- 더하기 버튼과 실시간 자동 제안 중 추가 대화 실행 방식
- 꼬리 질문, 기존 후보와 보호자 입력 기반 질문의 우선순위
- 웹 검색 사용 여부
- 사용자 설정 범위
- 스토리북의 피보호자 직접 제공 여부
- 스토리북의 실물 앨범 제작과 판매 여부

검토 중인 사항은 구현자가 임의로 확정하지 않는다.

## 담당자 위임

- FE: Flutter와 Android 버전, 화면, 녹음 상태 화면, 사용자 권한과 합의된 인터페이스 연동
- AI: 이미지, 녹음 라이브러리, 음성 형식, STT, 화자 처리와 생성 모델 및 품질 기준
- BE: 단말 데이터 구조와 로컬 DB, 모델 실행 연동, 처리 파이프라인, 데이터 경계와 선택적 서버
- QA: 평가 자료, 평가 방식과 통과 기준

## 역할

| 역할 | 담당 |
| --- | --- |
| 주 PM | 김영석 |
| 부 PM | 이예은 |
| BE 리드 | 김민혁 |
| FE 리드 | 이서형 |
| AI 리드 | 이문영 |
| 팀원 | 성채원, 이인성 |

Issue와 PR 진행 상태 및 최종 병합은 주 PM과 부 PM이 관리한다. 기술 변경은 해당 영역 담당자가 먼저 검토한다.

## 변경 규칙

- 제품 대상, 범위와 성공 기준 변경은 PM 검토 필요
- 확정, 담당자 위임, 검토 중과 미정을 구분해 기록
- 회의 결정이 바뀌면 이 문서와 영향을 받는 역할 문서를 함께 갱신
