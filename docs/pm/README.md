# PM 제품 기준

관리: 김영석, 이예은 | 갱신: 2026-09-19

## 제품과 대상

새록새록 팀의 카카오테크캠퍼스 충남대 1팀 2단계 프로젝트다. 보호자가 면회 전에 확인된 생애 정보와 지난 반응으로 대화 소재를 준비하고 확인된 이야기를 축적하는 Android 우선 Flutter 앱이다.

초기 대상은 경도인지장애부터 경도 치매 단계의 부모를 면회하는 보호자다. 대화가 어려워진 부모와 성인 자녀까지 넓힐지는 검토 중이다. 안부 이후 소재 부족, 반복과 침묵으로 느끼는 보호자의 부담을 다룬다.

## 제품 범위

| 포함 | 제외 |
| --- | --- |
| 프로필 이미지, 기본 정보, 취향과 생애 정보 | 의료 진단, 병세 예측, 기억 회복과 치료 효과 주장 |
| 대화 카드와 추가 질문 지원 | AI가 보호자를 대신해 대화 |
| 면회 녹음, STT와 화자 처리 | 피보호자 직접 인지 훈련 |
| 보호자 평가, 리포트와 변경 제안 | 확인되지 않은 생애 사실의 자동 반영 |
| 생애 시기별 이야기와 다음 회차 반영 | 말기 치매 대상 초기 검증 |

실물 스토리북 판매와 iOS는 후속 검토다. 요구사항별 상태와 제외 이유는 [테크스펙](../tech-spec.md)에 기록한다.

## 제품 흐름과 확인 원칙

프로필과 사진 후보 확인 → 대화 카드 → 동의와 권한 확인 후 면회 녹음 → 음성 처리와 보호자 평가 → 리포트와 변경 제안 → 승인된 이야기와 반응 반영 → 다음 회차.

- 현재 목 계약에서는 보호자 평가가 리포트 생성의 입력이다.
- 대화가 이어지면 주제가 달라져도 개입하지 않는다. 주제가 바뀐 뒤 대화가 멈추면 추가 지원을 검토한다.
- 메타데이터와 AI 출력은 후보이며 보호자 확인 전 사실로 반영하지 않는다.
- 분석 실패 시 계산하지 못한 수치를 만들지 않고 보호자 입력으로 전환한다.
- 한 회차의 반응이나 카드 미사용 및 미응답만으로 소재를 영구 제외하지 않는다. 사용자가 직접 추천 제외를 선택하는 경우는 아래 기준을 따른다. 승인 후 변경은 되돌릴 수 있어야 한다.
- 회차가 쌓이면 소재 선택의 근거가 늘어난다고 설명하며 대화의 질 향상이나 치료 효과를 보장하지 않는다.

분기와 반복은 [목표 흐름](../architecture/README.md#목표-사용자-흐름)을 참고한다.

## 2026-09-19 PM 결정

### 카드 미사용과 추천 제외

카드를 쓰지 않은 이유는 시간 부족이나 나중에 이야기하려는 선택일 수도 있다. 미사용과 미응답만으로 비선호를 추정하거나 추천 순위를 낮추거나 추천 대상에서 제외하지 않는다.

추천 제외는 사용자가 `앞으로 추천하지 않기`처럼 의사를 직접 표시했을 때 적용한다. 추천 대상에서 제외하는 것이며 과거 카드와 면회 기록을 삭제한다는 뜻은 아니다. 카드 추천은 핵심 기능이므로 로직을 별도로 설계한다. 제외할 대상의 범위, 해제 방법, 화면과 저장 필드 및 API는 후속 설계에서 함께 정한다.

### 면회 기록 삭제와 승인된 사실

면회 기록을 삭제해도 보호자가 이미 승인해 프로필에 넣은 사실은 유지하고, 삭제한 면회와의 출처 연결만 해제한다. 기록을 지운 이유만으로 승인한 사실까지 틀렸다고 판단할 수 없기 때문이다. 삭제 행동을 부정적 감정이나 카드 비선호로 자동 해석하지 않는다.

면회에서 확인한 사실은 생성 시 출처 회차를 연결하고, 해당 회차가 삭제된 뒤에는 연결값을 비울 수 있다. 필드 규칙은 [LifeFact 계약](../architecture/data-contracts.md#확인된-생애-사실-lifefact)을 따른다. 이 결정은 면회 기록 삭제에 한정하며 계정 탈퇴나 프로필 삭제 범위를 정한 것은 아니다.

### 개발 GPU와 시연 장비

현재 RTX 3060 Ti는 개발용이다. 시연에 필요한 장비 사양과 처리 성능은 AI와 BE의 추가 실험 결과를 보고 정한다. RTX 3060 Ti를 최종 시연 장비로 확정하거나 상시 가동 및 새 장비 구매를 승인한 것은 아니다.

## 처리와 동의

STT와 VLM은 온프레미스 GPU 1대에서 처리하고 데이터 관리도 서버 중심으로 전환하기로 했다. 현재 RTX 3060 Ti는 개발용이며 시연 장비의 사양은 실험 후 정한다. BE가 데이터별 저장과 처리 범위를 PR로 정리하고 FE, AI와 PM이 확인한다. 시연 장비, 운영, 모델, 이미지 출력과 세부 저장 계약의 미정 사항은 [ADR-006](../architecture/decisions/ADR-006-server-side-ai-processing.md)에 구분했다. 원본은 처리 후 즉시 삭제하고 최대 24시간을 넘기지 않는 기존 제한을 유지한다.

필수 동의는 개인정보 처리, 건강 관련 민감정보 처리와 피보호자 동의 확인이다. 이미지 분석은 기능 이용 시 동의를 확인한다. 품질 개선과 푸시 알림은 선택이며 거부해도 가입과 기본 기능을 차단하지 않는다. 대리 동의의 자격과 절차는 검토가 필요하다. 자세한 문구와 외부 전송 조건은 [법률 문서](../legal/README.md)가 정본이다.

## 검토 중인 제품 결정

| 결정 | 확인할 내용 |
| --- | --- |
| 최종 대상 | 질환 단계 한정 또는 부모와 성인 자녀로 확대 |
| 카드 제공 | 계약에는 12장 생성, 9장 제시와 3장 보충, 보호자 선택으로 명시되어 있으나 기존 PM 미결 목록과 달라 확정 여부 확인 필요 |
| 추가 대화 | 수동 요청 또는 실시간 제안, 꼬리 질문과 기존 후보 및 직접 입력의 우선순위 |
| 기억과 추천 | 확인된 사실, 최근 반응, 미확인 후보의 저장과 검색 및 갱신 규칙. 미사용 및 미응답 불이익 금지와 명시적 추천 제외 원칙은 확정했고, 추천 로직과 제외 범위 및 해제 방식은 별도 설계 |
| 데이터 관리 | 서버 중심 방향에 맞춘 데이터별 저장 범위, 단말 보관 여부, 접근 권한, 보관 기간과 삭제 구현 |
| 후속 확장 | 웹 검색, 사용자 설정, 스토리북 직접 제공과 실물 판매 |

현행 계약과 제품 기준이 다른 항목은 [계약 정합성 확인 목록](../architecture/data-contracts.md#현재-적용-범위)에서 함께 확인한다. 미결 정책을 구현자가 임의로 확정하지 않는다.

## 역할

| 담당 | 역할과 지원 관계 |
| --- | --- |
| 김영석 | 주 PM, 문제와 범위, 우선순위, PR 병합과 제출 |
| 이예은 | 부 PM, 결정 검토와 기록, 제출 및 진행 관리, 주 PM 부재 시 진행 |
| 이서형 | FE 리드, Flutter 화면과 접근성, 권한 및 합의된 인터페이스 연동 |
| 김민혁 | BE 리드, 저장과 데이터 이동, API, 서버 실행 연동과 로그 및 삭제 |
| 이문영 | AI 리드, 이미지와 음성 모델, 녹음 입력, 생성과 품질 및 실패 기준 |
| 성채원 | 정보 수집과 QA 전반, FE 중심 지원 |
| 이인성 | AI와 BE 리더 지원, 실험과 구현 검증 |

모델은 AI, 저장과 실행 구조는 BE, 화면과 앱 연동은 FE가 기술 검토한다. 공통 계약은 함께 확인하고 PM이 범위와 진행을 관리한다. 개인별 작업과 기한은 GitHub 이슈, 리뷰와 병합은 [협업 규칙](../../CONTRIBUTING.md)을 따른다.

[12주 목표](12-week-team-goals.md)와 [주간 운영](weekly-operations.md)은 별도 관리한다. 제품 대상, 범위나 성공 기준을 바꾸면 PM 확인 후 이 문서와 관련 명세를 함께 갱신한다.
