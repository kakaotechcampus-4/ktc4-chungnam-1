# 남은 보안 작업과 확인 방법

작성일: 2026년 11월 11일, KST. [최종 보고서](README.md), [점검 결과와 처리 내용](remediation.md).

우선 보완할 것은 음성을 글로 바꾸는 STT의 파일 처리 문제 3개다. 파일 저장소(S3)의 자동 삭제는 PM 보류 상태다. 그 밖의 항목은 관련 기능 수정, 이용량 확대, 백업 복원이나 배포 확인 시점에 함께 다룬다.

## 먼저 고칠 음성 처리 문제

아래 3개는 11월 8일 시험에서 확인했고, 원인 코드가 남아 있는 문제다. 이번 보고서 작성 중 최신 운영 서버에서 다시 시험하지는 않았다. 기존 Tailscale 사설망 연결은 유지한다.

| 문제 | 필요한 수정 | 수정 후 확인할 것 |
|---|---|---|
| 짧은 음성 파일을 다시 검사하는 동안 다른 요청도 지연될 수 있음 | 최초 검사는 이미 별도 실행한다. 남은 두 번째 검사도 요청 처리를 붙잡지 않게 변경 | 시험용 WAV 음성 파일을 검사하는 동안 다른 요청이 정상 처리되는지 확인 |
| 파일 검사 결과와 실제 음성 처리 결과가 다름 | 형식 정보가 중복된 비정상 파일을 거절하거나, 실제로 읽은 음성 데이터 양을 제한 | 작은 시험용 파일로 검사와 실제 처리의 차이가 해소됐는지 확인 |
| STT 프로그램 강제 종료 후 임시 녹음이 남음 | 정상 종료 시 삭제는 유지하고, 재시작 때 남은 임시 파일을 찾아 정리 | 시험 전용 폴더에서 강제 종료와 재시작 후 파일이 지워지는지 확인 |

짧은 전사는 [PR #285](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/pull/285)에서 계정별 동시 2개로 제한했다. @Sogeum100g의 [PR #317](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/pull/317)은 11월 11일 02:15 KST 병합됐고, 대기 기본값 90초와 선택적으로 켤 수 있는 서버 전체 동시 처리 제한을 추가했다. 전체 제한은 기본적으로 꺼져 있으며 운영에서 켰는지는 별도 확인 대상이다.

## 관련 작업을 할 때 함께 보완할 것

| 처리 시점 | 할 일 | 완료 확인 방법 |
|---|---|---|
| PM이 실제 삭제를 승인한 뒤 | S3 파일 삭제를 예약 실행하고, 사진의 이전 버전 처리와 실패 재시도를 정리 | 삭제 대상과 남길 자료를 구분하고 실제 삭제 완료 확인. 이번에는 자료 삭제나 AWS 설정 변경을 하지 않음 |
| 로그 관리 방식을 바꿀 때 | 생성 로그의 보관기한과 누적량 결정 | 원문 제거와 입력 상한은 유지하고, 정한 기한에 오래된 기록이 정리되는지 시험 |
| 이용량을 늘리기 전 | 계정별 하루 AI 생성 횟수 또는 비용 제한 결정 | 요금이 발생하지 않는 모의 호출로 제한과 안내 동작 확인 |
| STT의 시간 제한과 취소 처리를 고칠 때 | 실행 순서를 기다린 뒤에도 기한을 재확인하고, 처리 중 취소를 GPU 작업에 전달 | 시험용 처리 프로그램으로 만료와 취소 후 다음 작업이 정상 진행되는지 확인. 시작 전 만료와 24시간 초과 검사는 이미 있음 |

## 실제 문제가 생기는 조건을 더 확인할 항목

다음 6개는 추가 확인 후보다. 현재 노출이나 피해가 확인된 취약점으로 집계하지 않는다.

| 확인할 내용 | 현재까지 확인한 사실 | 언제, 어떻게 확인할지 |
|---|---|---|
| 다른 앱이 새록 내부 화면을 열 수 있는지 | 일반 웹링크를 받는 설정은 없고 로그인과 선택한 프로필이 필요함 | 앱 진입 화면을 바꿀 때, 시험용 앱에서 새록 화면을 직접 열어 실제 요청까지 이어지는지 확인 |
| 중단한 업로드의 파일 조각이 남는지 | 11월 8일에는 남은 조각 0개였음. 현재 값은 미확인 | 삭제 운영을 준비할 때 모의 저장소에서 업로드 중단과 조각 정리를 시험. AWS 임의 조회나 변경은 하지 않음 |
| 면회 음성의 빠른 삭제가 끝까지 확인되는지 | 삭제 요청 성공 후 상태를 기록함. 짧은 전사는 별도 대기열에서 파일이 없다는 응답까지 확인 | 삭제 코드를 고칠 때 이전 버전, 권한 거절, 응답 실패를 모의 저장소로 시험 |
| 과거 백업을 복원한 뒤 탈퇴와 동의 철회가 유지되는지 | 자동 복원 금지와 승인 절차는 있음. 백업 이후 변경을 다시 적용하는 절차는 보완 필요 | 복원 전에 시험 자료로 탈퇴, 동의 철회와 로그인 토큰 폐기를 다시 적용하는 절차 확정 |
| STT 오류 기록에 음성 파일 접근 주소가 남는지 | 내부 오류 원인에 유효기간이 있는 파일 접근 주소를 보유하는 경로가 있음. 운영 기록 노출은 미확인 | 로그 처리를 고칠 때 가짜 주소를 넣어 최종 기록까지 따라가며 확인. 실제 파일 접근 주소는 출력하지 않음 |
| 설치한 AI 모델의 버전이 고정돼 있는지 | CK 예비 서버는 저장된 모델을 오프라인으로 읽음. 승인 모델 버전과 주 GPU의 저장 정책은 미확인 | 모델 설치나 교체 때 출처, 고정 버전 또는 파일 식별값을 기록 |

## 추가로 보강할 수 있는 부분

관련 코드를 수정할 때 함께 검토할 후보다. 새 확정 취약점 수에 더하거나 별도 담당자와 필수 마감일을 지정하지 않았다.

| 대상 | 이미 있는 보호 | 추가로 확인할 것 |
|---|---|---|
| 사진 분석 동의와 카드 문장 | 동의 철회 시 AI 사진 설명 삭제, 지운 근거를 새 카드 입력에서 제외 | 이전 카드에 복사된 문장을 어떻게 처리할지 |
| 기기 자료와 알림 | 정상 탈퇴 후 자료 정리, 계정별 파일 분리, 로그아웃 시 서버와 알림 도구에서 등록 해제 | 탈퇴 응답을 못 받은 경우, 다른 기기에서 탈퇴한 경우, 기기 파일 삭제 실패와 발송 중인 알림 처리 |
| 사진 원본 | AI 입력에 촬영 정보 전용 항목을 따로 넣지 않음 | 시험용 위치 정보를 넣은 사진으로 실제 업로드와 외부 AI 전달 파일 확인. 현재 위치 유출이 확인됐다는 뜻은 아님 |
| 외부 AI의 자료 보관 | 결과 저장을 끄는 옵션(`store=False`) 요청, 제품 코드에서 Agents 실행 추적 기능을 쓰지 않는 것 확인 | 공급자의 보관 계약과 운영 추적 설정. 요청 옵션만으로 무보관을 보장할 수는 없음 |
| 시험 환경의 인증정보 | 기본 시험은 가짜 음성과 메모리 저장소 사용, `.env` 자동 읽기 차단, 지정한 비밀 파일 제외 | 실제 연결 시험용 저장소 구분, 시험 프로그램에 필요한 환경변수만 전달, 실제 알림 인증파일 이름도 제외되는지 |
| 서버 실행 권한과 외부 코드 | BE를 관리자 권한 없이 실행, 일부 서비스 권한 제한, 주요 자동화 도구의 버전 고정 | 필요한 경로만 쓰도록 제한하고 나머지 도구와 실행 이미지의 버전 고정 검토. 운영진 AWS 권한은 제외 |
| 자동 검사와 백업 복원 | 제품 회귀 시험, 앱과 서버 연결 시험, 격리 DB 복원 성공 | 인증정보와 외부 라이브러리 취약점 검사 도입 여부, 시험용 DB 원본과 복원본 비교 |

세부 코드와 확인 범위는 [보호 기능별 코드 근거](controls.md)에 있다.

## 배포와 문서를 확인할 때

- 실제 서버 코드 버전, DB 구조 변경, 앱 버전과 서명을 확인한다. 코드 병합과 실제 서버 적용은 구분한다.
- 서버의 API 안내 화면인 `/docs`, `/redoc`, `/openapi.json` 차단은 BE 운영 모드에서만 작동한다. STT 서버의 문서 설정은 별도다.
- 서버 앞단(Caddy)의 요청 크기 제한과 DB 백업 정리 예약 작업에는 11월 9일 적용 기록이 있다. S3 파일 삭제 자동 운영은 여전히 보류다.
- 사진 보관 동의와 사진 AI 분석 동의의 결정, 앱 화면과 개인정보처리방침 설명을 맞춘다.
- 녹음 원본, 전사문, 백업, 이전 파일 버전과 외부 AI 제공자의 보관기한을 따로 확인한다.
- 11월 8일의 삭제 대기 파일 219개, 중단된 업로드 조각 0개, 음성 저장소의 버전 관리 꺼짐은 당시 관측값이다.
- 마지막으로 정상 복원한 백업 1개는 보존한다. 이 백업이 14일을 넘겼다는 이유만으로 정리 실패로 판단하지 않는다.

## 유지할 기존 결정

| 대상 | 처리 기준 |
|---|---|
| 운영진 AWS와 자동화 토큰 | 팀 수정 범위에서 제외. 추가 조회, 권한 변경, 토큰 값 확인과 외부 문의 없음 |
| 기존 Tailscale STT 연결 | 사설 주소 설정과 연결 확인 기록이 있으며 기존 운영 유지. 공개 노출이나 우회가 확인된 것은 아님 |
| GitHub 배포 승인 | 기존 PM 승인, 본인 승인 허용과 main/develop 배포 범위 유지 |
| 앱 업로드 서명키 | 확인한 GitHub 비밀 설정에 키가 없어 현재 노출 문제로 보지 않음. 향후 등록 때 사용할 자동화 작업과 접근 범위 확인 |
| 개인 PC의 AI 시험 도구 | 이전 PM 결정대로 이번 팀 제품 수정 대상에서 제외 |
| 사용자 자료 | 임의 삭제 금지, 로그아웃 후 녹음 보관 정책 유지. 이야기 후보는 보호자 확인 후 확정 |
| GPU 구성 | 주 GPU 우선, CK는 제한된 예비 경로로 유지 |

## 추가 시험 원칙

시험은 가짜 계정, 사진과 음성을 사용해 격리 환경에서 한다. 외부망과 실제 인증정보를 차단하고 전용 임시 폴더, 자원과 시간 제한을 둔다. 운영 API, 실제 사용자 자료나 공유 GPU에는 공격 입력을 보내지 않는다.

이번 문서 수정에서는 제품 실행, 권한 변경이나 실제 자료 삭제를 하지 않았다.
