# 남은 보안 작업과 처리 기준

작성일: 2026-11-11, KST. [최종 보고서](README.md), [기존 26건 대조표](remediation.md).

지금 우선할 항목은 과거에 재현된 STT 파일 처리 3건이다. S3 자동 삭제는 PM 보류를 유지한다. 나머지는 해당 기능의 수정, 모델 교체, 복원이나 배포 확인과 함께 다룬다. 이 목록 전체를 확정 취약점이나 출시 차단 조건으로 취급하지 않는다.

## 1. 우선순위와 완료 조건

| 처리 시점 | 항목 | 필요한 작업과 완료 근거 |
|---|---|---|
| 다음 STT 수정 | R13 짧은 전사의 동기 WAV 재파싱 | 최초 검사는 이미 스레드에서 실행한다. 남은 두 번째 검사가 요청 처리를 막지 않게 보완하고 합성 WAV 회귀 시험 |
| 다음 STT 수정 | R23 WAV 검증기와 디코더 해석 차이 | 중복 fmt 등 비정상 입력을 거절하거나 디코더의 실제 출력 샘플 수를 제한. 작은 합성 WAV로 수정 전후 확인 |
| 다음 STT 수정 | R22 강제 종료 후 임시 음성 | 정상 finally 정리는 이미 존재한다. 전용 임시 경로에서 강제 종료와 재시작 후 정리 확인 |
| PM이 실제 삭제를 승인한 뒤 | R15 S3 자동 삭제 운영 | 실행 예약, 사진 버전 처리, 실패 재시도와 완료 확인. 실제 자료 삭제나 AWS 설정 변경은 이번에 실행하지 않음 |
| 로그 관리 변경 | R06 생성 로그 누적 | 원문 제거와 입력 상한은 반영됨. 남은 누적량과 보관기한 결정 및 검증 |
| 이용량을 늘리기 전 | R08 장기 AI 비용 | 입력과 동시 수 제한은 유지. 계정별 일일 생성량 또는 금액 기준을 정하고 과금 없는 모의 호출로 검증 |
| STT 처리 제어 변경 | R26 실행 중 기한과 취소 | 시작 전 만료 및 24시간 초과 검사는 존재. 잠금 대기 이후와 추론 중 취소 전파, 다음 작업 진행을 합성 worker로 확인 |

R13, R22, R23은 **11월 8일 재현 이력과 원인 코드 존속**을 확인했다. 이번 최종 보고서 작업에서 최신 환경에 공격 입력을 보내거나 영향도를 새로 측정하지 않았다. Tailscale 접근 방식과 연결하지 않는다.

짧은 전사의 계정별 동시 2건 제한은 #285로 병합됐다. @Sogeum100g의 [PR #317](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/pull/317)은 11월 11일 02:15 KST 병합됐고, 대기 기본값 90초와 선택적 서버 전체 상한을 추가했다. 전역 상한 기본값은 제한 없음이며 운영 활성화를 확정하지 않는다.

## 2. 기존 목록의 조건부 확인 6건

| 번호 | 항목 | 현재 사실 | 확인 시점과 최소 범위 |
|---|---|---|---|
| R02 | Android 외부 진입 | MAIN/LAUNCHER만 있고 VIEW/BROWSABLE 필터 없음. 웹링크나 무인증 공격 성립 미확인 | 라우터/진입점 변경 시 격리 APK로 다른 설치 앱의 명시 intent, 로그인과 선택 프로필 조건 확인 |
| R04 | 중단된 multipart 조각 | 11월 8일 잔존 0개. 현재 잔존이나 피해 확인 아님 | 삭제 운영을 적용할 때 합성 저장소로 업로드 중단과 정리 경로 확인. AWS 임의 조회/변경 금지 |
| R12 | 면회 음성 빠른 삭제 완료 확인 | DeleteObject 뒤 상태 기록. 짧은 전사는 별도 대기열과 HEAD 404 확인이 있음 | 삭제 코드 변경 시 버전, 권한 거절과 응답 실패를 모의 저장소에서 확인 |
| R16 | 과거 DB 복원 후 철회 재적용 | 자동 복원 금지와 승인 절차 있음. 백업 이후 탈퇴/동의 철회/토큰 폐기 재적용 절차 공백 | 복원하기 전에 합성 자료로 재적용 절차 확정. 실제 개인정보가 부활한 사건으로 기록하지 않음 |
| R21 | STT 예외의 presigned URL | 오류 cause에 URL을 보유하는 경로 있음. 실제 운영 로그 노출 미확인 | 로그 처리 변경 시 가짜 URL과 예외 체인으로 확인. 실제 서명 URL 출력 금지 |
| R25 | 모델 revision 고정 | CK offline 설정 있음. 승인 revision과 주 GPU 캐시 정책은 미확인 | 모델 설치/교체 때 승인 저장소와 불변 revision 또는 해시 기록. 현재 침해로 판정하지 않음 |

이 6건은 모두 즉시 개발을 중단해야 할 취약점이 아니다. 공격 조건, 노출과 영향을 확인하기 전에는 심각도나 피해를 확정하지 않는다.

## 3. 추가 보강 후보

다음은 기존 26건에 새 확정 취약점으로 더하지 않는다. 관련 코드를 수정할 때 함께 검토할 후보이며 별도의 담당자 요청이나 필수 마감은 만들지 않았다.

| 묶음 | 이미 있는 조치 | 남겨 둘 확인 |
|---|---|---|
| 동의와 파생 문장 | 사진 설명 제거, 지운 근거의 새 입력 제외 | 과거 카드에 복사된 문장의 처리 기준 |
| 기기 자료와 푸시 | 정상 탈퇴 후 정리, 계정별 파일 분리, 로그아웃 서버/SDK 푸시 해제 | 탈퇴 응답 유실, 다른 기기 탈퇴, 로컬 삭제 실패의 재시도와 오프라인 푸시 경합 |
| 사진 원본 | AI 입력의 전용 EXIF 필드 제외 | 합성 EXIF 사진으로 실제 업로드와 외부 AI 전달 파일의 메타데이터 확인. GPS 유출 확정 아님 |
| 외부 AI | store=False 요청, 제품 코드의 Agents tracing 미사용 확인 | 공급자 보관 계약과 운영 추적 설정. 요청 옵션만으로 무보관 보장 금지 |
| E2E와 비밀 분리 | 기본 합성 STT/메모리 저장소, .env 자동 읽기 차단, 비밀 파일 제외 | 로컬 실제 E2E의 테스트 버킷 구분, 자식 환경 허용목록, 서비스별 필요한 변수만 전달, 실제 FCM 파일명 제외 |
| 컨테이너와 공급망 | BE 비root, 일부 systemd 보호, 주요 action SHA와 locked 설치 | 팀 코드의 읽기 전용 파일시스템/capability, 나머지 action/이미지/Gradle 고정. 운영진 AWS 권한은 제외 |
| CI와 복원 | 제품 회귀 CI, 합성 E2E, 격리 DB 복원 성공 | 비밀 탐지/의존성 검사 도입 여부, 합성 DB 원본과 복원본 무결성 비교. 검사 도구 부재를 취약점으로 세지 않음 |

구체 코드와 한계는 [보호 조치 목록](controls.md)에 있다. 검토 후보를 확정 취약점 수에 추가하지 않는다.

## 4. 배포와 문서 확인 때 구분할 사항

- 서버 SHA, migration, 앱 버전과 서명을 실제 배포본과 대조한다. 코드 병합을 운영 적용 완료로 쓰지 않는다.
- BE의 /docs, /redoc, /openapi.json 차단은 production 설정일 때만 작동한다. STT 앱까지 같은 차단이 된 것은 아니다.
- Caddy 제한과 백업 정리 timer는 11월 9일 적용 기록이 있다. S3 삭제 자동 실행과 혼동하지 않는다.
- 사진 보관 동의와 사진 AI 분석 동의의 최신 결정, UI, 처리방침 설명을 맞춘다.
- 원본, 전사, 백업, 이전 버전과 외부 제공자의 보관기한을 나눈다. 11월 8일의 삭제 대기열 219건, multipart 0개, 음성 버킷 NeverEnabled는 당시 관측값이다.
- 마지막 정상 복원 확인 백업 1개를 남기는 정책 때문에 14일이 지난 백업이 있다는 이유만으로 정리 버그로 판단하지 않는다.

## 5. 제외와 기존 결정

### 설정 확인과 PM 범위 정정

| 대상 | 최종 처리 |
|---|---|
| 운영진 AWS, AUTO_ASSIGN_PAT | 팀 보안 이슈와 필수 요청에서 제외. 추가 조회, 설정 변경, 토큰 값 확인과 외부 문의 없음 |
| 기존 Tailscale STT | 사설 주소 설정과 연결 확인. 기존 운영 유지. 공개 노출이나 우회가 확인된 것 아님 |
| GitHub 배포 승인 | 기존 PM 승인, 본인 승인 허용과 main/develop 배포 범위 유지 |
| APK 업로드 서명키 | 확인한 GitHub 시크릿 범위에 키 없음. 현재 키 노출 이슈 아님. 향후 키 등록 시 사용 job과 보호 범위 확인 |
| 로컬 시뮬레이터 | 이전 PM 결정대로 이번 팀 제품 수정 대상에서 제외 |
| 실제 자료와 확인 단계 | 임의 삭제 금지. 로그아웃 후 녹음 보관 정책 유지. 이야기 후보는 보호자 확인 후 확정 |
| GPU 구성 | 주 GPU 우선, CK는 제한된 예비 경로. 보고서 정리로 구조와 사용 범위를 변경하지 않음 |


## 6. 새 시험이 필요할 때

운영 API, 실제 계정과 녹음/사진, 공유 GPU에는 공격 입력을 보내지 않는다. 소스와 도구는 읽기 전용으로 두고, 빈 환경의 허용 변수, 외부망 차단, 임시 작업 디렉터리, 자원과 시간 제한을 갖춘 격리 환경에서 합성 자료로 해당 경로만 검사한다.

문서 게시 과정에서 제품 실행, 권한 변경이나 실제 자료 삭제는 하지 않았다.
