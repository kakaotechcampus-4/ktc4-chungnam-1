# 새록 보안 조치 최종 보고서

새록은 보호자가 면회 대화를 준비하고, 녹음한 대화를 리포트와 이야기로 정리하는 앱이다. 이 보고서는 로그인 정보, 사진, 녹음과 이야기 자료를 보호하기 위해 구현한 기능과 남은 작업을 설명한다.

로그인 확인, 다른 계정의 자료 접근 차단, 동의 철회 반영, 파일 크기 제한, AI 결과 검사와 로그의 개인정보 축소가 구현돼 있다. 우선 보완할 부분은 **음성을 글로 바꾸는 STT의 파일 처리 3개**다. 파일 저장소(S3)의 자동 삭제 운영은 시험 자료 보존을 위한 PM 보류 상태다.

작성일은 2026년 11월 11일이며, PR 상태는 같은 날 02:34 KST 기준이다. 소스 검토 버전과 이후 변경은 문서 하단에 구분했다.

## 어떤 보호 기능을 구현했나

| 보호할 대상 | 구현한 내용 | 아직 구분해서 봐야 할 점 |
|---|---|---|
| 로그인과 사용자 자료 | Google 로그인 정보의 위조와 만료를 검사하고, 다른 계정의 사진이나 리포트 요청을 거절 | 실제 배포 서버의 로그인 설정은 별도 확인 |
| 동의한 처리 범위 | 음성 및 사진 AI 처리 전에 동의를 확인. 사진 분석 동의를 끄면 저장된 AI 설명을 지우고 늦게 도착한 분석 결과도 저장하지 않음 | 과거 카드에 이미 들어간 문장까지 모두 지우는 기능과는 구분 |
| 사진과 녹음 업로드 | 로그인 확인, 파일 형식과 크기 검사, 실제 받은 데이터 크기 제한 | 음성 파일 검사와 실제 해석 결과가 달라질 수 있는 문제는 아래에 남겨 둠 |
| 반복 요청과 비용 | 한 계정의 짧은 전사는 동시에 2개, 푸시 등록 기기는 5대, 한 면회의 리포트 재요청은 3회로 제한 | 하루 동안 반복해서 쓰는 AI 비용의 총액 제한은 별도 |
| 저장과 삭제 | 삭제할 파일을 목록에 등록하고 대상 확인 후 삭제. 음성과 전사문의 보관기한 관리, DB 백업과 복원 시험 구현 | S3 자동 삭제는 11/11 PM 승인으로 운영을 시작(#341, 5분 주기). 정상 상태에서도 다음 주기까지 지연될 수 있음 |
| AI가 읽고 쓰는 범위 | 카드 생성 AI는 지정한 한 사람의 자료만 조회. 결과 형식과 근거를 검사하고 이야기 후보는 보호자 승인 후 확정 | 가족 관계나 사진 설명의 의미를 항상 정확하게 해석한다는 보장은 없음 |
| 로그와 알림 | 로그에서 대화와 이야기 원문을 줄이고, 푸시 알림에 이름이나 대화 내용을 넣지 않음 | STT 오류 기록에 파일 접근 주소가 남는지는 추가 확인 필요 |
| 휴대폰과 서버 | 계정별 기기 자료 분리, 녹음과 사진의 Android 백업 제외, 배포 전 버전과 검사 결과 확인 | 최신 설치 앱과 서버에 어떤 코드가 적용됐는지는 배포 때 확인 |

구현 위치와 세부 조건은 [보호 기능별 코드 근거](controls.md)에 있다.

### 서버 주소 뒤에 /docs를 붙여 열리는 문서

`/docs`는 서버가 제공하는 API 목록과 호출 방법을 보여 주는 화면이다. 새록 서버에는 운영 모드(`environment=production`)에서 `/docs`, `/redoc`, `/openapi.json`을 끄는 코드와 테스트가 있다. [PR #227](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/pull/227), @decmoon05, 11월 5일 04:07 KST 병합.

11월 8일 기록에서는 서버가 개발 모드였고, 이번 보고서에서는 운영값을 다시 조회하지 않았다. 따라서 **차단 기능은 구현됐으며 실제 배포 설정 확인은 남아 있다.** 문서가 열린다는 사실만으로 사용자 자료를 읽거나 로그인 검사를 건너뛸 수 있는 것은 아니다. STT 서버의 문서 설정은 별개다.

## 무엇을 먼저 보완해야 하나

STT는 녹음을 글로 바꾸는 기능이다. 아래 3개는 11월 8일 시험에서 확인했던 문제가 관련 코드에 남아 있는 항목이다. 최신 운영 서버에서 다시 공격 시험을 한 결과는 아니다.

| 남은 문제 | 어떤 문제가 생길 수 있나 | 필요한 수정 |
|---|---|---|
| 짧은 음성 파일을 다시 검사하는 동안 요청 처리가 지연됨 | 최초 검사 후 같은 파일을 다시 읽는 부분이 다른 요청 처리까지 붙잡을 수 있음 | 두 번째 검사도 요청 처리를 막지 않도록 바꾸고 시험 |
| 음성 파일 검사와 실제 해석 결과가 다름 | 검사를 통과한 비정상 음성 파일(WAV)을 음성 처리 도구가 다르게 해석해 처리량 제한이 어긋날 수 있음 | 비정상 구조 거절과 실제 처리량 제한 확인 |
| STT 프로그램 강제 종료 후 임시 녹음이 남음 | 정상 종료 때는 지우지만 강제 종료 때는 임시 파일이 남을 수 있음 | 재시작 후 남은 임시 파일을 찾아 안전하게 정리 |

기존 Tailscale 사설망 연결은 유지한다. 위 작업은 음성 파일을 처리하는 코드의 문제다.

그 밖의 후속 작업은 다음 시점에 처리한다.

| 처리 시점 | 할 일 |
|---|---|
| PM이 실제 삭제를 승인한 뒤 | S3 파일 삭제의 예약 실행, 실패 재시도와 삭제 완료 확인 |
| 로그 관리나 이용량을 늘릴 때 | 로그 보관기한, 계정별 하루 AI 사용량 또는 비용 제한 |
| STT 처리 제어를 고칠 때 | 요청 시간이 끝나거나 취소됐을 때 GPU 작업도 중단되는지 확인 |
| 백업 복원이나 모델 교체 전 | 탈퇴와 동의 철회를 다시 반영하는 절차, 사용할 모델 버전 확인 |
| 배포 확인 때 | 실제 서버와 앱 버전, API 문서 차단 설정, 동의 설명 일치 확인 |

각 항목의 완료 조건은 [남은 작업과 확인 방법](follow-up.md)에 정리했다. 새 담당자나 마감일은 지정하지 않았다.

## 이전 점검 항목은 얼마나 처리됐나

11월 8일 점검에는 **시험으로 확인한 문제 4개와 추가 확인 후보 22개**, 총 26개가 기록돼 있었다. 아래 표는 그 26개의 처리 결과다.

| 처리 상태 | 개수 | 해당 내용 |
|---|---:|---|
| 수정 코드 병합 | 7 | 로그인 전 큰 파일 수신 제한, 대기 카드의 잘못된 실패 처리, 철회한 사진 설명 재사용, 로그인 검증의 반복 조회, 푸시 기기 수, 리포트 재시도 수, 계정별 짧은 전사 동시 수 |
| 일부 보완, 추가 작업 있음 | 3 | 생성 로그 누적, 장기 AI 비용, 요청이 끝난 뒤에도 계속되는 GPU 작업 |
| 확인했던 문제의 수정이 남음 | 3 | 위에서 설명한 STT 파일 처리 문제 |
| 실제 문제가 생기는 조건을 더 확인해야 함 | 6 | 다른 앱에서 새록 화면 열기, 중단된 업로드 조각, 음성 삭제 확인, 백업 복원, STT 오류 기록, 모델 버전 고정 |
| 보류 뒤 운영 적용(11/11) | 1 | S3 자동 삭제 운영(#341, #185) |
| 이번 팀 수정 범위에서 제외 | 4 | 로컬 시험 도구, 운영진 AWS, 운영진 토큰, 기존 Tailscale 연결 |
| 현재 추가 수정 없음 | 2 | 기존 배포 승인 절차, GitHub에 등록되지 않은 앱 업로드 서명키 |
| 합계 | 26 | 같은 항목을 두 상태에 중복 집계하지 않음 |

당시 시험으로 확인한 4개 중 큰 파일 수신 제한은 수정 코드와 서버 제한 적용 기록이 있고, 나머지 3개는 위 STT 항목이다. 추가 확인 후보를 모두 발견된 취약점으로 세지 않는다. 항목별 수정 내용과 코드는 [점검 결과와 처리 내용](remediation.md)에서 볼 수 있다.

이 보고서의 **보호 조치 76개**는 전체 코드에서 정리한 기능 수이고, **관련 PR 60건**은 기능, 수정, 문서와 시험을 포함한 변경 이력이다. 위의 점검 26개와는 세는 대상이 다르며, 어느 숫자도 보안 점수나 해결한 취약점 총수를 뜻하지 않는다.

## 사진이나 대화 속 문장으로 AI를 조종하려는 입력은 어떻게 막나

사진 설명이나 전사문에 “앞의 지시를 무시하라” 같은 문장을 넣어 AI의 행동을 바꾸려는 시도를 프롬프트 인젝션이라고 한다.

| 단계 | 적용한 보호 |
|---|---|
| 자료 읽기 | 시스템 지시와 사용자 자료를 구분하고, 자료 안의 명령을 따르지 않도록 안내 |
| 자료 조회 | 카드 AI의 조회 도구를 지정한 한 프로필로 제한. 임의 계정 조회, DB 쓰기와 명령 실행 도구는 제공하지 않음 |
| 결과 저장 | 자료에 없는 근거 번호, 잘못된 결과 형식과 일부 부적절한 의료 표현을 검사 |
| 이야기 확정 | AI가 뽑은 이야기는 확인 대기 상태로 두고 보호자가 승인한 뒤 저장 |

[PR #316](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/pull/316), @decmoon05, 11월 11일 02:08 KST 병합에는 합성 자료로 시험한 **28회**의 결과가 있다. 이야기와 세부 정보로 카드 만들기 7회, 사진 설명으로 카드 만들기 7회, 리포트 7회, 이야기 변경 제안 7회다.

시험 문서에는 입력에 심어 둔 표식, 외부 링크와 시스템 지시문이 출력에 나타나지 않았고, 지어낸 진단이나 이야기도 나오지 않았다고 기록돼 있다. 당시 모델은 `gpt-6-luna`, 코드는 `a855c87e`였으며 카드 프롬프트 2판, 리포트 6판과 이야기 후보 9판을 사용했다.

사진 속 글자를 직접 읽는 분석, 앱의 전체 흐름과 이후의 카드 프롬프트 3판은 이 시험의 통과 범위에 들어가지 않는다. 재실행 스크립트도 저장소에 없다. 이 보고서에서는 모델을 다시 호출하지 않았다. [당시 시험 조건과 결과](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/blob/6836ac8052067d50db1e24e39ab65cf21d5bc15e/docs/qa/prompt-injection-20261110.md), [AI 보호 코드](controls.md#5-ai-권한과-출력-보호).

자동 검사(CI)는 변경할 때 기존 기능이 깨지지 않는지 검사한다. 전체 흐름 시험(E2E)은 앱과 서버를 이어서 확인한다. 이 보고서에서 참고한 합성 자료 시험은 실제 외부 AI, GPU와 저장소의 모든 실패 조건을 보장하지 않는다. 코드 병합과 실제 서버 적용도 구분한다.
