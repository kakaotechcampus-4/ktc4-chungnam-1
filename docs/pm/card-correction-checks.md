# 사실 정정과 다음 대화 준비 검증

제품 기준은 [PM README](README.md#사실-정정과-다음-면회-카드-반영)를 따른다. 아래는 구현 요청과 검증 계획이다. 문서 병합을 기능 구현 완료로 표시하지 않는다.

## 담당과 인계

| 요청 담당 | 맡길 수정 | 인계할 결과 |
| --- | --- | --- |
| 이인성, BE와 AI 생성 | 사실 저장과 카드 근거 연결, 영향받은 카드 사용 중지, 다음 대화 준비 때 묶음 재생성, 오래된 카드의 면회 시작 차단 | 수정된 API와 상태, 실제 정정 입력 및 생성 결과, 저장과 시작 차단 검사 |
| 이서형, FE 대화 준비 | 사용 중지 표시와 선택 제한, 다음 대화 준비 및 재생성 안내, 생성 중 해당 프로필 정정 저장 제한 | 채원님과 같은 상태를 사용하는 화면, 준비부터 카드 선택 및 대화 시작 검사 |
| 성채원, FE 정정 입력 | 리포트 이후 생성된 내용과 일대기 또는 프로필의 정정 저장 결과를 대화 준비 상태에 연결 | 정정 저장 성공과 실패 표시, 앱 재실행 후 갱신 필요 상태 복원 검사 |
| 이문영, AI 검증 | 최신 정정이 생성 입력과 실제 질문에 반영되는지 확인 | 기존 사실을 다시 사용한 사례, 모델과 입력 및 출력 기록. 합성 자료 사용 |
| 김영석, PM | 수정 요청 범위와 구현 일정 추적, 제품 동작 변경 판단 | 담당별 진행과 남은 제한 |

기존 PR의 연결 수정과 새 정정 기능은 별도 작업으로 관리한다. 기존 PR을 이 기능까지 전부 넣는 대형 PR로 확장하지 않는다. 위 이름은 PM의 요청 담당이며 착수 또는 일정 수락을 뜻하지 않는다. 담당 영역이 다르거나 일정이 어려우면 실제 담당과 가능한 일정을 회신한다. BE 내부 세부 분담은 BE에서 정한다.

## 공통 테스트 자료

합성 프로필의 직업을 ‘교사’로 두고, 같은 사실을 근거로 한 카드 두 장과 관계없는 취미 카드 한 장을 준비한다. 사용자가 생성된 내용을 본 뒤 직업을 ‘버스 운전사’로 정정하는 상황을 검사한다. 실제 사용자 자료는 사용하지 않는다.

| 번호 | 상황과 조작 | 통과 기준 | 확인 담당 |
| --- | --- | --- | --- |
| C01 | 직업 정정 저장 | 사실과 갱신 필요 기록 저장. AI 호출 없이 관련 두 카드 사용 중지. 취미 카드는 열람 가능 | 인성, 채원 |
| C02 | 추가 사실을 여러 번 정정 | 저장만 하고 매번 생성하지 않음. 다음 대화 준비 시 최신 정정이 모두 입력에 포함 | 인성 |
| C03 | 정정 저장 요청 실패 | 저장 완료로 표시하지 않음. 재입력 또는 재시도할 수 있고 기존 편집 내용 유실 여부 확인 | 채원 |
| C04 | 정정 후 앱 종료와 재실행 | 서버에 저장한 정정과 사용 중지 상태 유지. 잘못된 카드로 대화 시작 불가 | 서형, 채원 |
| C05 | 다음 대화 준비 선택 | 누적 정정으로 묶음 전체 재생성. 완료 전 대화 시작 불가, 성공 후 새 묶음으로 교체하고 카드 선택 가능 | 인성, 서형 |
| C06 | 재생성 중 정정 저장 시도 | 해당 프로필의 저장을 잠시 막고 진행 상태 표시. 성공 또는 실패로 작업 종료 후 다시 저장 가능 | 인성, 서형 |
| C07 | 재생성 실패와 재시도 | 정정은 유지. 잘못된 기존 묶음으로 대체하지 않음. 최신 정정으로 재시도 | 인성, 서형 |
| C08 | 준비 버튼 반복 클릭 | 같은 입력으로 중복 생성 작업과 카드 묶음이 등록되지 않음 | 인성, 서형 |
| C09 | 카드 근거 연결이 없어 영향 판별 불가 | 정상 카드를 추측하지 않고 해당 묶음 전체 사용 중지 및 갱신 대상으로 처리 | 인성 |
| C10 | 사용 중지 후 평가와 추천 입력 조회 | 대화 평가의 미사용이나 부정 반응으로 기록하지 않고 추천 불이익 없음 | 인성, 문영 |
| C11 | 새 묶음 완료 후 추가 정정 | 다시 저장 및 사용 중지. 자동 재생성하지 않고 다음 준비 요청에서 반영 | 인성, 서형 |
| C12 | 기존 면회 기록 조회 | 정정을 이유로 과거 면회 내용을 소급해 다시 작성하지 않음 | 인성, 채원 |
| C13 | 실제 모델로 정정 후 질문 생성 | 생성 입력은 버스 운전사로 정정돼 있고 교사 경험을 사실로 전제하는 질문이 나오지 않음. 모델 출력 검사는 코드 검사와 별도 기록 | 문영, 인성 |

각 검사에는 실행 커밋, 환경, 입력과 결과, 통과 또는 미실시 사유를 남긴다. 아직 실제로 실행한 검사 결과는 없다. 10/18 첫 회차 통합 성공을 이 정정 기능의 완료로 대신하지 않는다.
