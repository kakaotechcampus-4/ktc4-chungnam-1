## 이야기 삭제와 추천 피드백

### 삭제와 추천 제외의 구분

- 일대기 이야기를 삭제했다는 이유로 관련 주제나 카드의 추천 우선순위를 낮추지 않습니다. 삭제 이유를 비선호로 추측하지 않습니다.
- 삭제한 이야기는 이후 생성 입력에서 제외합니다. 삭제 행동만으로 과거 카드와 면회 기록을 함께 삭제하거나 주제 전체를 추천에서 제외하지 않습니다.
- 앞으로의 추천 조정은 대화 후 보호자의 명시적인 선택으로 처리합니다. 어떤 주제를 덜 추천하거나 제외할지 보여주고, 반영 결과도 알립니다.
- 단순히 이번 대화가 별로였다는 답을 영구 제외로 바꾸지 않습니다. 카드 미사용과 미응답에도 불이익을 주지 않습니다.
- 이 방향은 삭제 시마다 관련 카드를 지울지 묻는 화면을 추가하는 대신, 대화 후 피드백으로 추천 의사를 확인하려는 PM 변경안입니다.
- 내용이 틀렸다고 정정하는 경우에는 기존 [사실 정정과 다음 면회 카드 반영 기준](README.md#사실-정정과-다음-면회-카드-반영)을 적용합니다. 잘못된 기존 카드를 계속 사용하게 하는 결정이 아닙니다.

### 대화 내용에 따라 묻는 질문

AI가 전사와 소감에서 보호자에게 확인할 부분을 찾았을 때, 리포트를 읽고 홈이나 다른 화면으로 나가려는 시점에 짧게 묻는 방향입니다. 앱 종료 시점을 뜻하지 않습니다. 현재 구현된 질문 기능으로 보고하지 않습니다.

- 부정적인 사건, 싸움이나 갈등이 언급됐다는 사실만으로 비선호를 확정하지 않습니다.
- AI는 질문할 내용과 대화 근거를 함께 제안합니다. 근거가 없으면 질문을 만들지 않습니다.
- 화자가 불분명하면 어르신의 감정으로 단정하지 않습니다. 전사에 없는 표정이나 행동을 만들지 않으며, 특정 갈등을 가족 등 상위 주제 전체의 문제로 확대하지 않습니다.
- 보호자는 답하지 않고 넘어갈 수 있습니다. 답했거나 넘긴 질문을 같은 리포트에서 나갈 때마다 반복하지 않습니다.
- 넘겼다는 이유로 AI 제안을 승인하거나 추천 제외를 적용하지 않습니다.
- 일대기에 새 이야기를 추가할지 확인하는 단계와 구분합니다. 이야기 후보는 보호자가 확인한 결과에 따라 반영합니다.
- 현재 소감을 저장한 뒤 녹음을 제출하고 분석하는 순서는 유지합니다. 이 질문은 전사와 AI 분석 이후에 보여줍니다.

### AI 출력과 답변 전달 검토안

별도 AI 호출을 추가하지 않고, 기존 이야기 후보와 주제 조정 제안을 만드는 호출에서 질문 정보도 함께 반환하는 안으로 검토합니다.

| 전달할 내용 | 검토 방향 |
| --- | --- |
| AI의 질문 | 확인할 주제, 대화 근거, 질문과 선택지를 정해진 JSON 형식으로 반환 |
| 보호자의 선택 | 현 상태 유지, 덜 추천, 앞으로 추천하지 않기와 기타 의견 입력을 검토 |
| 선택지의 동작 | AI가 보기 문구를 만들더라도 서버가 허용한 동작으로 처리. 보기 순서나 임의의 문구를 명령으로 사용하지 않음 |
| 기타 의견 | 저장하고 다음 카드 생성에 전달하는 방법 검토. 글을 적은 것만으로 추천 제외하지 않음 |
| 적용 결과 | 보호자가 최종 선택한 주제와 범위를 저장하고 이후 추천에 반영 |

10월 23일에 확인한 develop `5dfc669`의 기존 구조와 비교하면 다음 검토가 필요합니다.

- 기존 생성 결과는 주제를 더 자주 또는 덜 다루거나 제외하자는 제안과 이유입니다. 질문, 선택지와 자유입력의 전달 및 저장은 AI, BE와 FE가 함께 추가해야 합니다. `feedbackQuestions` 같은 새 필드명은 확정하지 않습니다.
- 기존 확인 API는 이야기와 주제 제안을 모두 한 번에 제출하도록 검사합니다. 추천 질문만 먼저 답할 수 있도록 이야기 승인과 추천 답변을 따로 저장하는 방법을 검토해야 합니다.
- 기존 주제 조정은 선택한 카드의 주제에 연결됩니다. 대화 중 새로 나온 갈등을 따로 다루려면 대상을 표현하는 방법이 필요합니다. 가까운 카드의 주제에 억지로 연결하지 않습니다.
- 기존 화면은 AI 제안을 기본으로 선택합니다. 새 질문을 넘기는 동작과 기존 제안을 승인하는 동작이 섞이지 않도록 구분해야 합니다.

AI는 프롬프트와 출력 형식, BE는 응답 검사와 저장 및 다음 생성 입력, FE는 질문 표시와 답변 및 건너뛰기를 검토합니다. 각 리더가 내부 담당을 제안해주세요.

## 최초 입력과 첫 카드 준비

### 기존 입력 유지

2026년 10월 22일 PM 결정입니다.

- 최초 필수 정보는 이름, 성별, 생년월일과 현재 상태 네 항목을 유지합니다. 생년월일은 년, 월, 일을 받습니다.
- 현재 상태의 기존 선택지인 경도 인지장애, 경도 치매와 '잘 모르겠어요'를 유지합니다.
- 직업, 고향, 취미, 가족 정보와 사진은 선택 입력입니다. 기존 화면과 건너뛰기를 유지합니다.

별도 사전 질문을 추가하지 않는 이유는 다음과 같습니다.

- 개인 경험을 추가로 입력하지 않아도 범용적인 대화 주제와 질문으로 시작할 수 있습니다. 최초 대화에 한해 고정 질문을 사용하는 것도 대안이며, 반드시 고정 질문을 사용하기로 정한 것은 아닙니다.
- 이미 생성 중이거나 준비된 카드에 답을 바로 반영하지 못하고 다음 대화로 미루면, 사용자는 입력한 내용이 왜 나오지 않는지 혼란스러울 수 있습니다.
- 앞으로 하고 싶은 이야기는 대화 3회마다 받는 중간평가에서 확인할 수 있습니다. 같은 목적의 사전 질문을 중복으로 받지 않습니다.

기본 정보 입력 → 기존 선택 정보 입력 또는 건너뛰기 → 백그라운드 생성 시작 → 홈 이용 → 준비된 카드 선택 → 대화 시작

- 10월 18일 에뮬레이터 통합 시험에서는 GPT-5.6 Luna로 카드 12장을 생성하는 데 45.3초가 걸렸습니다. 개인 검증 환경의 단일 실행이며, GPT-6 Luna의 처리 시간을 보장하는 수치가 아닙니다.
- 홈에 들어오자마자 카드를 열면 아직 생성 중일 수 있습니다. 준비 전 카드를 열었을 때의 안내와 생성 시간 단축 방법은 리더 의견을 받아 정합니다.
- 기존 초기 입력 완료 시점의 생성 요청은 유지합니다. 등록 완료와 카드 준비 상태를 혼동하지 않도록 안내하고, 생성 실패 안내와 재요청 경로를 유지합니다.

### 추가 정보를 모르는 경우

직업, 고향, 취미, 가족 정보와 사진을 모두 건너뛰어도 카드 생성을 허용합니다. 정보가 부족하다는 이유로 추가 입력을 강제하지 않습니다.

- 사용할 수 있는 프로필 정보나 사진 설명이 있으면 활용합니다. 사진 메타데이터는 다시 입력에 넣지 않습니다.
- 추가 정보가 없으면 음식, 음악 등 가벼운 일상 질문으로 시작합니다. 알 수 없는 직업, 가족관계나 개인 경험을 지어내지 않습니다.
- 생성 결과의 기존 검사를 생략하거나 생성 오류를 성공으로 처리하는 결정은 아닙니다.

## 대화 3회마다 받는 중간평가

2026년 10월 22일 PM이 질문과 주기를 정했고, 10월 23일 표시 시점과 건너뛰기를 정했습니다. 대화 3회는 PM이 정한 주기이며 멘토가 지정한 값이 아닙니다.

중간평가에서는 다음 고정 질문 두 개만 받습니다. AI가 대화 내용에 따라 만드는 질문이 아닙니다.

- "새록이 어르신과 대화하는 데 도움이 됐나요?"
- "앞으로 어떤 이야기를 나누고 싶으세요?"

대화 3회마다 해당 리포트를 읽고 홈이나 다른 화면으로 나갈 때 보여줍니다.

- 답하지 않고 건너뛸 수 있습니다. 답변 때문에 다음 화면으로 이동하지 못하게 하지 않습니다.
- 답했거나 건너뛴 중간평가는 같은 리포트에서 반복해서 묻지 않습니다.
- 답변에 따라 별도의 후속 질문을 추가하지 않습니다. 질문 문구에 '최근 세 번' 등 회차 수를 넣지 않습니다.
- 앞으로 하고 싶은 이야기는 이후 추천을 위한 희망 주제로 다루며, 실제로 겪은 생애 사실로 저장하지 않습니다.
- 대화 내용에 따라 묻는 추천 질문과 중간평가는 별개입니다. 중간평가 답변만으로 특정 주제를 추천에서 제외하지 않습니다.

당일 리포트에 쓰는 소감은 그대로 유지합니다. 현재 필수인 전체 만족도와 어르신 반응 두 질문을 이번 결정으로 없애거나 건너뛰게 하는 것은 아닙니다. 카드별 가벼운 평가와 자유 메모는 현재처럼 선택이며, 답하지 않은 것을 부정 평가로 취급하지 않습니다.
