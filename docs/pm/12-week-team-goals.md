# 앞으로 12주, 우리 팀이 함께 얻어갈 것

## 최종 목표

이번 프로젝트의 최종 목표는 앱 하나를 제출하는 데서 끝나지 않는다.

12주 뒤에는 모든 팀원이 실제 협업 환경에서 AI 제품을 기획하고 개발하며 검증한 경험을 GitHub 기록과 결과물로 증명할 수 있어야 한다. 개인별 성과와 전문성은 각자의 역할에 맞게 정리하되, 팀 전체는 아래 경험을 공통으로 완성한다.

## 1. 실제 GitHub 협업 체계 완성

- Issue로 작업 목적과 완료 조건 정의
- 기능별 브랜치와 PR 사용
- 담당자의 기술 검토와 피드백 반영
- PM 확인 후 병합
- 코드와 문서를 함께 관리
- 충돌 해결과 지속적인 기능 통합

단순히 GitHub를 사용한 팀이 아니라, GitHub를 중심으로 실제 개발 절차를 운영한 팀이 되는 것이 목표다.

## 2. 팀 공용 AI 에이전트 운영

- `CLAUDE.md`와 `AGENTS.md`로 절대 지켜야 할 규칙 공유
- 역할별 README로 필요한 프로젝트 맥락 제공
- 확정 사항, 검토 사항과 금지 사항 구분
- 서로 다른 AI 도구를 사용해도 일관된 기준 유지
- AI가 만든 결과도 리뷰와 검증 후 반영
- 기술과 요구사항 변경을 팀 문서에 계속 축적

개인이 AI를 잘 사용하는 수준을 넘어, 팀이 AI 에이전트를 일관된 개발 구성원처럼 운영하는 경험을 확보한다.

## 3. 아이디어를 실제 제품으로 연결

다음 사용자 흐름이 끊기지 않는 Android 앱을 완성한다.

> 프로필 설정 → 대화 카드 생성과 선택 → 면회 진행과 녹음 → STT와 화자 처리 → 리포트 → 보호자 평가 → 다음 추천 반영 → 스토리북

각 기능을 따로 만드는 데 그치지 않고 사용자가 처음부터 끝까지 사용할 수 있는 하나의 제품으로 통합한다.

## 4. 근거와 실험으로 핵심 가설 검증

- 맞춤 카드가 일반적인 대화 소재보다 실제로 선택되는지 확인
- 회차 기록이 다음 추천에 도움이 되는지 확인
- 면회 환경에서 STT와 화자 처리가 가능한지 검증
- 자동 지표와 보호자 평가가 얼마나 일치하는지 비교
- 보호자가 다음 면회에도 서비스를 다시 사용하는지 측정

잘 만들었다는 내부 평가가 아니라 실제 사용자 행동과 측정 결과로 서비스의 가치를 판단한다.

## 5. AI가 실패해도 사용할 수 있는 제품 설계

- 잘못된 카드의 수정과 제외
- 분석 신뢰도 부족 시 결과 생성 중단
- 자동 분석 실패 시 보호자 입력으로 전환
- 프로필 변경 전 사용자 승인
- 잘못 반영된 정보 되돌리기
- 관찰값과 AI 해석 구분

정상적인 시연만 가능한 제품이 아니라 실제 실패 상황에서도 사용자를 보호하는 제품을 완성한다.

## 6. 개인정보와 보안을 설계에 포함

- 수집하는 데이터와 목적 명시
- 로컬 저장과 서버 처리 범위 구분
- 외부 전송 정보 최소화와 마스킹
- 실제 녹음과 개인정보의 저장소 반입 차단
- 동의, 보관과 삭제 흐름 구현
- 외부 AI와 STT의 데이터 처리 경로 확인

보안을 마지막에 검사하지 않고 기능과 데이터 구조를 정할 때 함께 설계하는 경험을 확보한다.

## 7. 과정과 결과를 설명할 수 있는 기록 확보

12주 뒤에는 모든 팀원이 다음 내용을 자신의 역할에 맞게 설명할 수 있어야 한다.

- 어떤 문제를 해결했는가
- 자신이 무엇을 책임졌는가
- 어떤 결정을 내렸고 왜 그렇게 판단했는가
- 무엇이 실패했고 어떻게 수정했는가
- 어떤 방법으로 결과를 검증했는가
- 자신의 결과물이 전체 제품과 어떻게 연결됐는가
- 팀이 GitHub와 AI 에이전트를 어떻게 운영했는가

## 우리가 남길 결과

12주 뒤 우리에게 남아야 하는 것은 단순한 앱 하나가 아니다. 실제 사용자의 문제를 근거로 정의하고, GitHub와 팀 공용 AI 에이전트를 활용해 여러 역할이 함께 제품을 개발하며, 실패와 개인정보 문제까지 검증한 과정이 남아야 한다. 모든 팀원이 이 경험을 자신의 기록과 결과물로 증명할 수 있는 프로젝트를 만드는 것이 우리의 최종 목표다.
