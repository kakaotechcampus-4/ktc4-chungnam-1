# 새록 발표 예상 질문과 답변

## 발표 전체 대표 답변

> 새록은 환자의 기억을 회복시키거나 치료하는 서비스가 아니다. 경도인지장애 또는 경도 치매 부모를 면회하는 보호자가 대화 소재를 준비하고 이어가는 부담을 줄이는 서비스다. 환자의 생애 정보와 회차별 반응을 기록해 현재 시점에 맞는 소재를 추천하며, 음성 분석 결과는 대화 품질 평가가 아닌 관찰값으로만 사용한다.

## 1. 서비스 기획안

| 예상 질문 | 예상 답변 |
| --- | --- |
| 이 서비스가 꼭 필요한 딱 한 사람은? | 요양시설에 있는 경도인지장애 또는 경도 치매 부모를 정기적으로 면회하지만, 안부 이후 꺼낼 이야기를 찾지 못해 부담을 느끼는 성인 자녀 보호자. 현재 타깃 범위는 베타 검증 후 조정 가능 |
| 치매 환자의 문제를 해결하나요, 보호자의 문제를 해결하나요? | 1차 사용자는 보호자. 면회 전 소재 준비와 면회 중 대화 지속의 부담을 줄이는 것이 직접 목적. 환자는 보호자가 준비한 대화를 함께 경험하는 간접 수혜자 |
| 그 사람은 지금 이걸 어떻게 버티고 있나요? | 커뮤니티에서 대화 소재를 찾고, 옛 사진과 노래, 회상 카드를 준비하거나 요양보호사에게 근황을 물음. 준비하지 못한 날에는 같은 안부를 반복하거나 대화를 다른 활동으로 대체 |
| 왜 우리 서비스를 쓸까요? | 일반적인 대화 조언을 받는 데서 끝나지 않고, 면회 전에 바로 사용할 소재를 받고 면회 후 반응을 다음 추천에 남길 수 있기 때문. 매번 처음부터 소재를 찾는 수고를 줄여줌 |
| 환자가 기억하지 못하는데 맞춤 소재가 의미 있나요? | 목적은 기억을 정확히 복원하거나 시험하는 것이 아님. 상대적으로 보존될 가능성이 있는 생애 경험과 선호를 이야기 유도형 소재로 제시해 대화를 시작할 가능성을 높이는 것. 개인차가 크므로 반응이 없으면 다른 소재로 전환 |
| 회상치료를 앱으로 만든 건가요? | 회상 접근의 일부 원리를 참고하지만 치료 프로그램은 아님. 보호자가 대화 소재를 준비하고 실제 반응을 기록하도록 돕는 돌봄 지원 도구. 인지기능 개선이나 질환 완화는 목표에서 제외 |
| 회상 대화가 실제로 효과 있다는 근거가 있나요? | 2018년 Cochrane 검토에서는 일부 환경에서 의사소통과 기분 등에 작은 효과가 보고됐지만 결과가 일관되지는 않았음. 따라서 회상 대화의 치료 효과를 주장하지 않고, 과거 경험을 대화 소재로 사용할 수 있다는 제한된 근거로 활용 |
| 효과가 없었다는 연구도 있지 않나요? | 있음. REMCARE 연구에서는 삶의 질과 보호자 정신건강의 유의한 개선이 확인되지 않았고 일부 보호자 불안 지표는 증가. 그래서 카드를 사용하지 않을 선택권을 제공하고 환자 반응과 보호자 부담을 함께 확인 |
| 서비스가 보호자의 죄책감을 줄인다는 근거가 있나요? | 치매 가족 보호자의 죄책감과 우울의 연관성을 다룬 연구는 있지만, 대화 카드가 죄책감을 낮춘다는 직접 근거는 없음. 죄책감과 부담 감소는 베타에서 검증할 가설이며 확정 효과로 발표하지 않음 |
| 기존 회상 카드나 치매 교구와 무엇이 다른가요? | 기존 교구는 고정된 소재를 제공하며 사용 후 반응이 다음 카드에 반영되지 않음. 새록은 환자의 생애 정보와 회차별 반응을 함께 기록해 다음 면회의 소재 후보를 조정 |
| 차별점은 무엇인가요? | 환자에게 대신 말을 걸어주는 AI가 아니라, 보호자가 직접 꺼낼 소재를 환자의 생애 정보와 지난 면회 반응에 맞춰 매 회차 다시 고르는 서비스 |
| 누가 돈을 내나요? | 현재는 보호자 대상 B2C 가설. 보호자가 면회 준비 시간을 줄이고 개인화된 소재를 받는 결과에 비용을 지불하는 구조를 검토 중. 가격과 결제 의향은 아직 검증되지 않음 |
| 첫 100명은 어떻게 모으실 건가요? | 1차 채널 가설은 네이버 카페 치노사모. 주 1회 이상 면회하는 보호자 10명을 먼저 모집해 4회차까지 사용하도록 하고, 실제 사용 경험을 바탕으로 후속 모집을 진행할 계획 |
| 의료기기나 치료 서비스에 해당하지 않나요? | 진단, 예측, 치료 결정을 제공하지 않도록 설계. 병세가 좋아지거나 악화됐다는 판단도 생성하지 않음. 다만 실제 규제 적용 여부는 기능과 홍보 문구에 따라 달라질 수 있으므로 배포 전 별도 검토 필요 |
| 보호자가 환자의 민감정보를 너무 많이 입력하지 않나요? | 카드 생성과 안전 필터에 필요한 최소 정보만 수집. 진단 검사 결과, 상세 병력, 주민등록번호처럼 대화 카드에 필요하지 않은 정보는 받지 않음. 각 입력 항목의 사용 목적도 표시 |
| 가장 솔직한 현재 한계는 무엇인가요? | 맞춤 카드가 일반 카드보다 더 자주 사용되는지, 자동 관찰값이 보호자가 느낀 반응과 얼마나 일치하는지, 면회 준비 지원이 보호자 부담을 줄이는지 아직 직접 검증되지 않음 |
| 3개월 뒤에 손에 남는 게 무엇인가요? | 환자별 소재와 회차 반응 기록 구조, 면회 환경 음성 평가 결과, 확인형 질문과 민감 소재를 다루는 안전 규칙, 실제 보호자 사용 검증 결과 |
| 모델이 더 좋아지면 필요 없어지는 것 아닌가요? | 카드 문장 생성 자체는 범용 모델로 대체될 수 있음. 그러나 누구에게 어떤 소재가 어느 시점에 통했는지는 개별 회차 기록에서만 얻을 수 있음. 새록의 핵심은 모델보다 누적되는 맥락과 반응 기록 |

## 2. Agentic Workflow

| 예상 질문 | 예상 답변 |
| --- | --- |
| 이거 그냥 챗봇으로 하면 왜 안 되나요? | 챗봇은 사용자가 질문할 때 한 번 답하는 방식. 새록은 프로필과 이전 회차를 읽고, 소재를 고르고, 면회 결과를 분석하고, 보호자 확인을 거쳐 다음 추천을 갱신하는 반복 작업을 수행 |
| ChatGPT에 물어보면 나오는 것과 무엇이 다른가요? | 첫 회차 카드 생성은 ChatGPT로도 상당 부분 가능. 차이는 두 번째 면회부터 발생. 새록은 카드 사용 여부, 회차별 반응, 보호자 평가를 연결하고 안전 규칙을 적용해 다음 소재의 우선순위를 조정 |
| AI 에이전트 흐름은 어떻게 되나요? | 프로필과 이전 기록 확인 → 민감 소재와 최근 반응 확인 → 대화 카드 생성 → 보호자 선택 → 면회 녹음과 STT 처리 → 관찰값과 보호자 평가 기록 → 변경 제안 → 보호자 승인 → 다음 회차 추천에 반영 |
| AI가 어디까지 하고 사람은 어디서 멈추나요? | AI는 소재 후보 생성, STT와 화자 구분, 리포트 문장 정리를 담당. 보호자는 사용할 카드 선택, 녹음 동의, 분석 결과 확인, 프로필과 스토리북 변경 승인을 담당 |
| AI는 정확히 어디에 사용하나요? | 대화 카드 생성, 녹음의 STT와 화자 처리, 확인된 결과를 읽기 쉬운 리포트로 정리하는 지점에 사용. 금기 소재 차단, 시간 계산, 상태 전환, 변경 승인 처리는 코드와 규칙 사용 |
| 왜 에이전트여야 하나요? | 여러 회차의 데이터와 STT 같은 도구를 사용하고, 결과에 따라 다음 행동을 선택해야 하기 때문. 화자 구분 실패 시 수동 평가로 전환하는 것처럼 실패 경로까지 포함 |
| AI가 만드는 카드가 환자에게 상처를 줄 수 있지 않나요? | 가능함. 최근 기억을 시험하는 질문을 차단하고 사별, 갈등, 질환 등 민감 소재를 표시. 확인되지 않은 사실은 생성하지 않으며, 카드는 환자에게 바로 전달하지 않고 보호자가 먼저 선택 |
| 왜 발화량이 많으면 좋은 반응이라고 볼 수 없나요? | 화를 내거나 같은 말을 반복해도 발화량은 늘어날 수 있음. 반대로 말이 적어도 웃거나 대화를 이어갈 수 있음. 발화량과 응답 지연은 관찰값으로만 제공하고 보호자 평가와 함께 사용 |
| 검증된 대화 품질 측정도구가 있나요? | 기존 관찰형 도구는 전체적으로 심리측정 검증이 부족하다는 평가가 있음. ECD가 유망한 후보지만 한국어판 검증과 변화 측정 능력은 추가 확인이 필요. 따라서 자동 지표를 대화 품질 점수로 변환하지 않음 |
| 환자의 반응이 회차마다 달라지면 기록이 의미 있나요? | 같은 반응이 반복된다고 가정하지 않음. 고정 선호값 대신 회차별 반응을 보존하고 최근 기록을 더 중요하게 검토. 한 번의 반응만으로 소재를 영구 제외하지 않음 |
| 치매가 진행되면 축적한 프로필이 쓸모없어지지 않나요? | 고향과 직업 같은 고정 생애 정보와 최근 반응처럼 변하는 정보를 분리. 반응 정보에는 유효기간이 있다고 보고 최근 회차를 더 중요하게 사용 |
| 첫 회차에는 이전 기록이 없는데 무엇을 추천하나요? | 확인된 고향, 직업, 활동, 음악과 음식 등에서 서로 다른 소재를 생성. 정보가 부족하면 사실을 지어내지 않고 추가 입력을 요청하거나 일반적인 안전 카드 제공 |
| 쓸수록 남들이 못 따라오는 지점은 무엇인가요? | 카드 문장이 아니라 환자별 소재와 반응의 시간 흐름. 어떤 소재가 언제 사용됐고 어떤 반응이 있었는지는 실제 면회가 반복돼야 축적됨 |
| 실제로 쓸수록 좋아진다는 것을 어떻게 증명하나요? | 대화의 질이 계속 좋아진다고 주장하지 않음. 회차 기록을 반영한 카드와 일반 카드를 출처를 숨기고 제시한 뒤, 실제 면회용으로 어떤 카드가 더 많이 선택되는지 비교 |
| 이게 잘됐다는 것을 무엇으로 아나요? | 2회차 이상 재사용률, 카드 중 실제 사용한 수, 대화 시작 용이성, 보호자 부담 변화, 회차 기록을 반영한 카드의 선택률로 판단. 환자 발화량은 보조 관찰값 |
| 모델이 틀린 사실을 만들면 어떻게 하나요? | 카드와 리포트는 확인된 프로필과 회차 기록의 근거를 연결해야 함. 새로운 가족관계나 생애 이야기는 자동 저장하지 않고 보호자가 확인한 뒤 반영 |

## 3. 서비스 프로토타입

| 예상 질문 | 예상 답변 |
| --- | --- |
| 처음 들어와서 핵심 경험까지 따라가 볼까요? | 초기 프로필 설정에서 기본 정보, 취향과 생애 정보를 입력하고 선택적으로 이미지를 추가. 오늘의 대화 소재를 확인하고 보호자가 사용할 카드를 선택. 면회 중 녹음한 뒤 STT와 화자 처리를 거쳐 리포트와 보호자 평가를 작성. 확인된 결과만 다음 회차와 스토리북에 반영 |
| 대화 카드가 꼭 3장이어야 하나요? | 현재 3장은 선택 부담을 줄이기 위한 초기안. 처음부터 많이 생성할지, 기본 카드와 추가 생성 방식을 함께 사용할지는 프로토타입 사용성 검증 후 결정 |
| 준비한 주제가 끝나면 어떻게 하나요? | 추가 대화 버튼을 통해 새 소재나 꼬리 질문을 요청하는 흐름을 검토 중. 실시간 자동 생성과 사용자 요청 방식 중 어느 쪽이 면회를 방해하지 않는지는 아직 결정하지 않음 |
| AI가 틀리면 사용자에게 어떻게 보이나요? | 틀린 결과를 확정 사실처럼 표시하지 않음. 카드에는 맞지 않아요와 대체 기능을 제공하고, 프로필이나 스토리북 변경은 제안 상태로 보여준 뒤 보호자가 승인하거나 거절 |
| 화자 구분에 실패하면 무엇을 보여주나요? | 이번 회차는 목소리 구분이 어려워 자동 지표를 계산하지 않았다고 표시. 숫자를 임의로 생성하지 않고 카드별 반응을 보호자가 직접 입력하는 화면으로 전환 |
| 이 단계가 실패하면 그다음은 어떻게 되나요? | 카드 생성 실패 시 추가 프로필 입력 또는 안전한 일반 카드로 전환. 음성 분석 실패 시 수동 평가로 전환. 프로필 변경이 거절되면 기존 프로필을 유지하고 회차 기록만 남김 |
| 결과가 없으면 빈 화면이 나오나요? | 정보가 부족하다는 이유와 필요한 입력 항목을 안내. 확인되지 않은 내용을 만들어 채우지 않고, 추가 입력이나 일반 카드 선택지를 제공 |
| 카드가 부적절하면 되돌릴 수 있나요? | 보호자가 사용 전에 카드를 제외하고 대체할 수 있음. 반영된 프로필과 스토리북 변경도 변경 이력에서 되돌릴 수 있도록 설계 |
| 대화가 잘됐다는 것을 어떻게 측정하나요? | 하나의 대화 품질 점수를 제공하지 않음. 카드 사용 여부, 대화 지속 관련 관찰값, 보호자의 반응 평가와 면회 부담을 나눠 표시 |
| 녹음은 개인정보 문제가 크지 않나요? | 큰 위험 요소로 보고 있음. 녹음 시작 전 필요한 동의를 받고 처리 목적과 범위를 표시. 원본은 처리 후 삭제하며, 외부 처리가 필요한 경우 전송 범위와 업체 정보를 별도로 고지 |
| 스토리북은 어떤 기능인가요? | 회차에서 보호자가 확인한 생애 이야기를 유년기, 청소년기 등 시기별 블록으로 정리하는 후속 결과물. 피보호자에게 직접 제공할지, 앨범 형태로 판매할지는 아직 결정하지 않음 |
| 프로필 이미지는 어떻게 사용하나요? | 이미지에서 대화에 필요한 상황이나 메타데이터를 찾는 기능을 검토 중. 이미지 분석을 사용할 때만 별도 동의를 받고 외부 전송 여부를 표시. 확인되지 않은 인물 관계나 사건은 자동 확정하지 않음 |

## 4. 프로젝트 관리안

| 예상 질문 | 예상 답변 |
| --- | --- |
| 기술적으로 제일 겁나는 부분은 어디인가요? | 다인 면회실 녹음에서 환자 발화를 구분하는 문제. 다른 사람과 안내방송이 섞이면 발화량과 응답 지연도 신뢰할 수 없으므로 실제와 유사한 환경에서 가장 먼저 검증 |
| 핵심 기술이 실패하면 프로젝트 전체를 버리나요? | 화자 구분이 실패하면 자동 반응 분석을 축소하고 보호자 수동 평가로 개인화 루프를 유지. 수동 입력 방식에서도 재사용이 발생하지 않으면 문제 정의나 제품 구조를 다시 검토 |
| 지금 가장 불확실한 부분은 무엇인가요? | 화자 구분 정확도, 자동 관찰값과 보호자 평가의 일치도, 회차 기록을 반영한 카드의 실제 선택률. 추가 카드 제공 방식과 실시간 생성 필요성도 아직 미정 |
| 이 결정은 팀에서 누가, 어떻게 정했나요? | 초기 7개 후보를 타깃의 구체성, 현재 우회 행동, 에이전트 필요성과 차별성 기준으로 검토한 뒤 팀 투표로 주제를 수렴. 이후 범위와 제품 결정은 주 PM 김영석과 부 PM 이예은이 관리하며 기술 세부사항은 담당 리더가 검증 후 확정 |
| 역할은 어떻게 나눴나요? | 주 PM 김영석과 부 PM 이예은이 문제 정의, 범위, 문서와 PR을 관리. 김민혁은 BE, 이서형은 FE, 이문영은 AI 리드로서 각 영역의 기술 결정과 검토를 맡고 성채원과 이인성은 기능 개발과 검증에 참여 |
| 10주 안에 어디까지 만드나요? | 프로필 입력부터 카드 생성과 선택, 녹음, STT와 화자 처리, 리포트, 보호자 평가, 변경 승인, 다음 회차 추천까지 한 바퀴가 연결되는 수준. 진단, 예측, 실시간 대화 대행과 정밀 사투리 분석은 제외 |
| 마일스톤은 어떻게 구성했나요? | 1주차와 2주차는 화자 처리 가능성, 3주차와 4주차는 반응 판단 기준, 5주차와 6주차는 개인화 카드 선택률, 7주차와 8주차는 재사용률, 9주차와 10주차는 회차 누적 효과를 검증 |
| 기술 스택은 무엇인가요? | Android 우선 Flutter 앱으로 개발하며 기준 화면은 412 x 917 dp. STT 모델과 화자 처리 방식은 BE와 AI 담당자가 성능 검증 후 확정. 별도 백엔드와 외부 LLM은 아직 도입을 확정하지 않았으며, 필요한 데이터 흐름과 검증 결과를 확인한 뒤 기술을 선택 |
| 서버가 개인정보를 모두 보관하나요? | 원본 데이터를 장기 보관하는 구조는 지향하지 않음. 단말 우선 저장을 원칙으로 하고 서버 처리가 필요한 경우 동의된 최소 데이터만 임시 처리. 장기 개선 데이터는 별도 선택 동의와 가명처리 범위 안에서 관리 |
| API 키는 어디에 있나요? | 현재 저장소에는 실제 API 키가 없음. 외부 API를 도입하면 모바일 앱과 GitHub 코드에 넣지 않고 백엔드 환경 변수나 비밀 관리 수단에서 관리. 로컬 STT만 사용하면 해당 STT API 키는 필요하지 않음 |
| 테스트는 어떻게 하나요? | 일반 2인 대화, 작은 목소리, 제3자 개입, 안내방송, 반복 발화, 화난 발화와 정보 부족 등 실패 유형을 나눠 평가. 실제 결과가 나오기 전에는 테스트를 통과했다고 표시하지 않음 |
| 피봇 기준은 무엇인가요? | 예상한 사용자가 문제를 느끼지 않거나, 핵심 기술이 대체 경로까지 포함해 작동하지 않거나, 개인화 카드가 일반 카드보다 선택되지 않는 신호가 둘 이상 나타나면 재수렴 회의를 진행 |

## 심사 마무리용 답변

> 새록의 핵심은 좋은 질문 한 문장을 생성하는 기능이 아니다. 보호자가 면회에서 어떤 소재를 사용했고 환자와 보호자가 어떻게 반응했는지를 회차별로 남겨, 다음 면회에서 사용할 소재를 다시 고르는 구조다. 아직 효과가 입증됐다고 주장하지 않으며, 10주 동안 개인화 카드의 실제 선택률, 반복 사용 여부와 보호자 부담 변화를 검증한다.
