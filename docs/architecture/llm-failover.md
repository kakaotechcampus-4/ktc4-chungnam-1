# LLM 장애 대응 설계안

작성일: 2026-11-10. 갱신: 2026-11-11. 상태: 일부 로컬 구현, 미배포. 실제 Claude 합성 연결 검사 통과, 자동 전환·생성 품질 미검증.

일시적 오류는 같은 모델에 최대 1회 재시도하며, 기본 설정은 `SAEROK_LLM_RETRY_ENABLED=false`다. SDK 재시도는 끄고 전체 처리 시간 제한과 재전송 전 작업·삭제·동의·만료 검사를 적용한다. 엘리스 Claude Haiku 5.5(`anthropic/claude-haiku-5-5`)는 실제 API로 스트리밍·구조화 출력·도구 호출을 확인했다. 운영 생성 함수의 Claude 자동 전환과 개인·외부 API 호출은 미구현이다. 실행 방법은 [AI README](../../ai/README.md), 구조 검토는 [ADR-010](decisions/ADR-010-llm-resilience.md)을 참고한다.

2026-11-11 로컬 검사: `ai/`에서 `.venv/bin/python -m pytest`는 216 passed·24 skipped, `backend/`의 같은 명령은 488 passed·557 skipped. DB 연결 설정이 필요한 통합 검사는 실행하지 못했다. 재시도 횟수, 시간 예산, 서버 대기 안내, 불완전 스트리밍 응답 폐기, 형식 재시도와의 중복 방지, 삭제된 카드 작업과 철회된 사진 동의의 재전송 차단은 합성 자료와 로컬 대역으로 확인했다. 위 단위검사에서는 외부 API를 호출하지 않았다. 이후 제공받은 실제 엘리스 Claude 주소로 합성 연결 검사를 별도 수행해 통과했다(호출 제한 30초, 출력 상한 2048, 재시도 끔). 카드·리포트 품질, 이미지 입력과 운영 자동 전환 검증 및 배포는 하지 않았다.

## 목적과 우선순위

카드, 리포트, 변경 제안과 사진 설명 생성이 단일 LLM 경로 장애로 모두 중단되는 위험을 줄인다. 카테캠 기간에는 비용 지원을 받는 엘리스 ML API를 최대한 사용한다.

2026-11-10 사용자 결정에 따른 전환 순서는 다음과 같다.

1. 엘리스 ML API를 통한 `gpt-6-luna` 모델 호출
2. 엘리스 ML API를 통한 Claude Haiku 5.5 모델 호출
3. 개인 OpenAI API 계정으로 `gpt-6-luna` 모델 직접 호출. 이 호출도 실패하면 외부 Claude API를 통한 Claude Haiku 5.5 모델 호출로 전환

두 엘리스 호출 경로가 모두 실패하면 개인 OpenAI API 계정을 사용하고, 해당 GPT 호출도 실패하면 외부 Claude API로 전환한다. 외부 Claude 모델은 앞서 지정한 Claude Haiku 5.5를 사용하는 설계 가정이며, 실제 제공 여부와 API 모델 식별자는 구현 전에 확인한다. 외부 API별 지출 상한과 상한 도달 시 동작은 아직 정하지 않았으며 운영 적용 전에 확인한다.

같은 경로의 일시적 오류 재시도는 최대 1회(최초 호출 포함 최대 2회 시도)로 한다. 전환 시간은 검증 후 정한다. 재시도는 로컬 합성 검증을 진행했고, 실제 서비스 성능과 자동 전환 검증은 아직 하지 않았다.

이 문서에서 호출 경로는 ‘새록 서버가 요청을 보내는 API 서비스와 그 API가 실행하는 모델의 조합’을 뜻한다. 예를 들어 개인 OpenAI API 계정을 통한 직접 호출은 엘리스 ML API를 거치지 않고 새록 서버가 사용자의 개인 계정 API 키로 OpenAI API에 요청하는 방식이다. API 키는 서버의 비밀 설정으로만 관리하고 문서·저장소·로그에 남기지 않는다. 대체 모델명 Claude Haiku 5.5와 엘리스 API 식별자 `anthropic/claude-haiku-5-5`는 사용자가 제공했다. 엘리스 API 주소와 모델 식별자의 실제 호출은 확인했다. 외부 Claude API의 모델 식별자와 호출 주소는 아직 확인하지 않았다.

현재 BE 설정의 카드·리포트 생성 기본 모델은 `gpt-6-luna`이며, 사진 설명은 별도 설정이 없으면 리포트 모델을 사용한다. 운영 환경의 명시적 설정은 기본값보다 우선한다. `ai/common/llm.py`의 모델 주소는 모두 엘리스 경로이고 SDK(API 호출을 처리하는 라이브러리)의 자동 재시도는 꺼져 있다. 이 문서는 자동 전환이 구현됐다는 뜻이 아니다.

## 장애 구분과 경로 선택

오류 코드, 연결 단계, 최근 호출 결과와 합성 입력 점검을 함께 사용한다. 중계 플랫폼의 시간 초과나 5xx만으로 상위 모델 장애를 확정하지 않는다. 원인 확정보다 사용 가능한 경로를 확인해 복구하는 것을 우선한다.

| 관측 결과 | 판단과 대응 |
| --- | --- |
| 엘리스 ML API의 GPT 호출 실패, Claude 호출 성공 | GPT 연결 구간 문제 가능성. 엘리스 ML API의 Claude Haiku 5.5 사용 |
| 엘리스 ML API의 두 모델 호출 실패, 개인 OpenAI API의 GPT 호출 성공 | 엘리스 공통 연결 구간 문제 가능성. 개인 OpenAI API의 GPT 사용 |
| 앞의 세 경로 실패, 외부 Claude API 호출 성공 | 원인 불명 또는 복합 장애. 외부 Claude API의 Claude Haiku 5.5 사용 |
| 네 경로 모두 실패 | 명시적 실패와 재시도 안내 |

표의 엘리스 모델 호출은 위 목록의 구체적인 API·모델 조합을 뜻한다.

표의 성공·실패는 관측 결과이며 플랫폼 전체 장애의 확정 판정이 아니다. OpenAI API로 GPT 모델을 직접 호출한 적이 없다면 상태는 ‘미확인’으로 둔다. 개인 OpenAI API와 외부 Claude API의 유료 점검 호출도 각 경로의 비용 제한을 적용한다. 엘리스 ML API를 통한 Claude Haiku 5.5 모델 호출이 정상이면 원인 진단을 위해 OpenAI API로 GPT 모델을 추가로 직접 호출할 필요는 없다.

점검은 우리 운영 서버에서 사용자 자료 없는 합성 입력으로 수행한다. 홈페이지 접속 여부뿐 아니라 실제 생성과 필요한 JSON 출력·도구 호출·이미지 입력의 지원 여부를 확인한다. 매 요청마다 모든 경로를 호출하지 않고 최근 결과와 주기적 점검을 활용한다. 점검 주기와 상태 유효기간은 검증 후 정한다.

## 호출과 복구 규칙

- 연결 실패, 시간 초과, 5xx와 일시적 호출 제한은 제한된 재시도 또는 전환 대상으로 분류한다. 인증·결제·설정 오류는 반복하지 않고 운영자에게 알리며 허용된 대체 경로를 판단한다. 입력·권한·동의 오류는 다른 경로로 우회하지 않는다.
- 일시적 오류는 같은 경로로 최대 1회 재시도하고, 다시 실패하면 다음으로 허용된 경로로 전환한다. 엘리스 ML API를 통한 `gpt-6-luna` 모델 호출 다음에는 엘리스 ML API를 통한 Claude Haiku 5.5 모델 호출을 우선한다. 재시도 전에는 잠시 대기하며 일시적 429의 서버 대기 안내와 남은 처리 시간을 확인한다. 시간 초과 등으로 예산이 부족하면 재시도를 생략하고 전환 또는 명시적 실패로 끝낸다. 대기 시간은 검증 후 정한다.
- SDK 자동 재시도는 끈 상태를 유지하고 공통 전환 코드 한 곳에서 재시도를 관리한다. SDK·생성 단계·worker에서 각각 재시도해 상한이 중복 적용되지 않게 한다. 이 상한은 개별 LLM 호출의 같은 경로 재시도 기준이며, 보호자가 요청하는 리포트 재처리 횟수와는 별개다.
- 재시도, 점검과 전환에 하나의 전체 시간·호출·비용 예산을 적용한다. 주 경로가 전체 시간을 소진하기 전에 예비 경로를 시도할 여유를 둔다. 반복 실패한 경로는 잠시 제외하고 회복 점검 후 복귀한다. 구체적인 상한과 복귀 조건은 시험으로 정한다.
- 다단계 생성은 실패한 단계의 입력과 호환성을 확인해 재개 범위를 정한다. 제공사 전용 추론 상태를 다른 모델에 그대로 전달하지 않는다. 늦게 도착한 응답과 재시도로 결과가 중복 저장되지 않게 한다.
- 형식·내용 검증 실패는 인프라 장애와 구분한다. 대체 모델 결과에도 같은 검증을 적용하고, 빈 결과나 불완전 결과를 정상 완료로 저장하지 않는다. AI 제안은 보호자 승인 없이 프로필·스토리북에 반영하지 않는다.
- 리포트 재시도는 기존 전사의 남은 보관 기한 안에서 수행한다. LLM 장애만으로 STT를 다시 실행하거나 보관 기한을 연장하지 않는다. 매 외부 전송 직전 삭제·권한·동의·만료 조건을 다시 검사한다.
- 기록에는 경로, 모델·프롬프트 버전, 오류 분류, 처리 시간, 전환 결과와 사용량 등 필요한 운영 정보만 남긴다. 입력·출력 원문, 사진 주소, 키와 민감한 오류 본문은 남기지 않는다.
