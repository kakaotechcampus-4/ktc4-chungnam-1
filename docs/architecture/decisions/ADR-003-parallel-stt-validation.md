# ADR-003: Python 기준 환경과 온디바이스 STT 병렬 검증

상태: proposed
담당: PM, BE, AI
결정일: 결정 대기
관련 Issue: #6, #7, #9

## 배경

현재 아키텍처는 프로필, 전사문과 회차 기록의 단말 저장을 기본으로 하고, STT와 화자 처리도 단말 실행을 우선 검토한다. 동시에 초기 모델, 신뢰도 기준, 처리 단계와 공통 데이터 계약은 반복 실험을 거쳐야 한다.

Python 환경은 모델과 파이프라인을 빠르게 검증하는 데 유리하지만, 서버 전체 흐름이 완성된 뒤에만 온디바이스 검증을 시작하면 스프린트 1의 핵심 기술 위험인 단말 STT 실행 가능성을 늦게 확인하게 된다. FE가 서버 구현을 기다리면 화면과 처리 흐름의 병렬 개발도 지연된다.

## 제안

- 스프린트 1부터 Python 기준 환경과 온디바이스 STT 실험을 병렬로 진행한다.
- Python 환경은 합성 자료 또는 사용 권한이 확인된 테스트 자료로 데이터 계약, STT 기준 결과와 처리 파이프라인을 빠르게 검증하는 개발용 기준 환경으로 사용한다.
- 온디바이스 STT는 Python 환경의 전체 구현 완료를 기다리지 않고 대상 Android 단말에서 기능 단위로 실행한다.
- 온디바이스와 Python 또는 서버형 기준 STT는 동일한 테스트 자료와 평가 항목으로 비교한다.
- FE는 서버 구현을 기다리지 않고 버전이 있는 공통 데이터 계약과 합성 mock 데이터로 워킹 스켈레톤을 구현한다.
- Python 환경과 온디바이스 구현은 정상, 저신뢰도와 실패 결과를 동일한 공통 계약으로 반환한다.
- 특정 모델, 서버 DB, HTTP 응답 형식과 외부 SDK 형식을 공통 데이터 계약에 직접 노출하지 않는다.
- 실제 사용자 데이터의 저장 위치, 보유기간, 삭제 범위와 외부 처리 조건은 이번 ADR에서 확정하지 않고 별도 결정으로 유지한다.
- 외부 STT, LLM과 이미지 분석 업체 도입은 이번 ADR의 범위가 아니며, 도입 전 법률 및 데이터 처리 조건을 별도로 검토한다.
- 기존 ADR-001의 실제 사용자 원본 처리 경계와 동의 기준은 이 제안으로 완화하지 않는다.

이 ADR이 승인되기 전까지 기존 테크스펙과 영역별 README의 로컬 우선 기준은 유효하다.

## 검토한 대안

### 처음부터 단말에서 전체 처리

- 실제 사용자 데이터의 외부 이동을 최소화할 수 있다.
- Flutter 연동, 모바일 모델 실행, 단말별 성능과 복구를 동시에 해결해야 하므로 기준 결과와 데이터 계약 검증이 늦어질 수 있다.

### Python 서버 전체 구현 후 단말로 이전

- AI와 BE가 한 환경에서 전체 흐름을 빠르게 연결할 수 있다.
- 단말 STT의 처리 시간, 메모리, 발열과 실패 가능성을 늦게 확인하게 되며 서버 구현이 로컬 이전의 선행 조건이 될 수 있다.

### Python 기준 환경과 온디바이스 STT 병렬 검증

- 기준 결과와 데이터 계약을 빠르게 검증하면서 단말 실행 위험을 초기에 확인할 수 있다.
- 두 환경의 중복 작업을 줄이려면 공통 계약과 실행 경계를 먼저 합의해야 한다.

## 영향

- BE는 Python 검증 환경, 공통 데이터 검증과 STT 구현 교체 경계를 구성한다.
- AI는 온디바이스 후보와 Python 또는 서버형 기준 후보를 같은 자료와 평가 기준으로 비교한다.
- FE는 합성 mock 데이터와 공통 계약을 사용해 서버와 STT 구현을 기다리지 않고 핵심 화면 흐름을 구성한다.
- QA는 정상, 저신뢰도, 처리 실패와 수동 전환 케이스의 자료, 기대 결과와 출처를 관리한다.
- 공통 데이터 계약은 FE, BE와 AI 리더가 공동 검토하며 한 영역이 단독으로 호환성을 깨는 변경을 하지 않는다.
- 실제 사용자 데이터를 처리하는 구조는 동의, 인증, 암호화, 로그, 보유기간, 삭제와 외부 업체 조건을 확정한 뒤 도입한다.

## 검증

- 허가된 동일 테스트 자료로 온디바이스 후보와 기준 후보를 각각 최소 한 번 실행한다.
- 모델명, 버전, 실행 환경, 정확도, 처리 시간, 메모리, 발열, 비용과 실패 결과를 가능한 범위에서 함께 기록한다.
- 정상, 저신뢰도와 실패 결과를 동일한 공통 계약으로 표현한다.
- FE 워킹 스켈레톤이 실제 서버와 STT 없이 합성 mock 데이터로 실행된다.
- Python 검증 환경이 서버 배포 없이 개발자의 로컬 환경에서 재현된다.

## 재검토 조건

- 대상 Android 단말의 STT 벤치마크 결과가 나온 경우
- Python 기준 결과와 온디바이스 결과의 차이가 제품 기준을 충족하지 못하는 경우
- 실제 사용자 자료를 이용한 검증을 시작하는 경우
- 프로필, 전사문, 리포트와 누적 문맥의 서버 보존 여부를 결정하는 경우
- 외부 STT, LLM 또는 이미지 분석 업체를 도입하는 경우
