# ADR-004: 로컬 FastAPI 기준 환경과 온디바이스 처리 병렬 검증

상태: proposed  
담당: PM, BE, AI, FE  
결정일: 결정 대기  
관련 Issue: #6, #7, #9

## 배경

새록은 프로필, 전사문과 면회 회차 기록을 사용자 단말에 저장하는 것을 기본으로 한다. STT와 화자 처리도 경량 모델을 이용한 단말 실행을 우선 검토하고 있으나, 모델과 실행 방식, 신뢰도 기준 및 처리 단계는 아직 검증 중이다.

Flutter 앱에는 합성 목 데이터로 동작하는 화면 골격이 준비되어 있다. 이제 Python 기반 처리 파이프라인과 Flutter 사이의 HTTP 통신, 공통 데이터 계약, 정상·저신뢰도·실패 상태를 실제 실행 환경에서 검증할 기준 구현이 필요하다.

Python 환경은 AI 및 처리 파이프라인을 빠르게 실험하기에 적합하지만, 이를 곧바로 실제 사용자 데이터를 보관하는 운영 서버로 해석하면 기존의 로컬 저장 원칙과 충돌한다. 반대로 Python 기준 환경의 전체 구현이 끝날 때까지 온디바이스 검증을 미루면 단말 성능, 메모리, 발열과 앱 생명주기 관련 위험을 늦게 발견할 수 있다.

## 결정

- 개발자의 로컬 PC에서 실행하는 FastAPI를 Flutter 연동과 Python 처리 파이프라인 검증을 위한 기준 환경으로 사용한다. 이는 운영 서버 도입을 확정하는 결정이 아니다.
- 첫 구현은 합성 데이터로 동작하는 상태 확인과 대화 카드 생성까지로 제한한다. 실제 인증, 데이터베이스, 사용자 기록 저장, 음성·이미지 업로드와 외부 AI 호출은 포함하지 않는다.
- 프로필, 전사문, 회차와 리포트의 기본 저장 위치는 단말로 유지한다. FastAPI는 합의된 처리만 수행하는 `ProcessingGateway`로 분리하고 내부 생성 구현은 교체 가능한 adapter 뒤에 둔다.
- Flutter, FastAPI와 온디바이스 구현은 `schemaVersion`이 있는 공통 데이터 계약으로 정상, 저신뢰도와 실패를 동일하게 표현한다. 실패를 사용자에게 알리지 않고 목 결과나 성공으로 바꾸지 않는다.
- 요청·응답 본문과 민감정보를 로그에 남기지 않으며, 실제 사용자 자료와 마스킹한 실제 자료는 첫 구현의 요청, 응답, 로그와 테스트에 사용하지 않는다.
- FastAPI 기준 환경과 온디바이스 STT 검증을 병렬로 진행한다. 운영 배포나 실제 사용자 데이터 처리가 필요해지면 ADR-001을 따르고 데이터 흐름, 법률 문서와 별도 ADR을 먼저 갱신한다.

## 검토한 대안

### 처음부터 모든 처리를 단말에서 수행

- 사용자 데이터의 외부 이동을 최소화할 수 있다.
- Flutter 연동, 모바일 모델 실행, 데이터 계약과 처리 파이프라인을 동시에 해결해야 하므로 기준 결과를 빠르게 만들기 어렵다.

### FastAPI를 운영 백엔드로 먼저 완성

- 하나의 Python 환경에서 API, 저장소와 AI 파이프라인을 연결할 수 있다.
- 운영 서버와 인증, 개인정보 저장 및 원본 처리 경계를 먼저 결정해야 한다.
- 온디바이스 실행 가능성 검증이 늦어지고 서버 구현이 로컬 처리의 불필요한 선행 조건이 될 수 있다.

### 로컬 FastAPI 기준 환경과 온디바이스 처리를 병렬 검증

- Flutter와 Python 사이의 계약과 실패 흐름을 빠르게 검증하면서 단말 실행 위험도 초기에 확인할 수 있다.
- 기준 환경과 단말 구현의 중복을 줄이려면 공통 데이터 계약과 adapter 경계를 먼저 합의해야 한다.

위 이유로 세 번째 대안을 제안한다.

## 영향

- BE는 로컬에서 재현 가능한 FastAPI 구조, 입력 검증, 오류 처리, 로그 제한, 처리 서비스와 adapter 경계를 구현한다.
- AI는 FastAPI용 기준 adapter와 온디바이스 후보가 사용할 입출력, 모델 정보, 신뢰도 및 실패 기준을 BE와 함께 검토한다.
- FE는 화면이 구체적인 HTTP 구현에 직접 의존하지 않도록 로컬 저장소와 처리 gateway를 분리하고, 명시적인 설정으로 목 구현과 FastAPI 구현을 선택한다.
- QA는 정상, 저신뢰도, 처리 실패와 수동 전환을 검증할 합성 또는 사용 권한이 확인된 자료와 기대 결과를 관리한다.
- PM은 이 제안이 운영 서버 도입이나 실제 사용자 데이터의 외부 전송 동의로 확대 해석되지 않도록 MVP 범위를 관리한다.
- 공통 데이터 계약의 필드와 enum을 바꾸면 FE, AI와 BE가 함께 검토하고 관련 문서와 합성 목 데이터를 같은 변경에서 갱신한다.
- 개발용 HTTP 연결은 신뢰할 수 있는 로컬 개발 환경에서 합성 데이터로만 사용한다. 운영 환경의 전송 보안 결정으로 간주하지 않는다.

## 검증

- 새 환경에서 문서화된 명령으로 FastAPI를 로컬 실행하고 상태 확인 엔드포인트가 정상 응답하는지 확인한다.
- Android 에뮬레이터 또는 허가된 개발 단말에서 Flutter가 로컬 FastAPI에 연결되는지 확인한다.
- 합성 카드 생성 요청과 응답이 공통 데이터 계약 및 Flutter 모델과 일치하는지 계약 테스트로 확인한다.
- 잘못된 enum, 버전, 시간 형식과 필수값 누락이 명시적인 오류 코드로 거부되는지 확인한다.
- 서버 중단과 타임아웃이 Flutter에서 성공이나 목 결과로 표시되지 않고 수동 재시도가 가능한 실패 상태로 보이는지 확인한다.
- 로그와 예외 메시지에 요청·응답 본문, 직접 식별정보, 전사문과 로컬 파일 경로가 포함되지 않는지 확인한다.
- 첫 구현에 실제 계정 DB, 사용자 기록의 영구 저장, 음성·이미지 업로드와 외부 AI 호출 경로가 없는지 확인한다.
- 허가된 동일 테스트 자료로 Python 기준 후보와 온디바이스 후보를 각각 실행하고 가능한 범위에서 처리 시간, 메모리, 실패 결과와 품질 지표를 기록한다.

## 재검토 조건

- 실제 사용자 자료로 통합 검증을 시작하는 경우
- 음성 또는 이미지 원본을 FastAPI로 업로드해야 하는 경우
- FastAPI를 외부에서 접근 가능한 운영 환경에 배포하는 경우
- 계정 인증이나 프로필, 전사문, 회차 기록의 서버 저장이 필요한 경우
- 작업 큐, 데이터베이스 또는 외부 저장소를 도입하는 경우
- 외부 STT, LLM 또는 이미지 분석 업체를 도입하는 경우
- 온디바이스 벤치마크 결과가 나와 서버 처리 필요성을 다시 판단할 수 있는 경우
- 공통 데이터 계약의 하위 호환성을 깨는 변경이 필요한 경우
