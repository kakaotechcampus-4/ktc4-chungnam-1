# ADR-006: STT와 VLM의 서버 측 처리

상태: accepted
담당: PM, AI, BE
결정일: 2026-09-11
관련 Issue: #7, #19, #24

## 배경

대상 Android 단말에서 STT를 실행한 결과, 작은 모델은 처리 시간과 잡음 환경의 품질이 서비스 흐름에 맞지 않았다. VLM도 시험한 모바일 후보에서 문맥 생성 품질과 자원 제약이 확인됐다. 2026-09-10 팀 논의 후 PM이 두 기능의 온디바이스 처리를 제외하고 서버 측 처리로 전환하기로 확정했다.

이 결정은 AI 처리 위치를 정한다. 자체 장비, 학교 GPU, 클라우드 GPU와 외부 API 중 어떤 환경을 사용할지는 아직 정하지 않는다.

## 결정

- STT와 VLM은 온디바이스에서 실행하지 않고 서버 측에서 처리한다.
- 프로필, 확정된 전사문, 회차 기록과 스토리의 기본 저장 위치는 사용자 단말로 유지한다.
- 음성과 이미지 원본은 해당 기능의 동의를 확인한 뒤 암호화해 전송하고, 처리 완료 후 즉시 삭제한다. 어떤 경우에도 24시간을 넘기지 않으며 삭제 결과를 확인할 수 있어야 한다.
- 처리 업체, 국가, 보유기간, 자체 학습 여부와 법적 조건을 확인하기 전에는 실제 사용자 자료를 외부 서비스에 보내지 않는다.
- VLM은 태그 목록을 주 결과로 사용하지 않는다. 사진에서 직접 관찰한 내용, 대화에 쓸 수 있는 문맥, 불확실한 내용과 질문 후보를 구분해 반환한다.
- 사진 메타데이터는 AI 입력의 보조 참고값으로만 사용한다. 스캔, 재촬영, 편집과 전송 과정에서 달라질 수 있으므로 사실로 확정하지 않는다.
- VLM 결과와 메타데이터는 보호자가 확인하기 전에는 프로필과 스토리에 반영하지 않는다.
- 로컬 FastAPI 골격은 계약과 오류 흐름을 검증하는 개발 기준 환경으로 계속 사용한다. 운영 배포 구조로 자동 확정하지 않는다.

## 아직 정하지 않은 내용

- 서버 운영 위치와 업체
- GPU 사양, 모델, 동시 처리량과 비용 한도
- 작업 큐, 재시도, 취소와 장애 복구 방식
- 문맥형 VLM 결과의 최종 필드와 평가 기준
- STT 모델, 화자 처리 방식과 품질 기준
- 처리 결과를 단말로 전달하는 인증과 API 세부 구조

## 검토한 대안

### 온디바이스 처리 유지

원본 이동을 줄일 수 있지만, 현재 시험한 단말과 후보에서는 처리 시간과 결과 품질이 핵심 흐름을 충족하지 못했다. 모바일 최적화를 계속하는 비용도 커서 제외했다.

### 서버 측 처리

더 큰 모델과 GPU를 사용할 수 있고 앱의 자원 제약을 줄일 수 있다. 대신 원본 전송, 동의, 암호화, 임시 보관, 삭제와 비용 관리가 필요하다. 현재는 이 방식을 채택한다.

## 영향

- FE는 업로드 동의, 처리 대기, 취소, 실패, 재시도와 보호자 확인 화면을 제공한다.
- BE는 업로드 허용 필드, 인증, 작업 상태, 로그 제한, 임시 파일 삭제와 삭제 확인을 구현한다.
- AI는 서버 환경에서 STT와 문맥형 VLM의 모델, 프롬프트, 품질과 실패 기준을 검증한다.
- QA는 잘못된 메타데이터, 환각, 잡음, 부분 실패와 서버 장애 시나리오를 확인한다.
- PM은 업체와 비용, 실제 사용자 자료를 처리할 수 있는 법적 조건을 승인한다.

ADR-003과 ADR-004의 온디바이스 병렬 검증 방향은 이 결정으로 대체한다. 두 문서에서 정한 합성 자료, 공통 계약, 실패 상태와 로컬 FastAPI 검증 원칙은 유지한다.

## 검증

- 실제 사용자 자료가 아닌 허가된 평가 자료로 서버 후보의 정확도, 지연시간, 비용과 실패 상태를 기록한다.
- 음성과 이미지 원본이 허용 목록 밖의 로그와 저장소에 남지 않는지 검사한다.
- 처리 성공, 부분 실패, 전체 실패와 타임아웃을 공통 데이터 계약으로 구분한다.
- VLM의 관찰, 추정과 질문 후보가 구분되고 보호자 승인 전 사실로 저장되지 않는지 확인한다.

## 재검토 조건

- 서버 비용이나 지연시간이 제품 기준을 충족하지 못하는 경우
- 외부 업체의 보유, 학습 또는 국외 이전 조건이 팀의 개인정보 기준과 맞지 않는 경우
- 대상 단말과 모델 기술이 바뀌어 온디바이스 처리가 제품 기준을 충족한다는 새 근거가 생긴 경우
- 실제 사용자 자료를 이용한 통합 검증을 시작하는 경우
