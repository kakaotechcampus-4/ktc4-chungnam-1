# ADR-006: MVP의 AI 실행과 서버 중심 데이터 관리

상태: accepted
담당: PM, AI, BE
결정일: 2026-09-14
관련 Issue: #7, #18, #19, #24

## 배경

대상 Android 단말에서 STT를 실행한 결과, 작은 모델은 처리 시간과 잡음 환경의 품질이 서비스 흐름에 맞지 않았다. VLM도 시험한 모바일 후보에서 결과 품질과 자원 제약이 확인됐다. 2026-09-14 리뷰 미팅에서 온디바이스 처리를 현재 MVP 범위에서 제외하고 온프레미스 GPU 1대를 사용하는 방향을 확정했다.

이 결정은 MVP의 AI 처리 위치를 팀이 직접 관리하는 온프레미스 GPU 1대로 정한다. GPU의 소유자, 설치 장소, 모델과 운영 방식은 이 결정에서 확정하지 않는다. 상용 GPU 서버와 외부 AI API는 서비스 확장 후보로만 검토한다.

같은 회의에서 단말 저장 중심 문서로는 BE의 데이터 관리 역할이 불명확하고 FE의 로컬 DB 작업과 겹칠 수 있다는 점을 논의했다. 데이터 관리도 서버 중심으로 전환하되, BE가 처리할 정보와 역할을 정리한 PR로 세부 내용을 함께 확인하기로 했다. 2026-09-15 보완에서는 이 합의를 반영해 기존 초안의 단말 저장 유지 문구를 바로잡았다.

## 결정

- MVP의 STT와 VLM은 온디바이스에서 실행하지 않고 온프레미스 GPU 1대에서 처리한다.
- 데이터 관리는 서버 중심으로 전환한다. 프로필, 생애 사실, 회차, 카드, 평가, 리포트, STT 결과와 스토리의 항목별 저장 범위는 BE가 정리하고 FE, AI와 PM이 함께 확인한다.
- 이 방향은 모든 데이터를 서버에 영구 저장하거나 기존 전송 제한을 해제한다는 뜻이 아니다. 세부 계약이 정해지기 전에는 현재 허용 범위를 넘어 실제 사용자 자료를 전송하지 않는다.
- 음성과 이미지 원본은 해당 기능의 동의를 확인한 뒤 암호화해 전송하고, 처리 완료 후 즉시 삭제한다. 어떤 경우에도 24시간을 넘기지 않으며 삭제 결과를 확인할 수 있어야 한다.
- 처리 업체, 국가, 보유기간, 자체 학습 여부와 법적 조건을 확인하기 전에는 실제 사용자 자료를 외부 서비스에 보내지 않는다.
- VLM 출력은 아직 하나로 확정하지 않는다. 키워드 태깅, 이미지 description, description에서 태그를 뽑는 방식과 태그를 문장 및 주제로 결합하는 방식을 같은 사진으로 비교한다.
- 사진 메타데이터는 AI 입력의 보조 참고값으로만 사용한다. 스캔, 재촬영, 편집과 전송 과정에서 달라질 수 있으므로 사실로 확정하지 않는다.
- VLM 결과와 메타데이터는 보호자가 확인하기 전에는 프로필과 스토리에 반영하지 않는다.
- 로컬 FastAPI 골격은 계약과 오류 흐름을 검증하는 개발 기준 환경으로 계속 사용한다. 운영 배포 구조로 자동 확정하지 않는다.

## 아직 정하지 않은 내용

- 온프레미스 GPU의 소유자, 설치 장소, 사양과 운영 방식
- STT와 VLM 모델, 동시 처리량과 비용 한도
- 작업 큐, 재시도, 취소와 장애 복구 방식
- VLM의 태그, description과 결합 출력 중 선택할 형식과 평가 기준
- STT 모델, 화자 처리 방식과 품질 기준
- 처리 결과를 단말로 전달하는 인증과 API 세부 구조
- 데이터별 서버 저장 항목, 단말 보관 및 캐시 여부, 접근 권한, 보관 기간과 삭제 구현
- 계정 및 사용자 기록의 실제 DB 연결과 운영 배치, AI 실행 장비와 데이터 저장 서버의 배치 관계

2026-09-19 구현 상태 보완: PR #39의 PostgreSQL 개발 스키마와 Alembic은 develop에 반영됐다. 계정의 DB 영속 저장과 운영 배포가 완료됐다는 뜻은 아니다. 이 보완은 9월 14일의 결정일을 바꾸지 않는다.

원본 음성과 이미지의 처리 후 즉시 삭제 및 최대 24시간 제한은 미정 항목이 아니며 [ADR-001](ADR-001-consent-and-temporary-processing.md)을 유지한다.

## 검토한 대안

### 온디바이스 처리 유지

원본 이동을 줄일 수 있지만, 현재 시험한 단말과 후보에서는 처리 시간과 결과 품질이 핵심 흐름을 충족하지 못했다. 모바일 최적화를 계속하는 비용도 커서 제외했다.

### 온프레미스 GPU 1대 처리

더 큰 모델과 GPU를 사용할 수 있고 앱의 자원 제약을 줄일 수 있다. 대신 원본 전송, 동의, 암호화, 임시 보관, 삭제와 단일 장비 장애 처리가 필요하다. 현재 MVP는 이 방식을 채택한다.

### 상용 GPU 서버 또는 외부 AI API

운영 부담을 줄일 수 있지만 비용과 개인정보의 제3자 제공 여부를 확인해야 한다. GLM 5.3 Flash를 포함한 후보는 허가된 공개 자료로 먼저 비교하고, 실제 사용자 자료 전송은 법적 조건을 확정하기 전 금지한다.

## 영향

- FE는 업로드 동의, 처리 대기, 취소, 실패, 재시도와 보호자 확인 화면을 제공하고 합의된 저장 API를 연결한다.
- BE는 데이터별 저장 위치, 허용 필드, 인증, 접근 권한, 보관 기간과 삭제 조건을 PR로 제안한다. 합의 후 저장 API, 작업 상태, 로그 제한, 임시 파일 삭제와 삭제 확인을 구현한다.
- AI는 온프레미스 GPU에서 STT 모델과 VLM의 태그 및 description 출력, 프롬프트, 품질과 실패 기준을 검증한다.
- QA는 잘못된 메타데이터, 환각, 잡음, 부분 실패와 서버 장애 시나리오를 확인한다.
- PM은 업체와 비용, 실제 사용자 자료를 처리할 수 있는 법적 조건을 승인한다.

ADR-003과 ADR-004의 온디바이스 병렬 검증과 단말 우선 저장 방향은 이 결정으로 대체한다. 두 문서에서 정한 합성 자료, 공통 계약, 실패 상태와 로컬 FastAPI 검증 원칙은 유지한다.

## 검증

- 실제 사용자 자료가 아닌 허가된 평가 자료로 서버 후보의 정확도, 지연시간, 비용과 실패 상태를 기록한다.
- 음성과 이미지 원본이 허용 목록 밖의 로그와 저장소에 남지 않는지 검사한다.
- 처리 성공, 부분 실패, 전체 실패와 타임아웃을 공통 데이터 계약으로 구분한다.
- VLM의 태그, description과 결합 출력 결과를 같은 공개 이미지로 비교하고 보호자 승인 전 사실로 저장되지 않는지 확인한다.
- 실제 저장 연동 전에 데이터별 처리 목적, 저장 위치, 접근 권한, 보관 기간과 삭제 조건을 계약 및 법률 문서와 맞춘다. 서버 저장 범위가 미정인 자료를 합의 없이 전송하지 않는다.

## 재검토 조건

- 서버 비용이나 지연시간이 제품 기준을 충족하지 못하는 경우
- 외부 업체의 보유, 학습 또는 국외 이전 조건이 팀의 개인정보 기준과 맞지 않는 경우
- 대상 단말과 모델 기술이 바뀌어 온디바이스 처리가 제품 기준을 충족한다는 새 근거가 생긴 경우
- 실제 사용자 자료를 이용한 통합 검증을 시작하는 경우
