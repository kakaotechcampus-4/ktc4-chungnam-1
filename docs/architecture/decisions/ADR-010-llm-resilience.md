# ADR-010: LLM 1회 재시도와 엘리스 Claude 연결 분리

상태: proposed (재시도 1회와 전환 우선순위는 사용자 결정, 구현 구조는 검토 중)

작성일: 2026-11-11. 관련 Issue: 미연결. 검토: AI·BE, 운영 적용 조건은 PM 확인.

## 배경과 방향

운영 중인 GPT 호출을 유지하면서 엘리스 우선 장애 대응을 단계적으로 준비한다. [설계안](../llm-failover.md)의 전체 전환 흐름을 한 번에 배포하지 않는다.

- SDK 자동 재시도는 0으로 유지하고 동기 LLM 공통 호출부에서 일시적 오류를 최대 1회 재시도한다. 형식 재시도와 중첩하지 않으며 최초 호출과 전체 마감 안에서 수행한다.
- worker 설정 기본은 재시도 끔이다. 켜더라도 재전송 전 작업·삭제·동의·만료 검사를 생략하지 않는다.
- 엘리스 Claude의 연결 생성과 합성 점검을 운영 생성 경로에서 분리한다. 사용자 제공 식별자는 `anthropic/claude-haiku-5-5`이며, 2026-11-11 제공받은 실제 주소는 연결 코드 기본값에 반영했다. 2026-11-11 사용자 제공 엘리스 API 설명에서 Chat Completions·구조화 출력·도구 지원과 해당 모델 별칭을 확인했다. 실제 주소에서 합성 스트리밍 텍스트·구조화 출력·도구 왕복 검사를 통과했다. 실제 생성 기능의 품질과 자동 전환은 미검증이다. 모델 라이선스·이용 조건과 보관·학습 조건도 미확인이다.
- Claude 자동 전환, 개인 OpenAI API와 외부 Claude API는 이번 구현 범위에서 제외한다. API 응답·DB 스키마를 바꾸지 않는다.

## 영향과 검증

재시도를 활성화하면 호출량·비용과 처리 시간이 늘 수 있다. LangChain 동기 생성 경로를 확장하므로 버전 갱신 시 내부 스트리밍·도구·구조화 출력의 재시도 횟수를 재검증한다. 합성 장애와 로컬 HTTP 대역으로 횟수·시간·업무 검사·불완전 응답 폐기를 검사한다. 실제 DB 검사와 실제 Claude 연결·품질 시험은 별도이며, 실제 사용자 자료 사용 승인을 대신하지 않는다.

운영 활성화 전 대기 시간과 성공률·전체 지연을 검증한다. Claude 적용 전 기능별 API 호환성·품질과 [법률 확인 조건](../../legal/README.md#개발-우선과-실제-사용자-자료-사용-전-확인)을 확인한다. 구조화 출력·도구·이미지 지원 차이 또는 마감 준수 실패가 있으면 전환 구조를 재검토한다.
