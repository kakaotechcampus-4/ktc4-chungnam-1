# 법률과 개인정보 검토

관리: 주 PM 김영석, 부 PM 이예은

## 개발 우선과 실제 사용자 자료 사용 전 확인

2026-10-14 PM 결정: 기능 개발과 연동 테스트를 먼저 진행하고, 남은 개인정보와 법률 검토는 실제 사용자 자료를 사용하기 전에 마친다. 검토가 남았다는 이유로 기능 전체를 보류하지 않는다. 합성 데이터 또는 해당 처리와 전송에 사용할 권한이 확인된 테스트 자료를 사용하며, 문서별로 더 좁게 제한한 테스트 자료 범위는 유지한다.

정책이 미정인 부분은 테스트 가정과 미결 사항으로 구분한다. 개발자가 그 가정을 확정 정책으로 처리하지 않으며, 기존 인증, 동의 검사와 삭제 처리를 임의로 해제하지 않는다. 아래 확인이 끝나기 전에는 실제 사용자 자료를 사용하는 기능을 개방하지 않는다. 개발 서버나 시연도 실제 사용자 자료를 사용한다면 같은 조건을 적용한다.

| 사용 전 확인할 사항 | 확인 주체 | 완료해야 할 시점 |
| --- | --- | --- |
| 수집 목적과 항목, 필요한 동의 문구, 피보호자 동의와 대리 권한 확인 방식 | PM, FE와 BE 구현 확인 | 실제 사용자 자료 수집 전 |

| 외부 업체, 전송 항목, 국가, 보관과 학습 조건, 위탁 및 국외 이전 등 필요한 검토 | PM, BE와 AI가 실제 처리 경로 제공 | 실제 사용자 자료 외부 전송 전 |

| 자료별 보관 기간과 삭제 조건, 서버와 단말 및 임시 사본의 실제 처리 검증 | BE, FE, AI, PM이 정책 확인 | 실제 사용자 자료 저장 전 |
| 실패 전사의 남은 기한 보관(2026-11-03 PM 승인)에 맞춘 동의 문안 반영, 기기 녹음 안내와 삭제 실패 처리 | PM, BE와 FE가 코드 및 삭제 검사 결과 제공 | 11/3 복구 변경의 운영 적용 전 |

남은 세부 쟁점은 이 문서의 [열린 쟁점](#열린-쟁점)에서 관리한다. 테스트 통과는 위 검토와 실제 사용자 자료 사용 승인을 대신하지 않는다.

2026-11-03 ck SSH 예비 경로는 합성 음성으로 검증한 뒤 PM의 자동 전환 적용 요청으로
임시 배포했다. 개인 GPU의 기본 경로, BE의 기존 동의와 소유권 검사, 원본 삭제 기한은
유지한다. 실제 사용자 자료의 학교 서버 전송은 PM의 사용 범위 및 안내 확인과 BE, AI의
접근 권한, 로그, 임시 파일 및 삭제 검증을 별도로 기록한다. 자동 전환 구현을 실제 사용자
자료 전송의 법률 검토 완료로 표시하지 않는다. [운영 연결 문서](../../backend/docs/stt-backup-ssh.md)를 따른다.

## 현재 확정된 데이터 원칙

- 데이터 관리는 서버 중심으로 전환하되, 데이터별 서버 저장 항목, 단말 보관 여부, 목적, 접근 권한, 보관 기간과 삭제 구현은 BE 제안 후 FE, AI와 PM이 함께 확인함
- 서버 중심 전환은 모든 원본의 영구 저장이나 기존 전송 제한 해제를 승인한 것이 아님. 동의안과 기능 대응표를 새 데이터 흐름에 맞춰 검토하기 전에는 실제 사용자 자료의 수집과 전송 범위를 확대하지 않음
- 서버에 올린 녹음 사본은 동의한 기능에 필요한 경우 암호화하여 임시 저장하고 STT 처리 완료 후 즉시 삭제하며 서버 업로드 후 최대 24시간을 넘기지 않는 기준을 유지함. 기기 녹음의 보관은 별도이며 아래 로컬 수정안에서 구분함. 등록 사진과 AI 임시 사본의 보관 구분은 아래 PM 수정안에서 별도로 다룸
- BE는 음성 처리 동의를 확인한 요청만 AI 서버에 전달하고 동의 확인 이력을 관리함. AI 서버는 동의를 별도로 판단하지 않음
- 직접 식별정보는 외부 AI 요청에서 제외함
- 실제 사용자 자료와 마스킹한 실제 자료를 GitHub에 저장하지 않음
- 실제 사용자 정보와 전사 내용을 로그와 원격 분석에 남기지 않음
- 가입 시 서비스 제공을 위한 개인정보 처리와 건강 관련 민감정보 처리 동의를 구분해 받음. 피보호자 최초 정보 입력 전에 본인 동의를 확인하며 대리인이 동의할 때는 적법한 대리 권한도 확인함. 매회 녹음 전 같은 체크박스를 다시 요구하지 않음. 확인 시점과 현재 구현의 차이는 [ADR-001의 PM 수정안](../architecture/decisions/ADR-001-consent-and-temporary-processing.md#녹음-동의-확인-시점)에 기록
- 사진 보관과 AI 분석은 가입 화면에서 별도 선택 항목으로 받음. 이미 유효하게 동의한 항목은 다시 묻지 않고, 미동의자가 해당 기능을 사용하려는 경우에만 동의를 요청함
- 서비스 품질 개선용 가명정보 활용과 푸시 알림은 선택 동의로 운영
- AI 제안은 사용자 확인 전 프로필과 스토리북에 반영하지 않음

## 사진 보관과 분석에 대한 PM 수정안

상태: PR #92는 2026-10-05 병합됐다. 사진 보관과 AI 분석을 가입 화면의 선택 항목으로 받는 시점과 계정별 저장 방식은 2026-10-14 PM이 확정했다. 정책 정본은 [ADR-001의 사진 보관 구분](../architecture/decisions/ADR-001-consent-and-temporary-processing.md#등록-사진과-분석용-임시-사본의-구분)이다. 아래 내용은 실제 동의 화면이나 삭제 기능이 완성됐다는 뜻이 아니다.

- 가입 화면에서 사진 서버 보관과 AI 분석을 각각 선택 동의로 받고, 기존 `consent_records`와 `current_consents`에 두 항목과 이력을 추가한다. 유효한 동의는 사진이나 프로필마다 반복 요청하지 않는다. 거부해도 가입과 사진 없는 기본 서비스는 이용할 수 있다. 미동의, 철회 또는 기록이 없는 계정이 해당 기능을 사용하려고 할 때 필요한 동의를 요청한다. 기존 계정을 자동 동의 처리하지 않는다.
- 휴대폰 사진 선택과 카메라 및 마이크 접근은 기능 사용 시 처리한다. 피보호자별 동의와 대리 권한 확인은 최초 프로필 등록 전에 진행하며, 계정의 가입 동의로 대신하지 않는다.
- 등록 사진은 앨범, 일대기와 면회 기록 표시를 위한 보관 목적과 기간을 별도로 안내한다. 사진 삭제, 보관 동의 철회, 프로필 삭제, 탈퇴 또는 목적 종료 시 지체 없이 삭제한다.
- AI 분석은 별도로 동의를 확인하고 임시 사본만 처리 완료 후 즉시 삭제한다. 실패와 중단 시에도 해당 작업의 최초 임시 사본 생성 후 24시간을 넘기지 않는다.
- 분석 동의만 철회하면 분석을 중단하고 임시 사본을 삭제한다. 등록 사진은 별도로 동의받은 보관 목적이 유지되는 경우에만 보관한다.
- 기존 24시간 삭제 동의를 등록 사진의 지속 보관 동의로 간주하지 않는다. 목적이나 보유기간이 달라지는 자료는 변경 내용을 안내하고 필요한 동의를 확인한다.
- 사진 속 정보주체와 대리 권한 확인, 사진 API의 동의 및 철회 처리, S3 실제 삭제와 삭제 결과 확인은 적용 전 검증 사항이다. 사진 저장 어댑터나 DB 삭제 대기열이 있다는 이유로 완료 처리하지 않는다.
- 미확인 분석 결과의 보관 및 철회 시 처리, EXIF 등 메타데이터의 구체적인 처리 범위, 백업과 단말 자료의 삭제 절차는 이번 변경에서 확정하지 않는다. 사용자가 확인한 이야기 소재의 기존 보유 기준은 유지한다. 필요한 범위를 확인하기 전 실제 사용자 사진 처리를 확대하지 않는다.

법령과 정책의 구분 및 공식 출처는 [ADR-001의 확인 근거](../architecture/decisions/ADR-001-consent-and-temporary-processing.md#사진-보관-개정안의-확인-근거)에 기록한다.

## 구글 로그인 개인정보 처리에 대한 PM 제안

상태: 검토 중, BE와 FE 의견 확인 후 확정. 아래 내용은 팀의 확정된 저장 정책이 아니다.

- 구글 로그인 방식은 [로그인 ADR](../architecture/decisions/ADR-007-google-social-login.md)의 제안을 따른다.
- 서버에는 인증 제공자, 구글 계정 식별자(`sub`), 내부 계정 식별자와 필수 동의 이력만 저장하는 방향이 적절하다고 본다.
- 이메일과 구글 계정 이름은 현재 로그인 목적에 사용하거나 영구 저장하지 않는 안을 제안한다. 실제 구현에서 반환되면 처리 후 폐기할 수 있는지 확인한다.
- BE와 FE는 추가로 필요한 항목이 있다면 사용 목적과 구현상 이유를 공유하고, 그 내용을 함께 검토해 저장 범위를 정한다.
- ID 토큰은 검증 후 폐기하며 데이터베이스, 로그와 오류 응답에 남기지 않는 방향을 검토한다.

## 데이터 흐름 검토안

구글 로그인과 계정 생성 부분은 아래 PM 제안을 적용했을 때의 흐름이며 공동 검토 전이다. 녹음 이후 구간은 ADR-006의 서버 중심 데이터 관리를 따르며 데이터별 저장 범위와 보관 기간은 미정이다.

    구글 로그인과 ID 토큰 검증
    → 계정 생성에 필요한 필수 동의 확인
    → 계정 식별자와 동의 이력을 서버에 함께 저장
    → 피보호자 최초 등록 전 본인 동의 확인, 대리 동의 시 권한도 확인
    → 확인한 동의 범위에서 녹음 시작, 매회 별도 확인 체크박스 없음
    → 단말 녹음
    → 동의와 외부 전송 조건을 확인한 범위에서 Tailscale 사설망을 통한 개인 GPU 임시 처리
    → 관찰값과 이야기 후보 생성
    → 보호자 확인
    → 승인된 사실을 프로필과 이야기에 반영
    → 서버 중심 관리, 데이터별 저장 계약은 미정

위 흐름은 녹음 처리의 목표 설계다. 현재 가입과 녹음 제출 API의 동의 검사는 계정의 `serviceData`, `sensitiveData`를 대상으로 하며, 피보호자별 동의와 대리 권한 확인은 아직 구현되지 않았다. 실제 원본 업로드, 저장, 동의 확인, 삭제와 결과 반환의 구현 및 검증은 아직 필요하다. 녹음 원본은 보호자 확인을 기다리며 계속 보관하지 않고 STT 처리 완료 후 즉시 삭제하며 업로드 후 최대 24시간 제한을 유지한다. 사진은 위 PM 수정안에서 등록 사진과 분석용 임시 사본을 구분한다.

### 면회 음성 비동기 처리 제안

[ADR-008](../architecture/decisions/ADR-008-stt-pipeline.md)은 앱이 면회 WAV와 보호자가
확인한 참여자 수를 백엔드에 제출하고, 백엔드가 비공개 S3에 임시 저장한 뒤 Tailscale 사설망으로 연결한 개인 GPU의
STT 서버에서 비동기로 처리하는 흐름을 제안한다. S3에는 무작위 작업 식별자 기반 객체
키를 사용하고 서버 측 암호화를 적용하며, AI에는 짧은 수명의 Presigned GET URL만
제공한다. 정상 처리에서는 STT 직후 원본 삭제를 시도한다. 업로드 후 최대 24시간
기준을 지키려면 기한 삭제 작업과 지연 감시를 별도로 운영해야 한다. S3 Lifecycle은
일 단위 만료와 비동기 삭제이므로 이 규칙만으로 24시간 이내 삭제를 보장하지 않는다.
삭제 실행기와 만료 자료 대조 도구는 #204로 `develop`에 들어왔고 운영 적용 전이다.

작업 테이블에는 처리 상태, 참여자 수, 크기, SHA-256, 임시 객체 키, 삭제 기한과 삭제
완료 시각을 저장한다. 음성 원본, Presigned URL과 원래 파일명은 작업 테이블과 로그에
저장하지 않는다. 전사문은 현재 구현에서 리포트 입력으로 DB에 임시 저장하고 로그와
공개 상태 응답에는 넣지 않는다. 11/3 복구 보완은 실패 즉시 삭제하던 전사를
남은 기한 동안 재처리에 쓰도록 바꾸므로 보관 정책 변경이며, 2026-11-03 PM이 승인했다.
아래 수정안과 [복구 설명](../../backend/docs/speech-recovery.md)을 참고한다. 이 승인과
이번 구현, 검사는 실제 사용자 자료 사용을 승인하는 것이 아니다.
운영 저장소의 암호화, 접근 권한과 실제 기한 삭제는 적용 전에 확인한다.

이 내용은 합성 자료로 구현 계약을 검증하기 위한 `proposed` 결정이며 실제 사용자
자료의 전송을 승인하지 않는다. 제3자 음성의 처리 근거, 피보호자 동의 방식, S3의 실제
운영 주체와 리전, 접근 권한 및 삭제 증명은 운영 전에 PM과 법률 담당이 확인해야 한다.

### 실패 전사와 기기 녹음 보관의 로컬 수정안

상태: 2026-11-03 코드와 문서 대조 후 작성. 실패 전사 보관 변경은 같은 날 PM이 승인했다. 동의 화면이나 운영 설정은 바꾸지 않았다.

| 자료 | 로컬 코드에서 확인한 보관 및 삭제 | 운영 적용 전 확인 |
| --- | --- | --- |
| 서버 녹음 사본 | STT 직후 삭제 시도, 실패한 삭제는 대기열 처리. 업로드 후 24시간 기준은 전사 재시도로 연장하지 않음 | 실제 삭제 실행과 지연 감시. Lifecycle만으로 기한 삭제를 보장하지 않음 |
| DB 임시 전사 | 최초 STT 저장 시각부터 24시간. 리포트 저장 완료 시 먼저 삭제. 리포트 실패와 작업 임대 만료 시에는 남은 기한 동안 재처리에 사용 | 보관 변경은 2026-11-03 PM 승인. 동의 문구 반영 확인 |
| 재시도한 전사 | 원래 STT 시각과 만료 시각 유지. 이전 작업의 전사는 지우고 새 작업에 옮김. 만료 전사는 재사용 거절 | 만료 정리 실행과 삭제 이력 확인. 재시도 횟수와 관계없이 기한 연장 없음 |
| 기기 앱 전용 녹음 | 전송과 분석 결과 및 경과 시간만으로 삭제하지 않음. 로그아웃 후 계정 격리, 탈퇴 시 삭제 시도, 앱 삭제 시 OS가 앱 전용 자료 제거 | 보관 안내와 탈퇴 시 파일 삭제 실패 처리. 서버 녹음의 24시간을 기기 파일에도 적용한다고 안내하지 않음 |

DB 만료 전사는 worker가 다음 작업을 가져오기 전 또는 상태를 바꿀 때 삭제한다. worker가 멈췄거나 긴 작업을 처리 중이면 물리적 삭제가 늦어질 수 있다. 정리 주기와 지연 감시까지 검증하기 전에는 “코드가 정확히 24시간 이내 삭제를 보장한다”고 설명하지 않는다. 계정 또는 프로필 삭제 시 DB 전사는 연쇄 삭제되지만, 그 전에 만든 DB 백업 안에는 아래 [배포 DB 백업 보관](#배포-db-백업-보관)의 기간 동안 남는다.

전사문의 외부 ML API 전송도 이 24시간 기한 안에서만 시작한다. 코드는 남은 전사 기한이 리포트 생성 단계의 작업 임대 시간(기본 900초, 생성 제한 시간 600초보다 60초 이상 길게 둠) 이상일 때만 생성을 시작하고, 그보다 적게 남은 대기 작업은 보내지 않고 전사를 지운다. 리포트 호출 뒤 변경 제안 호출(같은 전사문의 두 번째 전송) 직전에는 작업 행을 다시 읽어, 그 사이 계정, 프로필이나 회차가 지워졌거나 작업이 끝났거나 기한이 지났으면 보내지 않는다. 이미 보낸 리포트 호출은 되돌리지 못하며, 외부 업체가 받은 요청을 보관하거나 삭제하는 방식은 이 코드로 확인하지 않는다.

기기 보관은 기존 develop `2f3c141`에도 있던 동작이며 이번 복구 변경에서 새로 늘린 기간이 아니다. 다만 기존 동의안에는 서버와 기기 구분이 빠져 있었다. 탈퇴 화면은 기기 파일 삭제 예외를 넘기며 영속 재시도는 없으므로, 탈퇴 성공만으로 모든 기기 사본 삭제를 보증할 수 없다. [동의 문구 수정안](consent-draft.md#녹음과-임시-전사-보관-문구-수정안)에 이 구분과 적용 전 확인 사항을 남긴다. 기기 자료에 새 자동 삭제 기간을 임의로 추가하지 않는다.

### 배포 DB 백업 보관

상태: 보관 기간 14일은 2026-11-09 PM 결정이다. 정리 timer는 저장소(`backend/ops/backup-prune/`)에 있고 운영 서버 설치는 서버 담당이 한다. 이 문서를 고친 시점에는 설치하지 않았다. 설치와 확인 절차는 [오래된 백업 정리](../../backend/docs/release-safety.md#오래된-백업-정리14일-보관)에 있다.

배포 workflow의 백업 단계는 `check`와 `deploy` 모두 운영 DB 전체를 덤프해 서버의 백업 폴더에 남긴다. 덤프에는 그 시점의 계정, 동의 이력, 프로필, 면회 기록, 리포트와 DB 임시 전사가 모두 들어 있다. 백업 폴더와 파일은 root만 읽도록 만든다.

- 만든 지 14일이 지난 백업은 하루 한 번 도는 정리가 지운다. 14일이 지난 뒤 처음 도는 정리에서 지우므로 하루쯤 더 남을 수 있다. 복원 검사에 실패한 백업도 같은 기준으로 지운다.
- 복원 확인된 가장 최근 백업 1개는 14일이 지나도 남긴다. 배포가 14일 넘게 없으면 그 백업이 14일보다 오래 남고, 다음 배포의 백업이 복원 확인되면 그다음 정리에서 지운다.
- 그래서 탈퇴하거나 지운 계정과 프로필, 24시간 기한으로 DB에서 지운 임시 전사도 그 전에 만든 백업 안에는 위 기간 동안 남는다. 백업 안의 개별 계정만 골라 지우지는 않는다. 아래 [구글 로그인 데이터 이동에 대한 PM 검토안](#구글-로그인-데이터-이동에-대한-pm-검토안)의 계정 삭제 시 "지체 없이 파기"와 동의 문구에 이 보관을 어떻게 반영할지는 PM이 확인한다.
- 백업을 운영 DB에 복원하면 백업 시점 뒤의 탈퇴, 프로필과 사진 삭제, 세션 폐기와 동의 철회가 되돌아갈 수 있다. 이를 찾아 다시 적용하는 절차는 후속 작업이며 아직 없다. 복원 판단은 [이상이 생겼을 때](../../backend/docs/release-safety.md#이상이-생겼을-때)를 따른다.
- 남은 마지막 백업은 timer가 지우지 않는다. AWS 종료 전에 남은 백업을 모두 지우는 절차와 담당은 정하지 않았다.
- 정리는 배포 workflow가 만든 이름(`saelog-*.dump`와 같은 이름의 `.json`)만 다룬다. 같은 폴더에 손으로 만든 다른 이름의 덤프나 설정 파일 사본은 14일이 지나도 지우지 않으므로 서버 담당이 따로 처리한다.

## 구글 로그인 데이터 이동에 대한 PM 검토안

아래 판단과 계정 삭제 범위는 검토안이며, 실제 구현과 계약 조건을 확인한 뒤 확정한다.

구글은 새록의 지시를 받아 새록이 보유한 개인정보를 대신 처리하는 수탁자가 아니라, 자체 계정으로 사용자를 인증하고 ID 토큰을 발급하는 외부 인증 제공자다. 사용자가 구글 로그인을 선택하면 새록은 구글에서 계정 식별자 `sub`를 받는다. 이 출처, 항목과 이용 목적은 개인정보 처리방침에 공개한다.

현재 설계에는 새록이 보유한 프로필, 음성, 사진, 전사문, 면회 기록과 리포트를 구글에 전달하는 단계가 없다. 따라서 이 로그인 흐름은 새록이 보유한 개인정보의 구글 제3자 제공, 처리위탁 또는 국외 이전으로 분류하지 않는다. 실제 구현이나 구글 계약 조건이 이 데이터 흐름과 다르면 운영 전에 다시 판단한다.

계정 삭제 요청이 완료되면 서버의 인증 제공자, `sub`, 내부 계정 식별자와 동의 이력을 지체 없이 파기한다. 다른 법령에 따른 보존 근거가 확인된 항목만 해당 기간 동안 다른 정보와 분리해 보관한다.

외부 STT와 LLM 업체는 확정되지 않았다. 도입 전 업체명, 국가, 처리 목적, 항목, 보유기간, 자체 학습 여부와 국외 이전 근거를 문서화한다.

## 열린 쟁점

- 서버에서 관리할 데이터별 목적, 항목, 접근 권한, 보관 기간과 삭제 조건 및 동의 문구 반영
- 피보호자 본인의 녹음 동의 방법
- 의사결정 능력이 부족한 피보호자의 동의 처리
- 보호자 동의만으로 가능한 범위
- 요양시설의 녹음 허가 필요 여부
- 제3자의 목소리가 함께 녹음된 경우
- 음성과 화자 특징의 개인정보 해당 여부
- 피보호자 세부 정보 입력(B-3 ~ B-6)의 음성 전사(이슈 #138)에 가입 때 받은 음성 처리 동의가 해당하는지. 확인 주체는 PM이며 실제 사용자 음성으로 쓰기 전에 확인한다. 앱 구현과 테스트는 합성 음성으로만 진행했다
- 마스킹한 전사문의 가명정보 해당 여부
- 서버의 일시 처리와 외부 LLM 전달에 따른 의무
- 국외 이전과 처리위탁 여부
- 실제 구글 로그인 구현이 요청하는 OAuth 범위와 반환 항목
- 이메일과 이름을 저장하지 않는 PM 제안의 구현 영향과 추가 항목 필요성
- 계정 삭제 시 서버 데이터와 단말 세션의 실제 삭제 절차. DB 백업은 14일 보관 뒤 지우지만([배포 DB 백업 보관](#배포-db-백업-보관)), 그 기간 동안 백업에 남는 탈퇴 계정 자료의 안내와 복원 때 탈퇴를 다시 적용하는 절차는 남아 있다
- 보관 기간, 삭제 절차와 삭제 증명
- 사진 보관과 AI 분석은 가입 시 별도 선택 동의로 받고 기존 계정 동의 이력에 저장하기로 결정됨. 남은 작업은 두 항목의 필드와 API, 가입 및 미동의자의 기능 사용 화면 연결, 분석하지 않는 사진의 상태, 철회와 삭제 API 및 S3 삭제 대기열 실행
- 평가와 연구 목적의 데이터 재사용 가능 범위
- 진단과 치료 효과를 암시하는 표현의 위험
- 사진, 음악과 외부 자료의 저작권
- 스토리북을 피보호자에게 직접 제공할 때 필요한 동의와 안전 조치
- 스토리북을 실물 앨범으로 판매할 때 필요한 권리, 거래와 환불 조건

## 변경 기록 형식

법률과 개인정보 결정에는 다음 정보를 기록한다.

- 결정 번호와 날짜
- 상태: 검토 중, 확정, 폐기, 외부 확인 필요
- 데이터 항목과 처리 목적
- 저장 위치, 전송 대상과 보관 기간
- 삭제 방법과 접근 가능자
- 확인한 출처와 확인일
- 결정자와 재검토 조건

개인정보 이동 경로가 바뀌는 PR은 이 문서와 관련 ADR을 함께 갱신한다.
