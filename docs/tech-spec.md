# 새록 테크스펙

상태: 개발 중, 미결 항목 포함 | 갱신: 2026-09-15
문서 책임: 김영석, 이예은 | 기술 검토: 이서형, 김민혁, 이문영 | QA: 성채원, AI 평가 협력: 이문영, 이인성

이 문서는 구현 목표와 검증 기준을 설명한다. 아래의 ‘확정’은 제품 또는 설계 결정이며 구현 완료를 뜻하지 않는다. 현재 구현은 [루트 README](../README.md), 상세 문서의 위치는 [문서 안내](README.md)에서 확인한다.

## 배경

새록은 면회에서 안부 다음에 꺼낼 이야기가 부족한 보호자에게, 확인된 생애 정보와 이전 면회 반응을 활용한 대화 소재를 제안한다. 경도인지장애부터 경도 치매 단계의 부모를 면회하는 보호자를 초기 대상으로 하며, 대화가 어려워진 부모와 성인 자녀로 대상을 넓힐지는 미정이다.

1차 사용자는 보호자다. 환자의 기억 회복, 진단이나 치료 효과를 약속하지 않는다. 상세 대상과 비범위는 [PM 제품 기준](pm/README.md)을 따른다.

## 목표

프로필 설정부터 대화 카드, 면회, 보호자 평가, 리포트, 확인된 이야기 축적과 다음 추천까지 Android 앱에서 연결한다. 맞춤 카드의 선택, 기록 활용, 실제 면회 환경의 음성 처리, 관찰값과 보호자 평가의 일치, 재사용 여부로 유용성을 검증한다.

| 성공 지표 초안 | 정의 | 정할 내용 |
| --- | --- | --- |
| 2회차 이상 재사용률 | 첫 회차 사용자가 다음 면회에도 카드를 생성한 비율 | 측정식과 표본 |
| 카드 사용률 | 제공한 카드 중 실제 면회에서 사용한 비율 | 카드 수와 집계 기준 |
| 맞춤 카드 선택률 | 출처를 가린 비교에서 기록 반영 카드를 선택한 비율 | 비교 실험 설계 |
| 준비 부담 변화 | 대화 준비 부담의 사용 전후 변화 | 문항과 척도 |
| 관찰값 일치도 | 자동 관찰값과 보호자 평가가 같은 방향인 정도 | 비교 방식 |

발화량은 대화 품질 점수가 아닌 보조 관찰값이다. 수치 목표는 아직 확정하지 않았다.

## 아키텍처 설계

목표 흐름과 실행 위치는 [아키텍처 기준](architecture/README.md)에 모았다. MVP의 STT와 VLM은 온프레미스 GPU 1대에서 처리하고 데이터 관리도 서버 중심으로 전환한다. 장비 사양, 설치 장소, 운영 방식, 모델, API와 세부 저장 계약은 미정이며 서버 연결이 구현됐다는 뜻은 아니다.

[ADR-006](architecture/decisions/ADR-006-server-side-ai-processing.md)이 실행 위치와 데이터 관리 방향의 결정 근거다. 원본 임시 보관 제한은 NFR-002를 유지하며 카드와 리포트 생성 모델은 별도로 검증한다.

## 데이터 모델

필드, enum, 시간 단위와 JSON 예시는 [공통 데이터 계약](architecture/data-contracts.md)에만 작성한다. [합성 목 데이터](architecture/mock/README.md)는 화면 검증용이다.

카드 생성 요청, STT 구간별 결과와 주제 갱신 방식은 미정이다. 이야기 블록은 제품 요구사항에 있으나 독립된 저장 객체 계약은 아직 없다. 카드 수와 선택 방식은 현행 계약의 12장 및 9+3 구성과 PM 미결 목록이 달라 확정 여부를 확인해야 한다. 이미지 태그 구조는 비교 실험 후 출력 형식이 정해지면 함께 갱신한다.

## 인터페이스 명세

아래 표는 연동 목표이며 배포된 API 명세가 아니다. 현재 실행 API는 [BE README](../backend/README.md)에 기록한다.

| 흐름 | 입력과 결과 | 반드시 구분할 실패 |
| --- | --- | --- |
| 프로필 | 기본 정보, 취향, 생애 사실 → 저장 결과와 버전 | 필수값 누락, 저장 실패 |
| 이미지 | 동의와 사진 → 분석 후보 | 동의 없음, 실패, 식별 위험 |
| 카드 | CardGenerationRequest → 카드와 근거 | 정보 부족, 안전 필터, 모델 실패 |
| 녹음 | VisitSession과 동의 → 녹음 및 처리 상태 | 권한 거부, 동의 없음, 공간 부족 |
| 음성 | 녹음과 설정 → SpeechAnalysisResult | STT 실패, 화자 불확실, 타임아웃 |
| 리포트 | 분석과 보호자 평가 → VisitReport | 관찰값 부족, 신뢰도 부족 |
| 평가 | CaregiverEvaluation → 제출 및 승인 결과 | 회차 불일치, 중복 제출 |
| 이야기 | 승인 후보 → 이야기 블록과 변경 제안 | 승인 없음, 출처 누락, 버전 충돌 |

실제 연동 전에 카드 수와 선택 상태, 녹음 저장과 복구, STT 중간/최종 및 화자 상태, 관찰값 계산 조건, 승인과 되돌리기, 타임아웃과 재시도 상한 및 사용자 메시지를 공동 검토한다. 저장 경계는 [이슈 18](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/issues/18), STT 결과는 [이슈 24](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/issues/24)에서 다룬다.

웹 검색, 날짜/계절/날씨 활용, 사용자 설정 범위, 스토리북 직접 제공과 실물 판매, iOS 시점은 후속 검토다. 미정 사항은 담당자가 정하기 전 구현으로 확정하지 않는다. 구체적인 담당과 기한은 작업 이슈에서 관리한다.

## 시나리오

정상 흐름은 프로필 입력과 사진 후보 확인 → 카드 확인 → 동의 및 권한 확인과 면회 녹음 → 음성 처리와 보호자 평가 → 리포트와 변경 제안 확인 → 승인된 사실 및 반응 반영 → 다음 추천이다. 현재 목 계약에서 보호자 평가는 리포트 생성의 입력이다.

대화가 이어지면 기존 주제인지 새 주제인지와 관계없이 기록하며 개입하지 않는다. 주제가 바뀐 뒤 대화가 멈추면 추가 지원을 검토한다. 부적절한 카드는 보호자가 대체할 수 있다.

음성 처리에 실패하거나 신뢰도가 낮으면 이유를 표시하고 계산 불가능한 발화량, 지연 등 수치는 비워 둔다. 보호자가 사용 카드와 반응을 직접 입력하며, 잘못된 자동 값은 다음 회차에 반영하지 않는다. 승인, 거절과 반복 흐름은 [구조도](architecture/README.md#목표-사용자-흐름)를 참고한다.

## 트레이드오프

Android 우선 Flutter와 앱 식별자는 ADR-002, 상태 관리와 라우팅은 ADR-005, 동의와 원본 임시 처리는 ADR-001, STT와 VLM 실행 위치는 ADR-006을 따른다. [ADR 목록](architecture/decisions/README.md)에서 선택 이유와 이전 대안을 확인한다.

남은 비교는 서버 모델의 품질/지연/메모리, 화자 전환 탐지와 신원 식별 범위, 카드 및 리포트 생성 모델의 품질/비용이다. 온디바이스는 현재 MVP 범위에서 제외됐다.

## 릴리즈

| 검증되지 않은 외부 AI | 처리 조건과 비용 미정, 문서화와 검토 후 도입 |
