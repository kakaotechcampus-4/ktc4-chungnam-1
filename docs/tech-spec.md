상태: 최종 제출본, 실제 구현 기준 | 갱신: 2026-11-11, [처음 설계와 바뀐 점](#처음-설계와-바뀐-점) 추가 | 이전 갱신: 2026-11-10, 결정 상태에 현재 구현 표기 추가 | 이전 갱신: 2026-10-14, 녹음 동의 확인 시점 정리, 사진 보관과 AI 분석의 가입 시 선택 동의 및 계정별 저장 결정
문서 책임: 김영석, 이예은 | 기술 검토: 이서형, 김민혁, 이문영 | QA: 성채원, AI 평가 협력: 이문영, 이인성

이 문서는 구현 목표와 검증 기준을 설명한다. 아래의 ‘확정’은 제품 또는 설계 결정이며 구현 완료를 뜻하지 않는다. 결정 상태 열의 ‘현재 구현’은 2026-11-10 develop `83695093` 기준이다. 운영 서버의 BE도 11/10 01:41 KST 승인 배포([Deploy run 42656825849](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/actions/runs/42656825849))로 올린 같은 커밋이며, 11/9 배포(develop `59190ba7`) 뒤 병합된 #293(처리방침과 엘리스 ML API 문서)과 #295(이야기 후보 AI 분류와 아픈 기억 표시, 리포트 화제별 단락, 카드 2판)가 이 배포로 들어갔다. 운영 `.env`에 `SAEROK_CARD_GENERATION_PROMPT_VERSION`을 두지 않아 코드 기본값 2가 적용되므로 운영 카드도 2판이다. 그 전 11/9 승인 배포([Deploy run 42568179490](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/actions/runs/42568179490))에는 11/8 배포(develop `9c2b8276`) 뒤 병합된 #275, #277~#291이 들어갔다([API 명세](architecture/api-spec.md#api-목록)). STT 서버는 BE 배포 대상이 아니다(FR-007). 앱의 현재 구현도 develop 기준이며, Play 앱은 프로덕션 첫 게시를 검토 중이라(11/8) 이전 빌드가 남아 있고 최근 앱 수정이 들어 있지 않다([루트 README](../README.md)). GitHub Releases의 APK도 11/8 18:31 KST에 게시한 빌드라 그 뒤 병합된 앱 수정(#270~#272, #295의 일대기 분류 고르기, 녹음 파일 공유, 아픈 기억 표시)이 없다. #295의 앱 수정은 서버 배포와 별개로 새 APK를 빌드해야 휴대폰에 들어간다. 현재 구현은 [루트 README](../README.md), 상세 문서의 위치는 [문서 안내](README.md)에서 확인한다.

## 배경

새록은 면회에서 안부 다음에 꺼낼 이야기가 부족한 보호자에게, 확인된 생애 정보와 이전 면회 반응을 활용한 대화 소재를 제안한다. 경도인지장애부터 경도 치매 단계의 부모를 면회하는 보호자를 초기 대상으로 하며, 대화가 어려워진 부모와 성인 자녀로 대상을 넓힐지는 미정이다.

1차 사용자는 보호자다. 환자의 기억 회복, 진단이나 치료 효과를 약속하지 않는다. 상세 대상과 비범위는 [PM 제품 기준](pm/README.md)을 따른다.

## 목표

프로필 설정부터 대화 카드, 면회, 보호자 평가, 리포트, 확인된 이야기 축적과 다음 추천까지 Android 앱에서 연결한다. 맞춤 카드의 선택, 기록 활용, 실제 면회 환경의 음성 처리, 관찰값과 보호자 평가의 일치, 재사용 여부로 유용성을 검증한다.

| 성공 지표 초안 | 정의 | 정할 내용 |
| --- | --- | --- |
| 2회차 이상 재사용률 | 첫 회차 사용자가 다음 면회에도 카드를 생성한 비율 | 측정식과 표본 |
| 카드 사용률 | 제공한 카드 중 실제 면회에서 사용한 비율 | 선택용과 보충용 카드를 포함하는 집계 범위와 기준 |
| 맞춤 카드 선택률 | 출처를 가린 비교에서 기록 반영 카드를 선택한 비율 | 비교 실험 설계 |
| 준비 부담 변화 | 대화 준비 부담의 사용 전후 변화 | 문항과 척도 |
| 관찰값 일치도 | 자동 관찰값과 보호자 평가가 같은 방향인 정도 | 비교 방식 |

발화량은 대화 품질 점수가 아닌 보조 관찰값이다. 수치 목표는 아직 확정하지 않았다.

## 아키텍처 설계

목표 흐름과 실행 위치는 [아키텍처 기준](architecture/README.md)에 모았다. STT는 Tailscale 사설망으로 연결하는 개인 GPU 서버, 사진 설명과 카드 및 리포트 생성은 ML API를 활용하는 방향이다. 기존 온프레미스 일괄 처리 기록과 후속 방향은 [ADR-006](architecture/decisions/ADR-006-server-side-ai-processing.md#현재-적용할-방향-2026-10-11-정정)에 구분한다. 현재 STT 연결은 ADR-006의 2026-10-31 보완을 따른다. 처리 성능은 실측 후 판단한다. 현재 구현은 STT를 HTTP로, 카드와 리포트 및 사진 설명 생성을 BE worker의 함수 호출로 연결한다. 실제 사용자 자료 전송 승인을 이 문서로 확정하지 않는다.

[ADR-006](architecture/decisions/ADR-006-server-side-ai-processing.md)이 실행 위치와 데이터 관리 방향의 결정 근거다. 원본 임시 보관 제한은 NFR-002를 유지하며 카드와 리포트 생성 모델은 별도로 검증한다.

## 데이터 모델

필드, enum, 시간 단위와 JSON 예시는 [공통 데이터 계약](architecture/data-contracts.md)에만 작성한다. [합성 목 데이터](architecture/mock/README.md)는 화면 검증용이다.

카드 생성 입력과 응답, STT 구간별 결과는 공통 데이터 계약과 API 명세를 따른다. 주제 피드백을 추천에 반영하는 계산은 별도 검토한다. 카드 구성은 12장, 선택용 9장과 보충용 3장을 유지하고 각 카드에 첫 질문 1개와 꼬리 질문 3개를 둔다. 사용할 카드는 보호자가 고른다.

사진 출력은 `description`을 사용하고 메타데이터는 AI 분석과 주제 추천 입력에서 제외한다. 별도 내용 승인 없이 카드 입력에 사용하며 앨범에서 선택적으로 수정한다. 과거 태그 비교 실험을 현재 출력 형식의 미결 사항으로 남기지 않는다.

승인된 이야기는 `LifeFact`로 다루며 일대기에서 직접 수정한다. 거절 후보의 보관과 복구는 [주제 카드 설계](architecture/card-generation-flow.md#이야기-후보의-승인-거절과-복구)를 따른다. 이 정리는 새 JSON 필드나 승인 취소 API를 추가하지 않는다.

아래 표는 연동 목표다. 현재 구현된 API는 [API 명세](architecture/api-spec.md)와 [BE README](../backend/README.md)에 기록한다.

## 시나리오

정상 흐름은 가입 동의(필수 2개와 선택 4개) → 피보호자 최초 등록 전 동의 및 대리 권한 확인 → 프로필 입력과 선택적 사진 첨부 → 주제 카드 생성과 선택 → 마이크 권한 확인과 면회 녹음 → 보호자 소감 저장 → 녹음 제출과 STT → 리포트와 변경 제안 확인 → 승인된 이야기 및 주제 선택 반영 → 다음 추천이다. 사진 보관과 AI 분석에 이미 유효하게 동의했다면 다시 묻지 않는다. 미동의, 철회 또는 기록 없는 계정이 해당 기능을 사용하려고 할 때만 필요한 동의를 받는다. 휴대폰 사진 선택과 카메라 및 마이크 접근은 기능 사용 시 처리한다. 매회 녹음 전 같은 동의 체크박스를 다시 받지 않으며 휴대폰 권한은 개인정보 처리 동의를 대신하지 않는다. 피보호자별 확인 방법과 기록은 후속 설계다. 사진 설명은 별도 승인 없이 사용하며 앨범에서 원할 때 수정한다. 리포트 생성에는 전사와 소감이 모두 필요하다.

현재 구현 (2026-11-09 기준): 가입 동의의 선택 항목은 서비스 개선, 알림, AI 사진 분석 3개이고 사진 보관 동의는 없다. AI 사진 분석에 동의하지 않은 계정이 사진을 올리면 앱이 올리기 전에 동의 시트를 띄우며, 거절하거나 닫으면 분석 없이 올린다(거절하면 앱이 켜져 있는 동안 다시 묻지 않고, 다시 띄우지 않기를 고르면 그 기기에서 그 계정에는 묻지 않는다)([PR #272](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/pull/272)). 선택 동의는 설정의 계정 약관 동의 화면에서 바꾼다([PR #271](https://github.com/kakaotechcampus-4/ktc4-chungnam-1/pull/271)).

대화가 이어지면 기존 주제인지 새 주제인지와 관계없이 기록하며 개입하지 않는다. 소재가 필요하면 보호자가 미리 준비한 꼬리 질문이나 다른 카드를 선택한다. 부적절한 카드는 보호자가 대체할 수 있다. 면회 중 실시간으로 새 질문을 생성하지 않는다.

음성 처리에 실패하거나 신뢰도가 낮으면 이유를 표시하고 계산 불가능한 발화량, 지연 등 수치는 비워 둔다. 보호자가 사용 카드와 반응을 직접 입력하며, 잘못된 자동 값은 다음 회차에 반영하지 않는다. 승인, 거절과 반복 흐름은 [구조도](architecture/README.md#목표-사용자-흐름)를 참고한다.

## 트레이드오프

Android 우선 Flutter와 앱 식별자는 ADR-009, 상태 관리와 라우팅은 ADR-005, 동의와 원본 임시 처리는 ADR-001, STT와 VLM 실행 위치는 ADR-006을 따른다. [ADR 목록](architecture/decisions/README.md)에서 선택 이유와 이전 대안을 확인한다.

남은 비교는 서버 모델의 품질/지연/메모리, 화자 전환 탐지와 신원 식별 범위, 카드 및 리포트 생성 모델의 품질/비용이다. 온디바이스는 현재 MVP 범위에서 제외됐다.

## 테스트 전략

| 영역 | 최소 검증 |

| 평가 | 부분 동의, 거절, 중복 제출과 승인 전 미반영 |
