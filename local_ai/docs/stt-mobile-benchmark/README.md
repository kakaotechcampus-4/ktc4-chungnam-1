# 모바일 STT 벤치마크

Whisper Small과 Tiny를 Android 단말(갤럭시 S21)에서 실행한 KCSC 한국어 음성 전사 실험이다. 





## 1. Small을 모바일에서 시험한 맥락

Mac에서 `whisper.cpp`로 후보 모델을 비교할 때 속도보다 CER을 우선해 Small을 초기 후보로 골랐다. 당시 시험에서는 Small의 CER이 제일 좋게 나왔다.

| 모델 | 장치 | CER ↓ | WER ↓ | RTF ↓ | 실시간 대비 전사 속도 |
| --- | --- | --- | --- | --- | --- |
| tiny Q5_1 | CPU | 25.2% | 47.8% | 0.031 | 32.3배 빠름 |
| tiny Q8_0 | CPU | 23.4% | 44.8% | 0.028 | 35.7배 빠름 |
| base Q5_1 | CPU | 19.3% | 37.8% | 0.066 | 15.2배 빠름 |
| base Q8_0 | CPU | 19.7% | 36.5% | 0.062 | 16.1배 빠름 |
| small Q5_1 | CPU | 12.0% | 27.5% | 0.197 | 5.08배 빠름 |
| **small Q8_0** | **CPU** | **11.6%** | **27.9%** | **0.201** | **4.98배 빠름** |
| medium Q5_0 | CPU | 19.7% | 34.4% | 0.525 | 1.90배 빠름 |
| medium Q8_0 | CPU | 16.8% | 31.4% | 0.519 | 1.93배 빠름 |

이후 Small과 더 작은 Tiny를 실제 Android 단말에서 실행했다. 속도는 런타임·하드웨어 최적화 여지를 보되, 전사 품질을 먼저 확보하려는 선택이었다. 

## 2. 실험 조건과 읽는 방법

KCSC는 [MagicHub의 한국어 대화 음성 자료](https://huggingface.co/datasets/MagicHub/korean-conversational-speech-corpus) 별도의 노이즈가 없는 음성 데이터이며 독립된 화자의 발화가 담겨있다.

| 지표 | 뜻 | 읽는 방법 |
| --- | --- | --- |
| CER | 문자 오류율 = (삽입 + 삭제 + 치환 오류 수) / 정답 문자 수 | 낮을수록 좋다. 0.18은 정답 100문자당 편집 오류 약 18개라는 뜻이다. 문장 100개 중 18개가 틀렸다는 뜻은 아니다. |
| WER | 단어 오류율 = 단어 단위 편집 오류 수 / 정답 단어 수 | 보조 지표다. 띄어쓰기 등 평가 방식의 영향을 받는다. |
| RTF | 전사 시간 / 음성 길이 | 낮을수록 빠르다. 1 미만이면 음성 길이보다 짧은 시간에 전사한다. |

전체 CER·WER는 샘플별 비율의 단순 평균이 아니라 오류 수 합계 / 정답 단위 수 합계(micro)다. RTF도 전체 전사 시간 / 전체 음성 길이로 계산했다. CER은 정규화된 문자열의 오류 개수로 계산한 기존 측정값이다. 정규화·채점 코드는 이 폴더에 없다.

## 3. 측정 결과

### 전체 기록

| 모델 | 처리 완료 | CER | WER | RTF | 1시간 음성 전사 시간 환산 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Small | 15/15 | 0.181094 (18.11%) | 0.365843 | 0.7205 | 약 43.2분 |
| Tiny | 22/22 | 0.361320 (36.13%) | 0.539528 | 0.2138 | 약 12.8분 |

Small 모델의 경우 S21 기기에서 CER 18%로 100 글자 중 18개의 글자가 오류가 날 수 있다고 해석되고, 
RTF 0.7은 1시간 길이의 음성 녹음을 처리하는데 약 43분이 걸린다고 해석된다. 



## 4. 결과 해석과 서버 전환 근거

**전사 품질:** Small의 CER 18.11%를 초기 서비스 후보로 검토할 만한 수준이라 판단. 추후 1차 전사된 텍스트 결과물을 보정하는 파이프라인을 거쳐 CER 개선할 여지가 있음 

**속도:** Small의 RTF 0.7205는 음성 길이보다 빠른 처리지만, 녹음이 끝난 뒤 전사를 시작하면 1시간 음성 기준 약 43.2분, 15분 음성 기준 약 10.8분을 더 기다리는 수준이다. 담당자는 실제 사용 시 이 대기 시간이 길다고 느꼈다. RTF 1 미만이라는 사실만으로 면회 직후 결과를 제공하기에 충분히 빠르다고 판단하기는 어렵다.

**잡음 녹음에서의 품질:** 별도로 제공받은 잡음이 있는 녹음을 Small로 실행했을 때 전사 품질이 만족스럽지 않았고, 더 큰 모델에서는 눈으로 확인한 결과가 더 나았다는 담당자 관찰이 있다. 해당 비교의 CER, 잡음 수준과 상세 실행 조건은 측정·기록되지 않았으므로 정량 벤치마크 표에는 포함하지 않는다. 
- 해당 테스트 녹음본은 팀 디스코드 채널에만 공유되어있다. 


**On Device vs On Premise 판단:** Small에서도 확인된 대기 시간과 잡음 환경의 품질 우려를 함께 보면, 더 큰 모델을 GPU 서버에서 검증하는 방향이 타당하다고 판단했다. 대형 모델의 단말 처리 시간과 자원 부담을 우려해 온디바이스를 기본안으로 삼기 어렵기 때문이다.

## 테스트 데이터 출처와 재현 방법

테스트 데이터 출처는 [MagicHub KCSC](https://huggingface.co/datasets/MagicHub/korean-conversational-speech-corpus)이다. 이 데이터는 개인·비상업적 이용과 허가 없는 재배포 금지를 명시하므로, KCSC 음성 데이터는 별도로 레포에 올리지 않고 이 데이터들을 다운 받을 수 있는 다운로드 [스크립트](./data-downloader-kcsc.py)만 제공한다.

- 다운로드 도구는 음성과 정답 자료를 준비한다.
- 이 폴더에서는 모바일 STT 벤치마크를 재현할 수 없다. 별도로 벤치마크를 위해 제작한 flutter 앱 레포에서 재현해볼 수 있다.
