# [리포트] 새록 사진 키워드(이미지 태깅) 모델 후보 선정: 모바일 온디바이스 vs 온프레미스 서버

> **문서 목적**: 간병인이나 면회 온 가족들에게 대화거리를 추천해주는 서비스 "새록"의 사진 기반 키워드(이미지 태깅) 기능 구현을 위한 **모바일 온디바이스(Mobile On-device)** 및 **온프레미스 서버(On-premise Server)** 후보 모델 실측 평가 및 정보 공유  
> **평가 관점**: **"대화 소재로 직접 고를 만한 유의미한 키워드(태그 3~5개)가 나오는가"**  
> **테스트 배경 및 모델 분류 기준**:  
> - **출발점**: 본 테스트는 모바일 단말(실제 스마트폰 갤럭시 S21 등에서 가용 RAM을 확인했을 때 여유분이 약 1.x GB 내외에 불과한 점 감안)에서 로컬로 직접 돌릴 수 있는 이미지 태깅 모델을 선정하는 것에서 출발함.  
> - **임의 분류 경계선 (3B vs 4B+)**: 현실적으로 모바일에서 올려볼 수 있는 한계선인 **3B 이하를 '모바일 온디바이스 후보'**로 묶고, 모바일 구동이 어렵다고 판단되는 **4B 이상 모델은 '온프레미스 서버 후보'로 임의 분류**하여 비교를 진행함. (실제 모바일 벤치마크 측정은 RAM 여유가 있는 갤럭시 탭 S9+에서 수행함.)  
> - **실측 결과 및 하드웨어 환경 관점**: 3B 이하 모델은 태깅 품질이 완전히 붕괴되어 실사용이 불가능했으며, 최소 4B 이상이어야 유의미한 키워드가 나온다는 점을 확인함. 향후 정식 서버 인프라가 갖춰지면 인프라 수준에 따라 추론 지연과 메모리 제약이 해소되므로 9B 및 27B 등 대형 모델로 확장하는 것이 서비스 품질상 훨씬 유리함.

## 1. 핵심 결론

### 1) 모바일 온디바이스: 배제 강력 권고 (품질 붕괴, 지연 및 RAM 한계)
- **태깅 품질 전면 붕괴**: 3B 이하 모델 전반에서 정상 동작하는 모델이 전무함. 사진 시각 정보를 거의 읽지 못하고 프롬프트 예시어(`연탄불, 재봉틀...`)를 그대로 읊거나 동일 단어를 5회 연속 반복(`한류`×5 등)하여 대화 소재로 활용 불가.
- **언어 오염 및 런타임 크래시**: 그나마 시각 정보를 일부 읽은 `qwen2.5-vl-3b`조차 중국어 간체자를 14회나 쏟아냈고, `smolvlm-2.2b`와 `paligemma-3b`는 모바일 런타임에서 크래시 발생.
- **가용 RAM 한계 및 OOM 위험**: 일반 스마트폰의 실가용 RAM(약 1.x GB) 대비 2B~3B 모델의 RAM 점유(1.8GB~3.1GB)가 초과되어 상용 폰에서 OOM Killer(`SIGKILL`) 강제 종료 위험이 상존함. 1GB 미만 모델은 지능 수준이 완전히 붕괴됨.
- **다장(Multi-image) 처리 시 지연시간 누적**: 실제 사용 시 사진을 여러 장 넣는 시나리오에서 온디바이스 추론 시 장당 15~25초 이상 소요됨. 3~5장만 일괄 처리해도 수 분이 걸릴 것임.
- **최종 판정**: **현재 단계에서는 이미지 태깅에서 모바일 온디바이스를 웬만해서는 배제하는 방향으로.** 네트워크 완전 단절 등 온디바이스를 무조건 고수해야만 하는 특수한 제약이 있는 경우에 한해서만, 추후 '경량 비전/OCR + 모바일 SLM' 2-Stage 구조 정도를 차선책으로 검토해 볼 수 있는 수준.

### 2) 온프레미스 서버: 현 CPU 환경 1순위 `qwen3.5-4b` / 최종 지향 `qwen3.5-9b` (GPU 서버)
- **현 노트북 CPU 환경 기준 1순위 (`qwen3.5-4b`)**:
  - 현재 평가 환경인 로컬 워크스테이션(노트북 CPU) 기준, 별도 외장 GPU 없이도 20초 내외(21.7s)로 가볍게 기동 가능하며 시각 디테일과 예시어 복창 최소화(1회)를 가장 균형 있게 달성함.
- **최고 품질 후보 `qwen3.5-9b` 및 상대적 대형 모델(9B / 27B+) 관점**:
  - **태깅 품질 및 어휘 완성도**: 어휘의 구체성과 사진 맥락 묘사력(김치 축제, 자갈치 시장 등) 자체는 `qwen3.5-9b`가 비교군 중 가장 뛰어남. (결과물 상 유일한 단점은 17장 중 2건에서 발생한 프롬프트 예시어 복창 정도)
  - **CPU 테스트베드 한계 vs 향후 GPU 서버 확장**: 본 벤치마크의 36.4초 지연시간은 노트북 CPU 구동에 따른 환경적 한계이며, 향후 전용 GPU 서버가 갖춰지면 추론 시간(1~2초 내외)과 메모리 문제가 완화되므로, 9B 및 27B급 이상 대형 모델을 최우선 도입하는 것이 서비스 품질 고도화에 적합함.
- **대안 모델 (`gemma-3-4b`)**:
  - 예시어 복창 0회, 단어 반복 0회로 형식을 가장 엄격히 준수하나, 일상 사진을 군사 테마로 해석하는 도메인 편향이 관찰되어 백업 후보로 유지.

## 2. 벤치마크 환경 및 평가 기준

### 2.1 배포 환경 정의 및 하드웨어 스펙
다음 하드웨어에서 임의 분류한(3b까지 온디바스 모델 후보로 임의 분류 / 4b 이상 온프레미스 서버용 모델 후보로 임의 분류)모델들을 테스트 실시함.

- **모바일 온디바이스 (Mobile On-device)**: Galaxy Tab S9+ (SM-X810)
  - AP / OS: Qualcomm Snapdragon 8 Gen 2 / Android ARM64
  - 시스템 메모리 (RAM): 12 GB LPDDR5X (부팅 후 기저 실가용 RAM 약 5,715 MB)
  - 엔진: `llama.cpp` Android 네이티브 빌드 (`llama-mtmd-cli`)
  - 특징 및 모바일 메모리 제약:
    - 외부 네트워크 연결 없이 단말기 로컬 NPU/CPU로 추론 수행.
    - 초기 타깃이었던 일반 스마트폰(Galaxy S21 등, 8GB RAM 탑재 모델)은 OS 및 상주 서비스 점유로 인해 실제 사용 가능한 여유 메모리가 **약 1.x GB**에 불과하여, 1.5GB 이상의 VLM 로드 시 즉각 OOM Killer(`SIGKILL`)로 강제 종료될 위험이 매우 큼.
    - 따라서 3B급 모델의 동작 가능 여부와 태깅 품질을 검증하기 위해 여유 메모리가 확보된 Galaxy Tab S9+로 테스트함.
- **온프레미스 서버 (On-premise Server)**: 노트북
  - CPU / OS: Intel Core i5-13500H (12코어 16스레드) / Linux x86_64
  - 시스템 메모리 (RAM): 32 GB DDR5 4800MHz (실 가용 RAM 약 21 GB 이상)
  - 엔진: `llama.cpp` x86_64 빌드 (`llama-mtmd-cli`)
  - 4b이상 모델 테스트용.

> **공정 측정 조건**:
> - **기기 쿨다운**: 모델 간 실행 순서에 따른 발열 누적 및 쓰로틀링(클럭 다운) 왜곡을 방지하기 위해, 태블릿(표면 온도 34°C 이하)과 노트북(CPU 패키지 온도 65°C 이하)의 온도 센서 정보를 실시간으로 받아 해당 기준 온도 수준까지 냉각시킨 후 동일한 열 상태에서 동작시킴.
> - **순수 추론 시간(Inference Latency) 측정**: 프로세스 기동 및 모델 가중치 로드 시간을 제외한 순수 추론 시간만 분리 계측함.

### 2.2 공통 프롬프트 및 출력 규격 (JSON 스키마 제약)
모든 모델에 동일한 한글 질문(프롬프트)을 전달하고, 임의의 긴 서술형 텍스트 대신 정해진 규격의 JSON 형태로만 답하도록 엔진 단에서 출력 스키마(`schema.json`)를 강제함.

#### 1) 입력 프롬프트
```text
이 사진에서 그 시절의 일상 생활, 일거리, 도구, 음식 등 이야기 소재가 될 수 있는 구체적인 옛 추억 단어 키워드 3~5개를 JSON으로 출력해줘. (예: 연탄불, 재봉틀, 국민학교 도시락 등 일상 소재 / 사람, 건물, 풍경 같은 단순 일반명사는 제외)
```

#### 2) 출력 JSON 스키마 (`schema.json`)
`llama.cpp`의 문법 제약 옵션(`-jf`)을 통해 부가 설명이나 인사말 없이 오직 3~5개의 단어 배열(`topics`)만 출력하도록 제어함.
```json
{
  "type": "object",
  "properties": {
    "topics": {
      "type": "array",
      "items": { "type": "string" },
      "minItems": 3,
      "maxItems": 5
    }
  },
  "required": ["topics"]
}
```

> **검증 장치 (예시어 복창 탐지)**: 프롬프트 내 예시 단어(`연탄불`, `재봉틀`, `국민학교 도시락`)는 17개 평가 사진 어디에도 실제로 없는 소재로 의도적 배치함. 모델이 사진의 시각 정보를 인식하지 못하고 지시문 예시만 단순 복사할 경우 해당 단어가 그대로 노출되어 판별 기준으로 작용함.

### 2.3 참조 데이터셋 (Claude Opus 5 Description 및 Baseline)
단순 라벨 일치 채점을 넘어, 모델 출력을 다각도로 대조하기 위해 프론티어 VLM인 **Claude Opus 5** 참조 데이터 활용.
- **Claude Opus 5 Description**: 사진 17장을 직접 분석해 객체, 인물 행동, 소품, 간판 텍스트를 정밀 기술한 시각 기록.
- **Claude Opus 5 Baseline**: 동일 프롬프트로 Claude Opus 5가 추출한 대화 소재용 기준 키워드 목록.
- **평가 관점**: 프롬프트에 있는 키워드 단순 복창 여부를 거르고, **Claude Opus 5 Description에 기록된 실제 사진 속 디테일(행선판, 차력 소품, 동아줄 등)을 얼마나 잡아내는지** 대조 분석.

### 2.4 평가 지표
- **성공률 (ok / 17)**: JSON 파싱 오류나 런타임 크래시 없이 정상 완료된 비율.
- **추론 중앙값 (sec)**: 17개 이미지 순수 추론 시간의 중앙값 (실제 체감 반응속도).
- **고유 키워드 비율 (Unique Ratio)**: 단어 중복 없이 실제 선택지로 쓸 수 있는 유효 태그 개수.
- **예시어 복창 빈도 (Parrot Echo)**: 프롬프트 예시어를 그대로 뱉은 횟수.
- **언어 오염도**: 한국어 대신 중국어 간체자, 러시아어, 영문 템플릿 태그가 출력된 빈도.

## 4. 트랙별 후보 모델 심층 분석

### 4.1 트랙 1: 모바일 온디바이스(Mobile On-device) 후보 모델 분석

모바일 온디바이스 VLM은 태블릿 자체에서 오프라인 동작이 가능한 장점이 있으나, 현재 오픈소스 3B 이하 모델들의 태깅 성능은 **실서비스 적용 불가 수준**임.

1. **실패 패턴별 현황**:
   - **프롬프트 예시어 단순 복창 (Echoing)**: `qwen3.5-2b`(12/17회), `mobilevlm-3b`(10/17회), `smolvlm-500m`(9/17회). 사진의 시각 정보를 전혀 파악하지 못하고 프롬프트의 예시 단어(`연탄불, 재봉틀, 국민학교 도시락`)를 그대로 출력함.
   - **단어 무한 루프**: `qwen3.5-0.8b`는 17개 이미지 전량에서 한 단어만 5번 반복(`['한류', '한류', '한류', '한류', '한류']`, `['집', '집안', '집안', '집안']`).
   - **언어 오염**: `qwen2.5-vl-3b`는 시각 피처를 가장 잘 잡아냈으나 한국 사진을 보고 중국어 간체자(`国民学校`, `传统体育`, `传统服饰`, `传统渔村`, `建筑` 등)를 14회 출력함. `moondream-1.8b`는 영문 태그(`assistant`, `topics`)를 58회 출력함.
   - **런타임 크래시**: `smolvlm-2.2b`(토큰 디코드 -1 에러), `paligemma-3b`(Segfault)는 모바일 엔진 호환성 문제로 1장도 완주하지 못함.

2. **다장(Multi-image) 처리 시 치명적 지연 병목**:
   - 앱에서 사용자가 사진을 1장만 올리는 것이 아니라 여러 장을 일괄 업로드하는 경우, 장당 15~38초가 소요되어 3장만 처리해도 1분을 가볍게 초과함.
   - 단말 리소스 점유와 발열 쓰로틀링이 누적되어 사용자 대기 시간이 기하급수적으로 늘어남.

3. **단말 RAM 점유 한계 및 OOM Killer 강제 종료 위험**:
   - **스마트폰(S21 등) 가용 RAM 1.x GB 한계**: 3B 모델뿐 아니라 1.8B~2B급 모델(`moondream-1.8b`, `qwen3-vl-2b`, `qwen3.5-2b` 등)도 모델 가중치 파일만 1.5GB~2.0GB에 달하며, 실행 시 비전 버퍼를 포함해 최소 1.8GB~2.7GB(실측 `moondream-1.8b` 기준 2,156 MB)를 점유함. 가용 RAM이 1.x GB에 불과한 일반 스마트폰 환경에서는 프로세스 기동 즉시 OS 커널의 `ActivityManager`에 의해 OOM Killer(`SIGKILL`) 강제 종료 대상이 됨.
   - **12GB 태블릿 환경의 실측 메모리 압박**: 12GB RAM을 탑재한 Galaxy Tab S9+에서도 VLM 1회 구동 시 가용 메모리가 5,715 MB에서 3,558 MB로 2.1GB 이상 급감함. 연속 추론 시 메모리 해제 지연 및 발열 쓰로틀링이 누적됨.
   - **초경량 모델의 성능 붕괴**: 1GB 미만으로 적재 가능한 500M~0.8B 모델(`smolvlm-500m`, `qwen3.5-0.8b`)은 메모리 부담은 적으나, 태깅 품질이 완전히 붕괴되어 실사용이 불가능함.

4. **모바일 온디바이스 트랙 종합 판정**:
   - **배제 강력 권고**: 품질 붕괴와 다장 처리 지연, 메모리 고갈 위험으로 인해 **현재 온디바이스 탑재는 웬만해서는 하지 않는 방향을 강력 권고함.**
   - **불가피한 경우의 차선책 (Single VLM)**: `qwen2.5-vl-3b` (시각 인지는 유일하게 가능하나, 38.3초 지연, 3.1GB 점유, 중국어 간체자 필터링 필수).
   - **제한적 대안 구조 (2-Stage)**: 보안/네트워크 단절로 온디바이스가 무조건 강제되는 특수 상황에 한해, **모바일 경량 비전/OCR(0.1~0.5초) + 모바일 한국어 SLM(1~2초)** 파이프라인 PoC를 고려해 볼 수 있음.

> **포지셔닝 산출 공식 (3장 실측치 기반)**:
> - **X축 (추론 속도 점수)**: $X = 1.0 - \frac{\text{지연시간(초)} - 15}{120}$ (15초~135초 구간 정규화, 빠를수록 1.0에 수렴)

>    - 그러나 실제 정성 평가에서는 사진 맥락과 무관한 군사 테마(`군사도시`, `군함`, `군복`)를 출력하는 **도메인 편향(환각)**이 확인되어, 대화 소재 추천 실용성 관점에서는 Qwen 3.5 계열보다 후순위로 평가함.
> 2. **`qwen3-vl-4b`의 X축 우측 배치 주의 (Q4 탈락)**:
>    - 지연시간(20.2s)이 가장 짧아 X축 맨 우측(0.96)에 위치하나, 17장 중 7장에서 예시어를 단순 복창하여 Y축 최하위(0.17)로 떨어짐. 속도만 빠르고 품질이 불안정하여 실서비스 채택은 부적격함.
> 3. **실질적 추천 모델 (`qwen3.5-4b` & `qwen3.5-9b`)의 진짜 가치**:
>    - 수식 상 Y축(0.63, 0.77)은 중간~상위권에 분포하지만, 실제 사진 내 세부 OCR 판독(`서울역`, `광명`, `청계천`) 및 상황 맥락 묘사(`자율봉사`, `김치찌개`) 등 **정성적 시각 인지 및 대화 소재 생성 품질이 비교군 중 가장 뛰어남**.

## 6. 향후 과제: 프롬프트 고도화 방안

본 벤치마크 평가 과정에서 확인된 오류 패턴(예시어 단순 복창, 사진 맥락 무관 키워드 등)을 개선하고 대화 소재의 품질을 안정화하기 위한 2가지 프롬프트 고도화 접근 전략:

### 6.1 Zero-shot 프롬프트 고도화 (예시어 제거 및 제약 구조화)
1. **프롬프트 내 예시어 문구 전면 제거 고려**:
   - 지시문 본문에서 `(예: 연탄불, 재봉틀, 국민학교 도시락 등...)`과 같은 구체적 예시 단어를 완전히 삭제 고려..
   - 모델이 사진의 시각 정보를 인식하지 못했을 때 지시문의 예시어를 그대로 따라 출력하는 '예시어 복창(Echoing)' 현상을 차단.
2. **시각 관찰 중심의 지시문 정밀화**:
   - 예시 단어 나열 대신 "사진 속에 실제로 존재하는 사물, 인물 행동, 복장, 공간 배경"만을 시각적으로 관찰하여 구체적 명사형으로 추출하도록 지시 규칙을 엄밀히 재구성 고려.

### 6.2 Few-shot 프롬프트 도입 (어휘 톤앤매너 가이드)
1. **추억 회상 대화 소재 톤앤매너 유도**:
   - `건물`, `사람` 같은 단순·추상적 일반 명사 대신 `어물전`, `보따리`, `만원버스`처럼 실제 회상 대화 소재로 적합한 구체적 명사를 추출하도록 모범 입출력 예시를 제공 고려.
2. **텍스트 기반 상황-키워드 Few-shot ( CPU 환경)**:
   - 멀티모달 이미지 Few-shot은 예시 이미지 수만큼 비전 토큰과 연산 지연시간이 배수로 증가하여 CPU 환경에서는 병목이 큼.
   - 따라서 지연시간 증가(수십 토큰 수준)가 거의 없는 **"시각적 상황 묘사 텍스트 → 추천 키워드" 형태의 텍스트 Few-shot**을 우선 적용하여 속도 저하 없이 원하는 출력 유도를 고려..
3. **향후 GPU 환경에서의 멀티모달 Few-shot 검토**:
   - 외장 GPU 서버 인프라 확보 시, 대표 시대별 사진 1~2장을 직접 포함하는 멀티모달 Few-shot(또는 비전 토큰 프롬프트 캐싱) 고려.
