# [리포트] 새록 사진 키워드(이미지 태깅) 모델 후보 선정: 모바일 온디바이스 vs 온프레미스 서버

상태: 초기 후보 평가 기록. 아래 권고는 당시 측정 범위의 판단이다. 현재 STT와 VLM은 [온프레미스 GPU 1대 처리](../../../docs/architecture/decisions/ADR-006-server-side-ai-processing.md)로 확정됐으며, 최종 모델과 출력 형식은 비교 중이다.

> **문서 목적**: 간병인이나 면회 온 가족들에게 대화거리를 추천해주는 서비스 "새록"의 사진 기반 키워드(이미지 태깅) 기능 구현을 위한 **모바일 온디바이스(Mobile On-device)** 및 **온프레미스 서버(On-premise Server)** 후보 모델 실측 평가 및 정보 공유
> **평가 관점**: **"대화 소재로 직접 고를 만한 유의미한 키워드(태그 3~5개)가 나오는가"**
> **테스트 배경 및 모델 분류 기준**:
> - **출발점**: 본 테스트는 모바일 단말(실제 스마트폰 갤럭시 S21 등에서 가용 RAM을 확인했을 때 여유분이 약 1.x GB 내외에 불과한 점 감안)에서 로컬로 직접 돌릴 수 있는 이미지 태깅 모델을 선정하는 것에서 출발함.
> - **임의 분류 경계선 (3B vs 4B+)**: 현실적으로 모바일에서 올려볼 수 있는 한계선인 **3B 이하를 '모바일 온디바이스 후보'**로 묶고, 모바일 구동이 어렵다고 판단되는 **4B 이상 모델은 '온프레미스 서버 후보'로 임의 분류**하여 비교를 진행함. (실제 모바일 벤치마크 측정은 RAM 여유가 있는 갤럭시 탭 S9+에서 수행함.)
> - **실측 결과 및 하드웨어 환경 관점**: **이번에 시험한 3B 이하 후보 10종과 아래 프롬프트·양자화 설정에서는** 태깅 품질이 붕괴되어 서비스에 필요한 품질을 확보하지 못했고, 같은 조건에서 4B 이상 후보부터 유의미한 키워드가 나왔음. (3B 이하 모델 체급 전체의 한계로 일반화한 결론은 아니며, 다른 모델·프롬프트·양자화 조합에서는 결과가 달라질 수 있음.) 향후 정식 서버 인프라가 갖춰지면 인프라 수준에 따라 추론 지연과 메모리 제약이 해소되므로 9B 및 27B 등 대형 모델로 확장하는 것이 서비스 품질상 훨씬 유리함.

> **후속 비교**: 동일한 공개 이미지 17장과 같은 키워드 프롬프트로 Claude Haiku 4.5 low와 GPT-5.6 Luna low를 비교한 결과는 [Haiku 4.5와 Luna low 비교 보고서](haiku-luna-low-benchmark.md)에서 확인할 수 있다. 이 후속 실험은 구독형 CLI에서 실행했으므로 기존 로컬 모델 벤치마크와 실행 환경 및 토큰 문맥이 다르다.

## 1. 핵심 결론

> **전제 및 범위 (본 문서의 성격)**
> - 본 문서는 **후보 모델 평가 리포트**이며 최종 모델과 출력 형식을 확정하는 문서가 아님. 이후 팀은 [ADR-006](../../../docs/architecture/decisions/ADR-006-server-side-ai-processing.md)에서 MVP의 온프레미스 GPU 1대 처리를 확정했다. 키워드 태깅, description과 두 방식의 결합은 추가 비교 후 정한다.
> - **서버 방식을 채택하면 사진이 단말 밖으로 전송됨.** 이 경우 기존에 정해진 동의·암호화·삭제 조건을 그대로 따름: 이미지 분석 기능 이용 시 별도 동의 확인, 전송 및 저장 암호화, 처리 완료 후 즉시 삭제(어떤 경우에도 24시간 초과 금지)와 삭제 증명.
> - 관련 문서: [ADR-001 동의 구조와 원본 자료의 임시 처리 경계](../../../docs/architecture/decisions/ADR-001-consent-and-temporary-processing.md), [CONTRIBUTING.md](../../../CONTRIBUTING.md)
> - 본 문서의 수치는 아래 2장에 기재한 기기·엔진·프롬프트·양자화 설정에서의 실측값이며, **실측이 아닌 값은 본문에서 '예상치' 또는 '추정'으로 표기**함.

### 1) 모바일 온디바이스: 배제 강력 권고 (품질 붕괴, 지연 및 RAM 한계)
- **태깅 품질 붕괴 (시험 범위 한정)**: 이번에 시험한 3B 이하 후보와 동일 프롬프트 조건에서 서비스에 쓸 만한 품질을 낸 모델이 없었음. 사진 시각 정보를 거의 읽지 못하고 프롬프트 예시어(`연탄불, 재봉틀...`)를 그대로 읊거나 동일 단어를 5회 연속 반복(`한류`×5 등)하여 대화 소재로 활용 불가.
- **언어 오염 및 런타임 크래시**: 그나마 시각 정보를 일부 읽은 `qwen2.5-vl-3b`조차 중국어 간체자를 14회나 쏟아냈고, `smolvlm-2.2b`와 `paligemma-3b`는 모바일 런타임에서 크래시 발생.
- **가용 RAM 한계 및 OOM 위험**: 일반 스마트폰의 실가용 RAM(약 1.x GB) 대비 2B~3B 모델의 RAM 점유(1.8GB~3.1GB)가 초과되어 상용 폰에서 OOM Killer(`SIGKILL`) 강제 종료 위험이 상존함. 1GB 미만 모델은 지능 수준이 완전히 붕괴됨.
- **다장(Multi-image) 처리 시 지연시간 누적**: 실제 사용 시 사진을 여러 장 넣는 시나리오에서 온디바이스 추론 시 장당 15~25초 이상 소요됨. 3~5장만 일괄 처리해도 수 분이 걸릴 것임.
- **최종 판정**: **현재 단계에서는 이미지 태깅에서 모바일 온디바이스를 웬만해서는 배제하는 방향으로.** 네트워크 완전 단절 등 온디바이스를 무조건 고수해야만 하는 특수한 제약이 있는 경우에 한해서만, 추후 '경량 비전/OCR + 모바일 SLM' 2-Stage 구조 정도를 차선책으로 검토해 볼 수 있는 수준.

### 2) 온프레미스 서버: 현 CPU 환경 1순위 `qwen3.5-4b` / 최종 지향 `qwen3.5-9b` (GPU 서버)
- **현 노트북 CPU 환경 기준 1순위 (`qwen3.5-4b`)**:
  - 현재 평가 환경인 로컬 워크스테이션(노트북 CPU) 기준, 별도 외장 GPU 없이도 20초 내외(21.7s)로 가볍게 기동 가능하며 시각 디테일과 예시어 복창 최소화(1회)를 가장 균형 있게 달성함.
- **최고 품질 후보 `qwen3.5-9b` 및 상대적 대형 모델(9B / 27B+) 관점**:
  - **태깅 품질 및 어휘 완성도**: 어휘의 구체성과 사진 맥락 묘사력(김치 축제, 자갈치 시장 등) 자체는 `qwen3.5-9b`가 비교군 중 가장 뛰어남. (결과물 상 유일한 단점은 17장 중 2건에서 발생한 프롬프트 예시어 복창 정도)
  - **CPU 테스트베드 한계 vs 향후 GPU 서버 확장**: 본 벤치마크의 36.4초 지연시간은 노트북 CPU 구동에 따른 환경적 한계이며, 향후 전용 GPU 서버가 갖춰지면 추론 시간(**1~2초 내외 — 실측이 아니라 메모리 대역폭 기반 예상치**)과 메모리 문제가 완화되므로, 9B 및 27B급 이상 대형 모델을 최우선 도입하는 것이 서비스 품질 고도화에 적합함.
- **대안 모델 (`gemma-3-4b`)**:
  - 예시어 복창 0회, 단어 반복 0회로 형식을 가장 엄격히 준수하나, 일상 사진을 군사 테마로 해석하는 도메인 편향이 관찰되어 백업 후보로 유지.

## 2. 벤치마크 환경 및 평가 기준

### 2.1 배포 환경 정의 및 하드웨어 스펙
다음 하드웨어에서 임의 분류한(3b까지 온디바스 모델 후보로 임의 분류 / 4b 이상 온프레미스 서버용 모델 후보로 임의 분류)모델들을 테스트 실시함.

- **모바일 온디바이스 (Mobile On-device)**: Galaxy Tab S9+ (SM-X810)
  - AP / OS: Qualcomm Snapdragon 8 Gen 2 / Android ARM64
  - 시스템 메모리 (RAM): 12 GB LPDDR5X (부팅 후 기저 실가용 RAM 약 5,715 MB)
  - 엔진: `llama.cpp` Android 네이티브 빌드 (`llama-mtmd-cli`)
  - 특징 및 모바일 메모리 제약:
    - 외부 네트워크 연결 없이 단말기 로컬 NPU/CPU로 추론 수행.
    - 초기 타깃이었던 일반 스마트폰(Galaxy S21 등, 8GB RAM 탑재 모델)은 OS 및 상주 서비스 점유로 인해 실제 사용 가능한 여유 메모리가 **약 1.x GB**에 불과하여, 1.5GB 이상의 VLM 로드 시 OOM Killer(`SIGKILL`)로 강제 종료될 위험이 매우 큼. (스마트폰 가용 RAM 확인값과 태블릿 실측 점유량을 비교한 추정이며, 스마트폰 실기기 구동 실측은 아님.)
    - 따라서 3B급 모델의 동작 가능 여부와 태깅 품질을 검증하기 위해 여유 메모리가 확보된 Galaxy Tab S9+로 테스트함.
- **온프레미스 서버 (On-premise Server)**: 노트북
  - CPU / OS: Intel Core i5-13500H (12코어 16스레드) / Linux x86_64
  - 시스템 메모리 (RAM): 32 GB DDR5 4800MHz (실 가용 RAM 약 21 GB 이상)
  - 엔진: `llama.cpp` x86_64 빌드 (`llama-mtmd-cli`)
  - 4b이상 모델 테스트용.

> **공정 측정 조건**:
> - **기기 쿨다운**: 모델 간 실행 순서에 따른 발열 누적 및 쓰로틀링(클럭 다운) 왜곡을 방지하기 위해, 태블릿(표면 온도 34°C 이하)과 노트북(CPU 패키지 온도 65°C 이하)의 온도 센서 정보를 실시간으로 받아 해당 기준 온도 수준까지 냉각시킨 후 동일한 열 상태에서 동작시킴.
> - **순수 추론 시간(Inference Latency) 측정**: 프로세스 기동 및 모델 가중치 로드 시간을 제외한 순수 추론 시간만 분리 계측함.

### 2.2 공통 프롬프트 및 출력 규격 (JSON 스키마 제약)
모든 모델에 동일한 한글 질문(프롬프트)을 전달하고, 임의의 긴 서술형 텍스트 대신 정해진 규격의 JSON 형태로만 답하도록 엔진 단에서 출력 스키마(`schema.json`)를 강제함.

#### 1) 입력 프롬프트
```text
이 사진에서 그 시절의 일상 생활, 일거리, 도구, 음식 등 이야기 소재가 될 수 있는 구체적인 옛 추억 단어 키워드 3~5개를 JSON으로 출력해줘. (예: 연탄불, 재봉틀, 국민학교 도시락 등 일상 소재 / 사람, 건물, 풍경 같은 단순 일반명사는 제외)
```

#### 2) 출력 JSON 스키마 (`schema.json`)
`llama.cpp`의 문법 제약 옵션(`-jf`)을 통해 부가 설명이나 인사말 없이 오직 3~5개의 단어 배열(`topics`)만 출력하도록 제어함.
```json
{
  "type": "object",
  "properties": {
    "topics": {
      "type": "array",
      "items": { "type": "string" },
      "minItems": 3,
      "maxItems": 5
    }
  },
  "required": ["topics"]
}
```

> **검증 장치 (예시어 복창 탐지)**: 프롬프트 내 예시 단어(`연탄불`, `재봉틀`, `국민학교 도시락`)는 17개 평가 사진 어디에도 실제로 없는 소재로 의도적 배치함. 모델이 사진의 시각 정보를 인식하지 못하고 지시문 예시만 단순 복사할 경우 해당 단어가 그대로 노출되어 판별 기준으로 작용함.

### 2.3 참조 데이터셋 (Claude Opus 5 Description 및 Baseline)
단순 라벨 일치 채점을 넘어, 모델 출력을 다각도로 대조하기 위해 프론티어 VLM인 **Claude Opus 5** 참조 데이터 활용.
- **Claude Opus 5 Description**: 사진 17장을 직접 분석해 객체, 인물 행동, 소품, 간판 텍스트를 정밀 기술한 시각 기록.
- **Claude Opus 5 Baseline**: 동일 프롬프트로 Claude Opus 5가 추출한 대화 소재용 기준 키워드 목록.
- **평가 관점**: 프롬프트에 있는 키워드 단순 복창 여부를 거르고, **Claude Opus 5 Description에 기록된 실제 사진 속 디테일(행선판, 차력 소품, 동아줄 등)을 얼마나 잡아내는지** 대조 분석.

### 2.4 평가 지표
- **성공률 (ok / 17)**: JSON 파싱 오류나 런타임 크래시 없이 정상 완료된 비율.
- **추론 중앙값 (sec)**: 17개 이미지 순수 추론 시간의 중앙값 (실제 체감 반응속도).
- **고유 키워드 비율 (Unique Ratio)**: 단어 중복 없이 실제 선택지로 쓸 수 있는 유효 태그 개수.
- **예시어 복창 빈도 (Parrot Echo)**: 프롬프트 예시어를 그대로 뱉은 횟수.
- **언어 오염도**: 한국어 대신 중국어 간체자, 러시아어, 영문 템플릿 태그가 출력된 빈도.
