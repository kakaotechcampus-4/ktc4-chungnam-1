# Luna low와 medium 문맥형 이미지 출력 비교

실행일: 2026-09-14

## 결론

문장형 문맥 출력에서는 medium이 17장 중 10장에서 더 나았고, low가 더 나은 사진은 2장, 차이를 판단하기 어려운 사진은 5장이었다. medium은 인물, 물건과 공간의 관계를 조금 더 구체적으로 기술하고 사진 밖 사실을 단정하지 않는 경향이 있었다.

그러나 medium도 명확한 오류를 없애지는 못했다. 실제 개가 한 마리인 하이킹 사진을 low와 medium 모두 두 마리로 잘못 셌다. 화재 사진에서는 두 조건 모두 과거 화재 경험을 묻는 질문을 만들어 사용자에게 부담이 될 수 있었다. 따라서 medium 결과도 보호자 확인 전 후보로만 다뤄야 한다.

현재 한 번의 대응 실행만 놓고 보면 문맥형 최종 후보 생성에는 medium을 우선 검토할 수 있다. 평균 지연은 low보다 약 0.96초 길었다. 반복 실행이 없으므로 이 차이를 모델의 일반적인 성능 차이로 확정하지 않는다.

17장 각각의 low와 medium 출력 전문, 호출별 시간, 토큰과 비용은 [전체 출력 결과](luna-low-medium-context-full-results.md)에서 직접 비교할 수 있다.

## 이미지 조건 확인

이전 Haiku와 Luna 태그 비교와 이번 low와 medium 문맥 비교는 모두 원본 해상도 사진이 아니라 GitHub `target-image/`의 리사이즈 및 압축본 17장을 사용했다.

- 전체 크기: 3,418,086바이트
- 저장소 출처 문서의 설명: 웹 문서 열람용으로 리사이징 및 압축한 총 3.2MB 버전
- 출처 해상도 원본의 문서상 전체 크기: 약 114MB
- 이전 실험과 이번 실험의 이미지 SHA-256 대조: 17장 모두 일치
- 이번 실험 기준 커밋: `4626cc9830912410b0ad3b29e762a354ceffbd74`

따라서 PR 33의 첫 비교 결과도 압축본 결과로 읽어야 한다. 원본 해상도 효과는 이번 low와 medium 비교에 섞지 않았으며 별도 대응 실험이 필요하다.

## 비교 조건

| 항목 | low | medium |
| --- | --- | --- |
| 모델 | `gpt-5.6-luna` | 동일 |
| 추론 강도 | low | medium |
| 이미지 | GitHub 압축본 17장 | 동일 파일과 동일 해시 |
| 프롬프트 | 문맥형 출력 프롬프트 | 동일 |
| JSON Schema | 동일 | 동일 |
| 실행 도구 | Codex CLI 0.154.0 | 동일 |
| 반복 | 이미지당 1회 | 이미지당 1회 |

17장 모두 하나의 고정 프롬프트와 하나의 고정 JSON Schema를 사용했다. 사진마다 별도 설명, 질문, 정답, 출처 문구나 Claude Opus 5 참조 설명을 입력하지 않았다. 각 호출에서 바뀐 것은 이미지 파일과 low 또는 medium 설정뿐이다. `conversationOpeners`의 질문 두 개는 사진별 입력 프롬프트가 아니라 모델이 생성한 출력이다.

출력은 태그 배열이 아니라 다음 네 필드로 고정했다.

- `observedContext`: 사진에서 직접 보이는 행동, 물건, 복장과 공간 관계를 2문장으로 기술
- `conversationContext`: 생활 경험이나 대화로 연결할 수 있는 문맥 1문장
- `uncertainties`: 사진만으로 확인할 수 없는 내용 1개에서 3개
- `conversationOpeners`: 최근 기억을 시험하거나 사실을 전제하지 않는 열린 질문 2개

사용한 [프롬프트 원문](context-prompt.txt)의 SHA-256은 `3d603b1096a253937c24dc22e521002acb173996790c79c7484643defd15a85d`다. 출력 형식은 [JSON Schema](context-output-schema.json)에서 확인할 수 있다.

## 대표 출력 비교

### 버스 사진

low는 뒤 인물이 앞 사람을 `돕고 있습니다`라고 단정했다. medium은 `그 사람 가까이에 손을 뻗고 있습니다`라고 써 관찰과 해석의 경계를 더 잘 지켰다. 다만 두 조건 모두 사진의 핵심인 버스 안내양과 만원버스 상황은 잡지 못했다.

### 차례상 인쇄물

low는 `차례상 차리는법`이라는 제목과 인쇄물임을 정확히 기술했다. medium도 인쇄물을 인식했지만 불확실성에서 실제 상인지 안내 그림인지 확인할 수 없다고 적어 자신의 관찰과 일부 충돌했다. 이 사진에서는 low가 더 나았다.

### 하이킹 사진

medium은 `2023 에코하이킹 영월` 문구와 휴대전화를 읽었다. 그러나 실제 사진에는 개가 한 마리인데 low와 medium 모두 두 마리라고 기록했다. 추론 강도를 높여도 물체 개수 오류가 사라지지 않는 사례다.

### 화재 사진

관찰 문맥은 두 조건 모두 대체로 맞았다. 그러나 질문에서 과거 화재나 긴급 상황 경험을 바로 물어 민감하거나 불편한 기억을 자극할 수 있다. VLM 문맥 생성 뒤 별도의 민감 소재 필터와 질문 완화 단계가 필요하다.

## 적용 판단

1. 태그 배열보다 문장형 구조가 관찰 사실과 불확실성을 분리하는 데 유리했다.
2. 한 번만 생성한다면 medium을 우선 후보로 둘 수 있다. 추가 시간은 장당 약 0.96초였다.
3. low도 특정 글자와 인쇄물 판독에서는 더 나았으므로 medium 우세를 일반화하지 않는다.
4. 출력은 `observedContext`, `conversationContext`, `uncertainties`, `conversationOpeners`로 분리한다.
5. 관찰 문장도 사실로 자동 저장하지 않고 보호자 확인 전 후보로 둔다.
6. 질문 생성 전 민감 소재, 최근 기억 시험과 사실 전제를 별도 규칙으로 검사한다.
7. 원본 해상도 17장과 압축본 17장의 대응 비교를 별도 실험으로 수행해야 해상도 효과를 판단할 수 있다.

## 제외한 점검 실행

정식 34회 전에 표준입력과 프로세스 실행을 확인한 low 점검 2회가 있었다.

- 첫 점검: 15,725 입력 토큰, 364 출력 토큰, 정가 환산 0.0035818달러
- 두 번째 점검: 15,825 입력 토큰, 260 출력 토큰, 정가 환산 0.0034770달러

두 점검은 공식 통계에서 제외했다. 모델 호출 전에 중단된 PowerShell 러너 시도는 모델 비용이 발생하지 않았고 기반 시설 실패로 기록했다.
